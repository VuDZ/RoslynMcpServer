# Epoch 4 — Оптимизации по результатам измерений

Статус: **optional**. Не одна большая фича: каждый выбранный пункт — отдельное
решение, изменение и handoff. Ничего из списка не обязательно для завершения v2.

## 4A. Явная частичная загрузка и metadata references

Делать, если основной расход — размер ненужного графа. Называть режим explicit
partial load: автоматической догрузки по запросу символа здесь нет.

- По умолчанию сохранить обычную загрузку. `graphScope=project` для `.sln`
  требует root project path; неоднозначное имя — ошибка, не первый найденный.
- В обоих cache keys учитывать scope и canonical selected roots. A и B внутри
  одного sln — разные запросы. Ответ сообщает requested roots, фактические
  проекты, metadata-only dependencies и неполноту поиска.
- Expand выполняется повторной полной загрузкой нового scope. Новые вызовы
  navigation не должны незаметно менять граф.
- У semantic tools есть общий partial hint. Rename/refactoring, требующий полноты,
  должен запросить полный scope или явно отказаться от неполной операции.
- Проверить отдельно CLI build/test: не менять явную цель команды из-за scope;
  учитывать существующие test discovery / binary resolution paths, которые
  используют текущую solution как подсказку.
- Metadata references — отдельный opt-in. Использовать результаты Epoch 0 для
  конкретной версии Roslyn. Замену source graph на DLL не считать эквивалентностью
  full mode; устаревший bin требует честного описания ограничения.
- Смена metadata mode вызывает reopen, эффективный режим отражается в ответе.
  Недоступная/повреждённая DLL обрабатывается проверенным fallback, а не обещанием
  недоказанного поведения Roslyn.

Приёмка: V24–V25, измеримое ускорение для соответствующего use case и отсутствие
ложного full-solution результата.

## 4B. Сокращение проверки файлов

Делать, если profiler показывает доминирование probes.

- Начать с устранения повторных чтений, дедупликации linked inputs и bounded I/O.
- Merkle — optional агрегат hashes; сам по себе не позволяет пропустить обход
  после рестарта. Directory mtime не доказывает неизменность потомков.
- Size+mtime shortcut допустим лишь как отдельная явно названная non-strict
  политика с документированным риском. Strict mode остаётся доступен.
- Не ослаблять проверку graph/config/analyzer/metadata inputs ради ускорения.
- Для live session доверие watcher требует coverage, overflow recovery и обработки
  unavailable watchers. Отдельно описать риск потерянных событий без сигнала ошибки.

Приёмка: V10, V16, V19–V23 для strict; отдельные ожидаемые ограничения non-strict.

## 4C. Членство без полного DTB и инвалидация по проектам

Делать только после доказательства корректности более простого режима.

- Изменение source set без DTB разрешать только узкому распознаваемому профилю
  с доказанной моделью Include/Exclude/Remove/conditions; unknown -> full load.
- Перепроверять negative dependencies, imports и linked memberships.
- Per-project cache требует mapping project instances и транзитивной инвалидации
  зависимых проектов. Изменение B может менять compiler inputs A; одного DTB B
  недостаточно без доказательства независимости A.
- Мержить граф атомарно, сохраняя корректные ProjectReferences и TFM contexts.
- Пройти всю equivalence-матрицу заново; новый `.cs` при неизменном `.csproj`
  не является достаточным единственным тестом.

## 4D. Индекс имён символов

Делать только если после ускорения load измеренное узкое место — поиск по имени.

- Индекс даёт кандидатов, Roslyn проверяет их в текущей solution.
- Контекст записи включает document membership, project/TFM, parse options/defines,
  content hash и schema version; одного hash файла недостаточно.
- Удаление проекта/документа удаляет записи. Старый candidate не выдаётся как hit.
- При miss/невалидном индексе остаётся обычный поиск. Поведение generated symbols
  не расширяется без отдельной спецификации и тестов.
- Выбор SQLite или файла определяется замерами, без копирования внутренних
  Roslyn symbol/storage форматов.

Приёмка: V26, частое имя и отрицательный поиск, обе ветки `#if`, удаление файла,
смена TFM и сравнение с обычным semantic query.
