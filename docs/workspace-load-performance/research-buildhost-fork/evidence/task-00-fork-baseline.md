в research-ветке; стиль кода форка — Roslyn, не `docs/code-style.md` (записано в `AGENTS.md`

## Upstream

- `dotnet/roslyn` `35d9211b841e7613c1d2f8f5af6d628ace696c4c` (`release/insiders`, 2026-07-07) —
  ревизия из nuspec пакета `Microsoft.CodeAnalysis.Workspaces.MSBuild` 5.9.0.
- Дословно скопированы 109 файлов, с хешами в `forks/roslyn-buildhost/UPSTREAM.md`:
  - `BuildHost` и `Contracts`;

  - 16 файлов компилятора, которые подключает проект BuildHost;
  - `License.txt`, `THIRD-PARTY-NOTICES.txt` и `.editorconfig` Roslyn.

  Лицензия MIT.
- Минимальная граница форка — только процесс BuildHost-netcore.
  - Клиент (`Microsoft.CodeAnalysis.Workspaces.MSBuild.dll`) берёт BuildHost из папки
    `BuildHost-netcore` рядом с собой (`BuildHostProcessManager.GetBuildHostPath`, декомпиляция)
    и общается с ним JSON по именованному каналу.
  - Поэтому подмена — это копирование сборки форка в эту папку. Сборка Contracts форка
    используется только процессом BuildHost.
- Не форкаются: клиент, `BuildHost-net472` (проекты .NET Framework на Windows; в офисном решении
  такие варианты есть, это ограничение до task-02) и Mono.

Стенд:

- решение в другой системе контроля версий, не Git. Первый запуск остановился на

Результаты переданы владельцем вне репозитория, сюда вошла только сводка.

| метрика (медиана) | оригинал | форк | отношение |
|---|---|---|---|
| загрузка | 41 779 мс | 41 838 мс | 1,001 |
| первый поиск | 36 836 мс | 37 474 мс | 1,017 |
| CPU клиента | 50 016 мс | 52 891 мс | 1,057 |
| пик памяти клиента | 1 199 МБ | 1 203 МБ | 1,004 |

| CPU BuildHost (нижняя граница) | 51 062 мс | 51 188 мс | 1,002 |
| пик памяти BuildHost | 539 МБ | 532 МБ | 0,987 |

- Эквивалентность: **identical** на 142 проектах. Все поля проектов, диагностики и ответ
  поиска совпадают во всех 8 загрузках, полей с естественным разбросом нет.
- Подключение форка не замедляет загрузку. CPU клиента ×1,057 — больше, чем на других стендах
  (×1,018 и ×1,048). Загрузка и CPU BuildHost совпадают, и это медиана трёх замеров, поэтому
  считаю это разбросом. Если отличие повторится в следующих сравнениях, его нужно разобрать.
- Ограничение: sampler считает только процессы `dotnet`. `BuildHost-net472` запускается
  отдельным `.exe`, его процесс, CPU и память в таблицу не входят. Варианты `net472` в обоих
  прогонах грузит один и тот же не форкнутый host, поэтому их совпадение ожидаемо и форк не
  проверяет.
