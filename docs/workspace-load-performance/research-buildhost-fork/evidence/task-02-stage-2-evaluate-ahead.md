## Что сделано

Форк ([README](../../../../forks/roslyn-buildhost/README.md)): `ProjectBuildManager_EvaluateAhead.cs`, включается
`ROSLYN_BUILDHOST_EVALUATE_AHEAD=<число рабочих потоков>`, независимо от A.

- **Что оценивается.** Рабочие потоки оценивают ссылки уже оценённых проектов и записи решения. Evaluation идёт в
  коллекции host и с его настройками, как `LoadProjectAsync`. `ProjectCollection` хранит результат, поэтому
  загрузка клиента получает тот же `Project`, как получила бы проект, загруженный host раньше.
- **Порядок.** Рабочий берёт первый не начатый проект в прямом порядке DFS: от записей решения, затем от других
  запрошенных проектов, по уже известным ссылкам. Это порядок, в котором их попросит клиент. Ссылки проекта
  читаются на рабочем потоке, пока evaluation ещё не отдана: потом сборка переключает у проекта `TargetFramework`.
- **Запрос клиента.** Запрос к проекту, который оценивает рабочий, ждёт эту evaluation (span
  `wait-evaluation-ahead`). Запрос к ещё не начатому проекту оценивает его сам, как без B, и рабочие его уже не
  берут.
- **Ошибки.** Неудачная evaluation наперёд не сохраняется: запрос клиента оценивает проект заново и получает ту же
  ошибку в своём логе.
- **Загрузка из присланного содержимого** (`LoadProject` с текстом проекта). Если тот же путь уже оценён наперёд и
  клиент его не запрашивал, такая evaluation выгружается, чтобы коллекция не держала путь дважды.
- **Остановка.** `Dispose` останавливает рабочих до `EndBuild`. Начатая evaluation доходит до конца.

**Записи решения** (решение владельца, 2026-10-25). Клиент передаёт host только `SolutionDir`. Host берёт записи,
только если выполнены все условия:
- в `SolutionDir` ровно один `.sln` или `.slnx` и нет `.slnf`;
- MSBuild (`SolutionFile.Parse`) его читает;
- первый запрос клиента — первая запись, которую клиент отправит этому host: C# или VB, файл есть, и по правилам
  `BuildHostProcessManager.GetKindForProject` клиента 5.9.0 она идёт в .NET host.

Иначе B оценивает наперёд только ссылки. По тем же правилам рабочие пропускают проекты, которые клиент
отправляет в .NET Framework host. Решение о записях пишется в трассу (span `evaluate-ahead-start`, поле
`solution`). `ROSLYN_BUILDHOST_EVALUATE_AHEAD_SOLUTION`: `all` (по умолчанию, все записи с первого запроса), число
записей после последней запрошенной или `off`.

**От пробы не перенесены** опережение в один уровень и LIFO-замыкание. Проба показала, что они не лучше прямого
порядка ([шаг 0](task-02-step-0.md#итог-b-после-шага-0-2026-10-25)). Настройки — число потоков и окно записей.

**Стенд.** `-EvaluateAhead <потоки>` и `-EvaluateAheadSolution all|N|off` у
`Invoke-BuildHostForkBaseline.ps1` и `Invoke-BuildHostForkScenarios.ps1` ставят переменные только на стороне
форка, вместе с `-ReferencesFirst` или без него. В трассе span рабочих потоков идут одновременно со span запросов,
поэтому `trace-summary.md` относит это время к «several host spans at once».
