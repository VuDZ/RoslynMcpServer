## Отличие 1 — binlog новее reader

В `ProjectCostReplay` включить `AllowForwardCompatibility = true` и подписаться на
`RecoverableReadError`. Recoverable read error в файле с хотя бы одним
`ProjectStarted` — профиль `failed` с `ErrorType`/`RecordKind`. Файл без
`ProjectStarted` записывается в профиль как пустая сессия BuildHost: формат,
число событий по типам; в стоимость не входит.

Ожидаемо (ревью): PowerToys `capture-2.binlog` — формат 27, 6 событий, ни одного
проекта; `capture-1.binlog` — формат 26, 248 `BuildSubmissionStarted`.
Другое наблюдение — результат, который записывается, а не обходится.

## Отличие 2 — стоимость проекта

Evaluation верхнего уровня BuildHost в binlog не логируется (Files: 0 событий
`ProjectEvaluationStarted` при 11 top-level builds). `EvaluationMs` больше не
обязателен; профиль с `EvaluationMs=null` не считается неполным по этой причине.

Стоимость проекта — по разрывам внутри одного binlog (одного BuildHost):

- top-level builds файла упорядочиваются по `ProjectStarted.Timestamp`;
  проверяется, что они не перекрываются. Перекрытие — профиль `failed`:
  предпосылка последовательной загрузки неверна;
- `w(p) = end(p) − end(предыдущего top-level build файла)`: в разрыв входят
  evaluation, обработка на стороне Roslyn и сам build;
- первый проект файла: `end(p) − BuildStarted.Timestamp` записывается отдельно
  как `first` и в `w` не входит; оценка прогрева — вход для `h`, не стоимость проекта;
- Worker Roslyn обходит проекты одним циклом и для vcxproj обращается к
  BuildHost-net472. Время этих попыток попадает в разрыв следующего C# проекта.
  Отчёт показывает, сколько таких попыток было и сколько времени они заняли
  (по `MSBuildWorkspace "Failure"` и порядку проектов в solution); для модели
  это время либо относится к проекту, перед которым оно случилось, либо
  выносится в отдельную стоимость — выбор объясняется;
- сумма `w` по файлу плюс `first` сверяется с измеренным временем
  `LoadSolutionInfoAsync` того же profile-прогона: расхождение больше 10 % —
  причина в отчёте, профиль в модель не подаётся, пока причина не найдена.

`OwnBuildMs` остаётся в профиле для сравнения: доля build в `w` — отдельная
строка отчёта.
