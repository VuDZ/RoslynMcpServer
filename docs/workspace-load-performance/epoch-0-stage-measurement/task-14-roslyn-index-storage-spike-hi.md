## Вопрос

Сокращает ли включённое persistent storage Roslyn первый поиск в новом процессе
сервера, когда кеш уже заполнен прошлым процессом, без изменения ответов?

## Основания

[Профиль офисного прогона 1.5.13](evidence/office-first-search-2026-10-23.md#профиль-первого-поиска-на-1513-trace-server-gc):

- из ~54 с CPU первого поиска крупнейшие части — построение индексов имён (~19 с),
  контрольные суммы документов (~17 с), чтение файлов (~13 с) и разбор (~10 с);
- Roslyn 5.9.0 пытается открыть `SQLitePersistentStorage`, но
  `SQLitePCLRaw.batteries_v2` (ссылка на сборку версии 2.3.5.0) в сервере нет;
  NuGet-зависимость на него Workspaces не объявляет (найдено при исправлении декомпилятора, 1.5.10);
- поэтому индексы строятся заново в каждом процессе.

Последний стабильный `SQLitePCLRaw.bundle_green` — 2.1.11: у его сборок версия ниже 2.3.5.0,
и .NET такую сборку не загрузит. Пакеты `SQLitePCLRaw.*` 3.0.x — новая мажорная версия,
её API может не совпасть. Какой пакет совместим, нужно установить экспериментом.

## Границы

- Только standalone spike (`spikes/IndexStorage` или расширение `spikes/FirstSearchProbe`)
  и evidence. Production, Version, CHANGELOG не менять.
- Тот же Roslyn 5.9.0, та же MEF-композиция и загрузка, что у сервера.
- Не трогать формат кеша Roslyn и не писать свою сериализацию индексов.

## Шаги

1. Совместимость. Подобрать пакет SQLitePCLRaw, с которым Roslyn 5.9.0 открывает storage.
   Доказательства:
   - база создана в каталоге кеша;
   - нет `FileNotFoundException`, `MissingMethodException` и `TypeLoadException`;
   - нативная `e_sqlite3` есть для `win-x64` и `linux-x64` в self-contained publish.
2. Корректность:
   - ответ первого поиска в процессе с тёплым кешем совпадает с холодным
     (тот же упорядоченный список и SHA-256, как в task-11);
   - изменение файла между процессами меняет ответ: кеш инвалидируется по контрольной сумме;
   - два процесса с одним решением одновременно не ломают кеш.
3. Замер, каждый прогон — новый процесс:
   - холодный кеш (каталог удалён) и тёплый кеш;
   - локально на `RoslynMcpServer.sln`; на Windows-стенде task-11 на Roslyn.slnx
     с теми же двумя запросами;
   - записывать загрузку, первый поиск, CPU, рабочий набор и размер базы.

## Пороги (заданы до измерений)

**go**, если выполнены все условия:

- тёплый кеш: медиана первого поиска ≤ 0,70 от холодного на обоих запросах Roslyn.slnx;
- холодный кеш: первый поиск не медленнее прежнего (без storage) больше чем на 10%;
- все ответы совпали, а изменённый файл виден в ответе.

Иначе — no-go, или inconclusive, если совместимый пакет не найден.
