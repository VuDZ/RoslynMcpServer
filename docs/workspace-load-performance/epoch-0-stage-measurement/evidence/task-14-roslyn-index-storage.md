# D/E0/task-14 — persistent storage индексов Roslyn: локальная часть

Дата: **2026-10-23**. Spike `spikes/IndexStorage`, Linux, 2 vCPU. Production не менялся.
Матрица на Roslyn.slnx (Windows), по которой выносится вердикт, ещё не выполнена.

## Совместимость

- Roslyn 5.9.0 ссылается на `SQLitePCLRaw.batteries_v2, Version=2.3.5.0,
  PublicKeyToken=df579d6b11135638`. Это сборка из `SQLite3MC.PCLRaw.bundle` 2.3.5
  (SQLite3 Multiple Ciphers).
- `SQLitePCLRaw.bundle_e_sqlite3` 3.0.5 не подходит: у его сборок версия 3.0.5.3129
  и ключ `8226ea5df37bcae9`. У `SQLitePCLRaw` 2.1.x версия сборки ниже 2.3.5.0.
- С `SQLite3MC.PCLRaw.bundle` 2.3.5 Roslyn создаёт
  `<LocalApplicationData>/Microsoft/VisualStudio/Roslyn/Cache/dotnet-<hash>/<решение>-<hash>/sqlite3/v2/storage.ide`.
  Нативные библиотеки есть для `win-x64` (`sqlite3mc.dll`) и `linux-x64`
  (`libsqlite3mc.so`).
- Папка кеша названа по имени процесса: `dotnet-…` у spike, а у сервера в офисе
  `RoslynMcpServer.exe-…`. Будет ли хеш в имени меняться при смене каталога сервера
  (новая версия), не проверялось.

## Время, `RoslynMcpServer.sln`

Каждый прогон — новый процесс, медианы по 3 прогона:

| запрос | без storage | холодный кеш | тёплый кеш |
|---|---|---|---|
| `SolutionManager`, 1 объявление | 5 972 мс | 6 759 мс (×1,13) | 5 088 мс (×0,85 к без storage, ×0,75 к холодному) |
| отсутствующее имя | 2 258 мс | 2 534 мс (×1,12) | 1 008 мс (×0,45 и ×0,40) |

- Загрузка не изменилась: 4,8–5,0 с.
- Ответы совпали во всех режимах.
- Холодный прогон дороже на 12–13%: он записывает индексы в базу.
- Тёплый кеш сильнее помогает, когда достаточно индексов. Если нужна compilation
  проекта с совпадением, её стоимость остаётся.
- На этом малом решении пороги task-14 не выполняются: холодный ×1,12–1,13 против
  допустимых 1,10, тёплый к холодному ×0,75 против 0,70 на запросе с совпадением.
  Вердикт выносится только по Roslyn.slnx.

## Корректность

- **Инвалидация.** Решение Smoke, тёплый кеш, отдельный процесс на каждый шаг:
  - до правки — 0 объявлений `ZzzStorageProbe`;
  - после добавления класса в существующий файл — 1, и 1 при повторе;
  - после удаления — 0.

  Roslyn сверяет контрольные суммы документов, и устаревший индекс не используется.
- **Конкурентные процессы.** Три процесса одновременно с одним пустым кешем
  завершились без исключений с одинаковым ответом; база одна.

## Скрипт матрицы

`spikes/IndexStorage/Invoke-IndexStorageMatrix.ps1`:

- режимы `none`, `cold` и `warm`;
- перед `cold` удаляется только кеш этого решения в папках `dotnet-*`;
- `warm` идёт сразу после `cold`, а позиция `none` чередуется;
- сводка и вердикт строятся по порогам task-14.

Проверен end-to-end на Smoke (PowerShell 7.6.8, Linux).
Windows PowerShell 5.1 не проверялся.
