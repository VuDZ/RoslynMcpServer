## Воспроизведение на `6a1b48f`

В фикстуре P1-40 один TFM проходит `Demo.Fixture.Match`, во втором нет совпадений. Цель MSBuild после `VSTest` завершает запуск ошибкой. С кодом `MSB4181` публичный отчёт верно показывает неуспех. Заменить **только** код ошибки в MSBuild-задаче на `CI-001`. Настоящий `dotnet test` завершился с кодом 1 и вывел `Actual.csproj(1,840): error CI-001: Test result directory could not be written.`. Через `run_specific_test` получено `Filtered tests passed` и объяснение ненулевого кода несовпадением фильтра. Дефект повторился в полном журнале из 2 598 символов и при усечении. При удалении отдельной ошибочной цели команда действительно проходит.

## Причина и требуемое поведение

Отчёт использует наличие строки no-match как объяснение ненулевого кода. Самостоятельную ошибку он узнаёт по текстовому шаблону, который разрешает в коде диагностики только буквы с последовательностью цифр. Произвольный код корректной MSBuild-задачи выпадает из проверки. Успех всего запуска требует достоверного объяснения ненулевого выхода. При независимой ошибке показывать неуспех и сохранять сведения о действительно прошедших тестах. Когда причина не установлена, выводить неопределённый или неуспешный исход. Добавление одного литерала `CI-001` не покрывает этот контракт.

## Критерии приёмки

- [x] Сочетания no-match и независимой ошибки с обычным и пользовательским кодом дают неуспех и сохраняют диагностику. Проверить полный и усечённый вывод через публичный инструмент.
- [x] Успешный контроль с одним совпадением и единственной причиной no-match в соседнем TFM сохраняет принятый результат. Похожие на диагностику сообщения самого теста не должны ошибочно засчитываться как ошибки MSBuild.
