## Воспроизведение на `6a1b48f`

1. **Один проект, два способа получить новый файл.** Загрузить SDK-проект с `<CodePage>28591</CodePage>`. Через `update_file_content` записать в два новых класса константу со значением `Café`. Первый путь до вызова отсутствует. Второй файл после загрузки workspace заранее создать нулевой длины. Сервер подтвердил обе записи. Первый получил UTF-8 BOM, второй — UTF-8 без BOM. Одна и та же Release-сборка вернула значения `Café` и `CafÃ©` соответственно. UTF-8-байты второй скомпилированной константы — `43 61 66 C3 83 C2 A9`.
2. **Смена интерпретации после самого патча.** На Windows с системной страницей 1251 в проекте с автоматическим выбором кодировки создать исходник без BOM. Литерал `Keep` содержит байты `D0 96` (в Windows-1251 это `Р–`), а литерал `Edit` — байт `DF` (буква `Я`). Свежая сборка подтвердила `Keep == "Р–"`. Изменить только `Edit` с `Я` на ASCII-букву `X` через `apply_patch`. После этого весь файл стал допустимым UTF-8. Патч сообщил об успехе, байты соседнего литерала сохранились, но следующая сборка прочитала `Keep == "Ж"`. В другой фикстуре опубликованный снимок и заново загруженный документ также вернули разные строки.
3. **Файл с shebang.** Создать через публичный MCP `hello.cs`, начинающийся с `#!/usr/bin/env dotnet`. Проверенный сервер записал `EF BB BF 23 21` в начале. На Ubuntu 24.04 в WSL с SDK 10.0.115 после `chmod 0755` прямой запуск файла без shell вернул `ENOEXEC`. При удалении только трёх байтов BOM тот же файл напечатал контрольную строку и завершился с кодом 0. `dotnet run --file` с BOM также проходит, поэтому этот способ запуска сам по себе не обнаруживает регрессию.

## Причина и требуемое поведение

В текущем коде используются три разных правила. `ForDiskPath` смотрит на существование файла, `GetFileEncodingUnderLock` определяет кодировку по входным байтам, а `PersistedPayload` проверяет обратное преобразование в выбранной кодировке. Такая проверка не моделирует, в какой кодировке свежий потребитель прочитает **выходные** байты.

Для полной записи и патча применять одно правило успешного результата. Выбранное представление должно воспроизводить запрошенный текст при свежем чтении с настройками проекта. Для патча это включает сохранность текста вне замены. Для исполняемого исходника `#!` должно начинаться с байта 0. Сохранять существующую кодировку и BOM, когда они удовлетворяют этим условиям. Если принадлежность или кодировка неопределённа и однозначное представление подобрать нельзя, вернуть явную причину до изменения файла и публикации снимка. Конкретную реализацию выбора оставить исполнителю.
