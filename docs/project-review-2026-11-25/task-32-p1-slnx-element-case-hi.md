## Воспроизведение на `9d8b00c`

Создать `Old/Old.csproj` и `App/App.csproj`. В `Demo.slnx` перечислить оба проекта. Внутри элемента проекта `App` добавить `<builddependency Project="Old/Old.csproj" />`. `dotnet sln Demo.slnx list` возвращает 0 и оба проекта. Контроль с `Missing/Missing.csproj` в этом же атрибуте даёт ошибку SDK, подтверждая, что зависимость учитывается.

Выполнить `rename_project` для `Old` с `newProjectName="New"` и `dryRun=false`. Инструмент сообщает об успехе и перемещает проект. Значение `builddependency/@Project` остаётся старым. После переименования `dotnet sln Demo.slnx list` возвращает 1 и `Project 'Old\Old.csproj' not found`.

## Исправление

SDK 11.0.100 принимает имена элементов `Project` и `BuildDependency` в верхнем, нижнем и смешанном регистрах. Код выбирает элементы по строковым константам с точным регистром. Учитывать правила SDK для этих имён в построении плана. У проверенных атрибутов значим регистр (`Path` и `Project`).

## Критерии приёмки

- [ ] Параметризованный тест с каноническим и смешанным регистром элементов выполняет dry-run и реальное переименование. SDK читает решение до и после. Проверка XML отдельно подтверждает сохранённое ребро `App → New`.
- [ ] Предварительный просмотр оставляет каталоги и байты решения прежними. Ссылки на другие проекты сохраняются.
