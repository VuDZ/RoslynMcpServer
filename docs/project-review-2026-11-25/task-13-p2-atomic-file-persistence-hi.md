# P2-13. Сохранить целостность файла при частичном сбое записи

- Рекомендуемые модели: GPT-6.2 Astra.
- Рекомендуемый reasoning: high.
- Примерная сложность: 4/5.
- Риск ошибки: высокий — неудачная запись может обрезать существующий файл.
- Необходимые способности: атомарная замена файла, метаданные, watcher и TryApplyChanges.
- Статус: accepted, 2026-11-25. Приняты атомарная запись, учёт подтверждённых путей и согласование файлового наблюдателя.

- Модели, проводившие ревью: `gpt-6.2-sol`.

## Основание

`WriteAllBytes` и `WriteAllBytesAsync` пишут прямо в конечный путь. Если ошибка произойдёт после открытия, старый файл может остаться частичным, хотя его ещё нет в `SavedPaths`. Оценка основана на коде; для подтверждения нужен управляемый сбой после начала записи.

## Задача

Подготовить полное содержимое до замены существующего файла. Учесть синхронный и асинхронный пути, метаданные, вторую запись в `TryApplyChanges`, own-write события и отчёт о фактически сохранённых файлах.

## Критерии приёмки

- [x] При искусственной ошибке после записи части подготовленного содержимого исходный файл остаётся целым. После успешной замены файл содержит полный новый текст с правильной кодировкой и BOM.
- [x] Если сбой произошёл после видимой записи на диск, снимок и `SavedPaths` отражают результат. Проверить многофайловую операцию и уборку временных файлов после отказа и отмены.
