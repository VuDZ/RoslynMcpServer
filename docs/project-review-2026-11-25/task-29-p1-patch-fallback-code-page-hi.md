## Воспроизведение на `9d8b00c`

1. В проекте задать `<CodePage>28591</CodePage>` (ISO-8859-1). Загрузить в Roslyn исходник с UTF-8 BOM, текстом `Café` и выражением `Value => 1`. Материализовать снимок.
2. Внешней записью сохранить тот же файл в ISO-8859-1 без BOM, заменив только `1` на `2`. Перед патчем `é` представлен байтом `E9`.
3. Применить через `apply_patch` замену `Value => 2` на `Value => 1`. На `9d8b00c` получен успешный ответ, но в строке `Café` байт `E9` заменился на `EF BF BD` (символ `�` в UTF-8).

## Исправление

`ReadPatchFileUnderLockAsync` выбирает UTF-8, если прежний снимок имел BOM, а в файле теперь его нет. При отсутствии BOM учитывать действующую кодировку проекта. Если байты нельзя однозначно и без потерь прочитать в поддерживаемой кодировке, завершать операцию до записи. В базовом коде до P1-21 чтение без BOM тоже использовало UTF-8.

## Критерии приёмки

- [x] На указанной фикстуре патч меняет только байт цифры. Байт `E9`, отсутствие BOM и символ `é` в итоговом снимке сохранены.
- [x] Явный BOM текущего файла сохраняет приоритет. Если байты недопустимы для выбранной кодировки, ошибка оставляет файл побайтно неизменным.
