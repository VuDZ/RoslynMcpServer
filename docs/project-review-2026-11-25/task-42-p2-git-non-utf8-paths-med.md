## Воспроизведение

Проверена рабочая копия с исправлениями 28–35 поверх `380decf`, Release, Windows, SDK `11.0.100`.

Создать во временном Git-индексе два пути, различающихся одним байтом: `61 FE 2E 63 73` и `61 FF 2E 63 73`. На Windows их можно поместить непосредственно в индекс через байтовый ввод `git update-index -z --index-info`, без создания таких имён в рабочем каталоге. `git status --porcelain=v1 -z` вернул две разные записи. `get_changed_files` показал одно и то же имя `a�.cs` для обеих строк. Прежний вывод Git при стандартном `core.quotepath` различал `a\376.cs` и `a\377.cs`.

## Исправление

`StandardOutput.ReadToEndAsync` преобразует Git-вывод в строку до разбора NUL. UTF-8-декодер подставляет один и тот же заменяющий символ. Разбирать пути без потери исходных байтов и явно предоставлять обратимое представление, если имя нельзя представить строкой Unicode.

## Критерии приёмки

- [x] Два указанных пути остаются различимыми в публичном ответе, и из ответа можно восстановить байты каждого. Проверить обработку имён POSIX хотя бы на уровне Git-индекса.
- [x] Действительные UTF-8-пути, включая кириллицу, сохраняют буквальное имя. Проверки R/C, Markdown-символов и лимита 80 остаются зелёными.
