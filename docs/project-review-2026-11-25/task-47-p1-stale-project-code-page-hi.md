## Воспроизведение

1. Загрузить SDK-проект `net11.0` с `<CodePage>65001</CodePage>` и существующим ASCII-файлом `Program.cs` без BOM.
2. Поменять в проекте только `CodePage` на `28591`. В том же сеансе MCP вызвать `update_file_content` для `Program.cs` с полным текстом, содержащим литерал `Café`.
3. MCP сообщает `Successfully wrote`. В файле остаётся UTF-8 без BOM. Свежая сборка и запуск дают кодовые единицы `0043 0061 0066 00C3 00A9` вместо запрошенных `0043 0061 0066 00E9`.
4. После `load_workspace` и повторения вызова тот же компилятор получает `0043 0061 0066 00E9`.

## Исправление

Проверять актуальность настроек чтения проекта до записи. `GetSourceCodePagesUnderLock` читает метаданные последней загрузки, а блокировка workspace согласует операции с этим снимком. Если настройки графа изменились и актуальная интерпретация исходника неизвестна, допустим явный отказ до записи с указанием повторно загрузить проект. Успешная запись должна сохранять текст при свежей сборке.

## Критерии приёмки

- [x] В воспроизведённом сценарии успешный вызов даёт `Café` в свежей сборке. При отказе сохраняются исходные байты и опубликованный до вызова текст.
- [x] Проверена та же смена кодировки для патча по исходнику без BOM. Текст вне заменяемого фрагмента сохраняет смысл при чтении текущим проектом.
- [x] Повторение записи после загрузки изменённого проекта проходит. Регрессионные тесты для P1-44 продолжают проходить.
