# P1-03. Проверять пути плана rename_project до перемещения каталога

- Рекомендуемые модели: GPT-6.2 Astra.
- Рекомендуемый reasoning: high.
- Примерная сложность: 4/5.
- Риск ошибки: высокий — каталог может переехать с частично обновлённым графом проектов.
- Необходимые способности: MSBuild, файловые пути, интеграционные тесты Git checkout.

## Основание

В режиме `dryRun` для корневого `.csproj` исходный сервер запланировал перенос всего каталога и четыре изменения внутри него. `Apply` перемещает каталог и затем открывает файлы по старым абсолютным путям. Реальный репозиторий в ходе ревью не перемещали.

## Задача

Рассчитать конечные пути владельцев и относительные ссылки с учётом переноса. Если текущий контракт не позволяет поддержать структуру, распознать её на этапе планирования и вернуть отказ до изменения диска.

## Критерии приёмки

- [ ] Временная фикстура содержит проект, решение и вложенный ссылающийся проект в перемещаемом каталоге. Выполнимый preview соответствует результату apply, а неподдержанный план отклоняется до первой записи.
- [ ] После успешной операции все ссылки в `.sln`/`.slnx` и `ProjectReference` разрешаются, решение открывается. Сохраняется поддержка обычной схемы с соседними проектами.
