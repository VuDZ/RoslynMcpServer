## P1-44

Проверка исходных байтов Windows-1251 показала, что до патча значение `Keep` в DLL давало `D0 A0 E2 80 93` при выводе в UTF-8. Исходная версия после замены соседней `Я` на `X` меняла его на `D0 96`. Исправленная версия сохранила исходное значение `Keep`, а `Edit` дал `58`. Для `Fresh.cs` и созданного после `load_workspace` пустого `Empty.cs` константы из пересобранной DLL обе дали `43 61 66 C3 A9`. Публичный MCP и тесты проверяют диск, опубликованный снимок и повторную загрузку. В Ubuntu 24.04 с SDK 10.0.115 оригинальный префикс `EF BB BF 23 21` приводил к `ENOEXEC`. Созданный после исправления файл начинается с `23 21`, после `chmod 0755` он вывел `DIRECT-CS-OK` и завершился с кодом 0 при прямом запуске через `exec` без shell.

После ревью добавлены проверки без загруженного проекта и с посторонним workspace, а также с семибитными кодировками HZ-GB-2312 и IA5. Неоднозначный патч в проекте HZ оставил соседнюю константу `中` и исходные байты без изменений. В IA5 проверяется весь старый и новый фрагмент, включая общий префикс или суффикс. Безопасная замена вне национального символа сохранила `¤` в собранной DLL. Для кодировочно-зависимого патча по исходнику без BOM вне загруженного графа инструмент просит загрузить проект до записи. Целевой прогон выявил конфликт двух диагностик при непарном суррогате в замене. После исправления этот случай сохраняет исходное сообщение о невозможности кодирования и файл остаётся прежним. Исполнитель `impl44`, ревьювер `review44`. Принято в пятом раунде. [Карточка](../task-44-p1-source-write-reader-encoding-hi.md).

## P1-45

На одном TFM прошёл `Demo.Fixture.Match`, а на соседнем фильтр ничего не нашёл. Ошибочная цель MSBuild после `VSTest` возвращала код 1. В исходной версии пользовательский код `CI-001` приводил к `Filtered tests passed` в полном и усечённом журнале. После исправления как `CI-001`, так и `MSB4181` дали `Test run failed`, код выхода 1, текст исходной диагностики и один прошедший тест. Для усечения перед запуском первого TFM добавлялся журнал объёмом 946 893 байта. В контроле без ошибочной цели команда вернула 0, MCP сообщил об одном прошедшем тесте. В ревью дополнительно проверены обычное сообщение `Expected: error connecting to server: retrying` на успешной сборке и подлинная диагностика с источником `Build validation`.

Исполнитель `impl45`, ревьювер `review45`. Принято во втором раунде. [Карточка](../task-45-p1-test-command-failure-cause-hi.md).

## P2-46

Публичный `run_specific_test` на net10.0 и net11.0 показал ровно два исполнения при `minimal/normal` и `normal/minimal`, в каждом случае оба теста прошли. До исправления первый порядок давал `partial` с нижней границей в одно исполнение. Проект с одним и тремя тестами на тех же платформах дал ровно четыре при обеих комбинациях. Модульные регрессии проверяют запоздалый повтор, явно названное отсутствие совпадений, переплетение запусков и усечение вывода.

Ревью выявило двойной подсчёт запоздавшей подробной сводки, когда для второй сборки сохранилась строка `no-match` либо её запуск прервался. Регрессии охватывают оба порядка уведомления и частичные счётчики при `Total tests: Unknown`. Исполнитель `impl46`, ревьювер `review46`. Принято в третьем раунде.
