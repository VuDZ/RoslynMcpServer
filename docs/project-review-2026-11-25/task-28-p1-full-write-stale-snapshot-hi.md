## Воспроизведение на `9d8b00c`

1. Создать загруженный в Roslyn файл с `X => 1` в UTF-8 без BOM и с окончаниями строк LF. Вызвать `get_diagnostics_for_file`, чтобы материализовать исходный снимок A.
2. До обработки события файлового наблюдателя внешней записью заменить `1` на `2`, сохранив кодировку и LF. Вызвать `update_file_content` с **полным исходным текстом A**, включая те же окончания строк.
3. На `9d8b00c` инструмент вернул `Successfully wrote`, а отдельное чтение диска показало `X => 2`. В том же проекте `apply_patch` смог восстановить `X => 1`.

## Исправление

`EditingTools.WriteFile` передаёт текст в `UpdateDocumentInMemoryAsync`. Для этого пути решение о пропуске сохранения принимается по старому документу Roslyn. Полная перезапись должна учитывать фактический файл даже при совпадении с опубликованным снимком. Сохранить оптимизацию для других документов проекта.

## Критерии приёмки

- [ ] Детерминированный тест фиксирует снимок A и внешнее содержимое B. После успешного `update_file_content(A)` отдельно сравнивает байты файла и текст опубликованного документа с A.
- [ ] Если запись в этом сценарии отклонена файловой системой, ответ сообщает об отказе. Проходят имеющиеся проверки записи только изменённых документов и патча P1-21.
