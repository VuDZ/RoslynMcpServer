## Воспроизведение

Проверена рабочая копия с исправлениями 28–35 поверх `380decf`, Release, Windows, SDK `11.0.100`.

Загрузить SDK-проект с `<CodePage>28591</CodePage>` без `New.cs`. Через `update_file_content` создать `New.cs` с `public class New { public const string Value = "Café"; }`. Инструмент подтвердил запись. В файле нет BOM, `é` представлена байтами `C3 A9`.

Запустить `dotnet run -c Release` и вывести UTF-8-байты константы из собранной DLL. Сборка прошла, фактическое значение — `CafÃ©` (`43 61 66 C3 83 C2 A9`). Запрошенное значение — `Café` (`43 61 66 C3 A9`).

## Исправление

Для файла, который ещё не входит в снимок, `EditingTools.WriteFile` выбирает `SourceTextEncoding.ForDiskPath`. Новый файл получает UTF-8 без BOM, который компилятор читает в заданной кодировке проекта. Использовать однозначное для компилятора представление. Учесть, что фактическое членство нового файла определяется MSBuild при загрузке. Это смежный дефект существовавшего пути создания.

## Критерии приёмки

- [x] Проверить новый исходник в проекте с кодировкой по умолчанию. Для символа вне кодовой страницы допустимы точная запись в однозначном представлении либо явный отказ до создания файла.
