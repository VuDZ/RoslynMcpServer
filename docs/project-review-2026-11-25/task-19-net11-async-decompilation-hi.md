## Основание

Во время работы над P1-04/P2-07 инструмент декомпиляции показал `Stack underflow` для .NET 11 `System.Diagnostics.Process.WaitForExitAsync`. Дефект сначала наблюдался в установленном MCP 1.6.0.0. Текущий проект закрепляет собственную версию декомпилятора, поэтому требуется контрольный запуск на текущей сборке.

## Задача

Установить причину на текущем продукте и вернуть корректный C# для указанного метода. Если сбой относится к зависимости, зафиксировать точную сборку и поддерживаемый способ исправления. Обработка остаточных сбоев должна явно сообщать о неполной декомпиляции.

## Критерии приёмки

- [ ] Контроль на текущем `System.Diagnostics.Process.dll` воспроизводим и фиксирует версию зависимости и runtime. Целевой метод декомпилируется без `Stack underflow` после исправления.
- [ ] Регрессия обращается к продуктовой границе декомпиляции; обычный соседний метод сохраняет корректный результат. При доказанном внешнем блокере статус остаётся открытым с точным воспроизведением и остатком работы.
