# FIX-19. Исправить декомпиляцию async-метода .NET 11

- Рекомендуемые модели: GPT-6.2 Astra.
- Рекомендуемый reasoning: high.
- Примерная сложность: 4/5.
- Риск ошибки: высокий — псевдокод с ошибкой IL может быть принят за действительное тело метода.
- Необходимые способности: IL, async state machine, ICSharpCode.Decompiler.
- Статус: blocked, 2026-11-25. Обновление до ILSpy 11.2.0.10050 проверено. Для `WaitForExitAsync` на .NET 11.0.0 сохраняется некорректный `throw obj`, и MCP сообщает о неполной декомпиляции.
- Depends on: —.
- Модель, реализовавшая задачу: `gpt-6.2-sol`.
- Модели, проводившие ревью: `gpt-6.2-sol`.
- Количество раундов ревью: 2 (частичное исправление и обновление ILSpy).
- Количество исправлений после ревью: 0.
- Отчёт о реализации, ревью и validation: [реализация, проверка ILSpy 11.2 и остаток работы](evidence/task-19-implementation.md).

## Основание

Во время работы над P1-04/P2-07 инструмент декомпиляции показал `Stack underflow` для .NET 11 `System.Diagnostics.Process.WaitForExitAsync`. Дефект сначала наблюдался в установленном MCP 1.6.0.0. Текущий проект закрепляет собственную версию декомпилятора, поэтому требуется контрольный запуск на текущей сборке.

## Задача

Установить причину на текущем продукте и вернуть корректный C# для указанного метода. Если сбой относится к зависимости, зафиксировать точную сборку и поддерживаемый способ исправления. Обработка остаточных сбоев должна явно сообщать о неполной декомпиляции.

## Критерии приёмки

- [x] Контроль на текущем `System.Diagnostics.Process.dll` воспроизводим и фиксирует версию зависимости и runtime. Целевой метод декомпилируется без `Stack underflow` после исправления.
- [ ] Регрессия обращается к продуктовой границе декомпиляции; обычный соседний метод сохраняет корректный результат. При доказанном внешнем блокере статус остаётся открытым с точным воспроизведением и остатком работы.
