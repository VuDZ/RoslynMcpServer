## Воспроизведение

Проверена рабочая копия с исправлениями 28–35 поверх `380decf`, Release, Windows, SDK `11.0.100`.

В валидном решении с настоящими проектами `Old`, `App` и зависимостью добавить блок `<TelemetryExtension><project Path="Old/Old.csproj"/><builddependency Project="Old/Old.csproj"/></TelemetryExtension>`. Контроль с `Missing/Missing.csproj` только внутри расширения проходит `dotnet sln list`. Тот же путь в реальной зависимости даёт ошибку SDK.

`rename_project` изменил оба значения расширения на `New/New.csproj`. По сравнению с базой такое поведение распространилось на имена в нижнем и смешанном регистрах. Ранее оно уже затрагивало каноническое написание.

## Исправление

`RewriteXmlReferences` обходит всех потомков XML и выбирает атрибут по локальному имени элемента. Ограничить изменения элементами и отношениями, которые читает модель решения, с поддержкой допустимых папок и регистра.

## Критерии приёмки

- [x] После реального переименования SDK продолжает видеть оба проекта и зависимость App → New. Значения атрибутов в пользовательском расширении остаются исходными.
- [x] Проверить предварительный просмотр и применение для проектов в папке решения и при смешанном регистре поддерживаемых элементов.
