## Воспроизведение

Проверена рабочая копия с исправлениями 28–35 поверх `380decf`, Release, Windows, SDK `11.0.100`.

В SDK-проекте с `CodePage=0` (свойство опущено) загрузить исходник Windows-1251 без BOM с литералом `Ж Marker`. В проверенной Windows-фикстуре `SourceText` исходного документа имел кодовую страницу 1251. Внешним редактором сохранить тот же текст как UTF-8 без BOM. Отдельная свежая загрузка тех же байтов определила UTF-8 и вернула правильный текст.

До синхронизации прежнего снимка вызвать `apply_patch` с заменой `Marker` на `Б`. Сервер сообщил об успехе. На диске оказались байты `D0 96 20 C1` — исходная `Ж` сохранилась в UTF-8, новая `Б` записалась в Windows-1251. Строгое чтение в UTF-8 завершилось ошибкой.

## Исправление

При значении `CodePage=0` код использует кодировку исторического документа. Выбирать кодировку для актуальных байтов по правилам загрузки исходника и явно сообщать об ошибке, если корректная запись невозможна. Сравнение по коду показывает, что дефект существовал до этого раунда.

## Критерии приёмки

- [x] Тест удерживает исходный снимок и воспроизводит смену кодировки без BOM. После успешного патча файл целиком декодируется в UTF-8 как `Ж Б`, повторная загрузка совпадает с опубликованным документом.
- [x] Сохранить поведение для явной `CodePage`, действующего BOM и стабильного исходника в поддерживаемой однобайтовой кодировке.
