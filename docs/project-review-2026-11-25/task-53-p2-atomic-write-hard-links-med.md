# P2-53. Сохранять целостность жёстких ссылок при записи файла

- Рекомендуемые модели: GPT-6.2 Sol.
- Рекомендуемый reasoning: high.
- Примерная сложность: 3/5.
- Риск ошибки: средний. Два пути к одному файлу после успешной записи показывают разное содержимое.
- Необходимые способности: файловая идентичность NTFS и POSIX, атомарная замена и совместимость существующего контракта записи.
- Статус: accepted, 2026-11-25. Атомарная запись отклоняет замену файла с несколькими жёсткими ссылками и сохраняет обе ссылки и байты. [Приёмка](evidence/tasks-49-54-validation.md#p2-53).
- Повторная приёмка, 2026-11-26. Имя `libSystem.Native` проверено через запись существующего файла и отказ для жёстких ссылок в обеих Linux-публикациях полного сервера. [Результаты](evidence/tasks-49-54-validation.md#linux-self-contained-и-single-file).
- Depends on: —.
- Отчёт о воспроизведении: [повторное ревью](evidence/review-f82d4ff.md#p2-53).

## Воспроизведение

1. В пустом каталоге на NTFS создать `shared.txt` с содержимым `before\n`. Создать жёсткую ссылку `alias.txt` на тот же файл с помощью `os.link("shared.txt", "alias.txt")`. Проверить `os.path.samefile("shared.txt", "alias.txt") == True`.
2. Вызвать `update_file_content` для абсолютного пути `shared.txt` с текстом `after\n`. MCP возвращает `Successfully wrote`.
3. `samefile` теперь возвращает `False`. `shared.txt` содержит `after\n`, а `alias.txt` сохраняет `before\n`.

## Причина и требуемое поведение

`ReplaceStagedFile` назначает подготовленный файл одному имени. Остальные имена продолжают ссылаться на прежний файл. Запись непосредственно в существующий файл в базе `5639268` сохраняла общую файловую идентичность. Определить поддерживаемое поведение для файла с несколькими жёсткими ссылками. Допустим явный отказ до замены, если сохранение связей несовместимо с гарантиями атомарности.

## Критерии приёмки

- [x] При успешной записи оба имени по-прежнему обозначают один файл и читают новое содержимое. При отказе общая файловая идентичность и исходные байты сохраняются.
- [x] Проверить атомарную запись обычных файлов, запись через символические ссылки, отмену и отказ.
