# P2-05. Сохранить явно выбранное решение при конкурирующей автозагрузке

- Рекомендуемые модели: GPT-6.2 Astra.
- Рекомендуемый reasoning: high.
- Примерная сложность: 4/5.
- Риск ошибки: высокий — анализ может продолжиться на другом решении.
- Необходимые способности: публикация workspace, конкурентные тесты, жизненный цикл анализаторов.
- Статус: accepted, 2026-11-25. Приняты проверка опубликованного снимка под семафором и сохранение явно выбранного решения.
- Depends on: —.
- Модель, реализовавшая задачу: `gpt-6.2-sol`.
- Модели, проводившие ревью: `gpt-6.2-sol`.
- Количество раундов ревью: 1.
- Количество исправлений после ревью: 0.
- Отчёт о реализации, ревью и validation: [приёмка](evidence/task-05-implementation.md).

## Основание

Семантический запрос проверяет пустой workspace до получения семафора. Пока явная загрузка B не опубликовала снимок, запрос может поставить в очередь A из конфига и заменить B после освобождения семафора. Сценарий выведен из порядка операций.

## Задача

Под семафором проверить, требуется ли конфигурационная загрузка после завершения ожидаемой явной загрузки. Сохранить поведение при первой загрузке и ошибке.

## Критерии приёмки

- [x] Управляемый тест с двумя различимыми решениями заводит B первым, затем семантический запрос. После успешной явной загрузки запрос и последующая навигация видят B.
- [x] Проверить обычную загрузку из конфига и существующий контракт после отказа или отмены явной загрузки. Для изменённого пути публикации выполнить также `AnalyzerLifecycle`.
