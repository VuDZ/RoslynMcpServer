## Воспроизведение

1. Создать в каталоге `Tests in Review` xUnit-проект со сборками для `net10.0` и `net11.0`. Тест `Demo.Fixture.Match` существует только в первой сборке. Запуск последовательный, для первой платформы используется консольный логгер `minimal`, для второй — `normal`.
2. Вызвать `run_specific_test` для `Demo.Fixture.Match`. CLI возвращает 0, печатает один прошедший тест и сообщение об отсутствии совпадений для второй сборки. MCP возвращает `partial` и `Total tests: unknown`, хотя журнал полон.
3. Тот же проект в каталоге `TestsReview` даёт `Filtered tests passed` и `Total: 1`.

## Исправление

`GetNoMatchSource` ищет последнее ` in ` в строке, поэтому отделяет хвост пути `Review\bin\…\Demo.dll` от остального имени. Определять границу пути по структуре сообщения VSTest и сопоставлять полный путь с наблюдавшимся запуском.

## Критерии приёмки

- [x] В указанном сценарии отчёт MCP даёт `Filtered tests passed` и ровно один прошедший тест. Пробелы и ` in ` в пути сохраняются.
- [x] Контроль без ` in ` в пути и проверки P2-46 для запоздавшей сводки проходят. Неоднозначный усечённый вывод по-прежнему допускает только подтверждённую нижнюю границу.
