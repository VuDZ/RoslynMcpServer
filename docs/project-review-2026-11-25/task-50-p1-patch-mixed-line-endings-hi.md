- Рекомендуемые модели: GPT-6.2 Astra.
- Рекомендуемый reasoning: high.
- Примерная сложность: 3/5.
- Риск ошибки: высокий. Патч может изменить значение литерала, которого нет в заменяемом фрагменте.
- Необходимые способности: сопоставление текстовых диапазонов, сохранение исходных байтов, проверка скомпилированного литерала.
- Статус: accepted, 2026-11-25. Патч сохраняет исходные байты вне диапазонов замены при смешанных переводах строк. [Приёмка](evidence/tasks-49-54-validation.md#p1-50).

## Воспроизведение

1. В исполняемом проекте `net11.0` создать `Program.cs` в UTF-8 без BOM. Внутри verbatim-литерала между `A` и `B` записать LF. После закрывающей кавычки и на остальных строках использовать CRLF. Минимальное содержимое удобно записать побайтно.

   ~~~python
   from pathlib import Path

   Path("Program.cs").write_bytes(
       b'var keep = @"A\nB";\r\n'
       b'var edit = "X";\r\n'
       b'System.Console.WriteLine(edit);\r\n'
       b'System.Console.WriteLine(string.Join(" ", System.Linq.Enumerable.Select(keep, c => ((int)c).ToString("X4"))));\r\n'
   )
   ~~~

2. Убедиться, что `dotnet run -c Release` печатает `0041 000A 0042`. Загрузить проект и вызвать `apply_patch`, передав `var edit = "X";` в `oldString` и `var edit = "Y";` в `newString`.
3. Инструмент подтверждает одну замену. В соседнем литерале байты `41 0A 42` превращаются в `41 0D 0A 42`. Повторная успешная сборка печатает `0041 000D 000A 0042`.

## Причина и требуемое поведение

Инструмент сопоставляет фрагмент на нормализованном тексте. `RestorePreferredLineEndings` затем применяет CRLF ко всему результату при наличии хотя бы одного исходного CRLF. Сохранять оригинальные границы строк в незатронутых диапазонах при переносе найденной замены в исходный текст.

## Критерии приёмки

- [x] В указанном сценарии меняется только `X` на `Y`, а соседние байты и кодовые единицы `keep` остаются прежними.
- [x] Сохранить точное и гибкое сопоставление, `replaceAll` и обработку однородных LF и CRLF.
