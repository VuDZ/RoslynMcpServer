# Инструменты отладчика через MCP

Дата: **2026-10-22**. Статус: **deferred — решение владельца не строить, пока
нет фактов пользы**. Реализация не начиналась.

## Идея

Группа MCP-инструментов поверх Debug Adapter Protocol (клиент к netcoredbg;
vsdbg вне VS/VS Code лицензией не разрешён): запуск теста или процесса под
отладчиком, точки останова по file:line, вычисление выражений.

Ценность ожидается не от пошаговой отладки, а от режимов без долгой остановки:

1. Logpoint/снимок по условию — стек и состояние при выполнении условия,
   без правки кода и пересборки, затем продолжение.
2. Остановка на first-chance исключении с фильтром по типу.
3. Снимок всех потоков при зависании.

## Почему отложено

Разбор на случаях 2026-10-22 не нашёл, где это дало бы больше имеющихся средств:

- Гонка watcher/flush в `WorkspaceNonCSharpDiskSyncTests`: остановка меняет
  тайминги; хватает логгера и тестовых хуков `DuringContentReadForTests` /
  `DuringDiskFlushForTests`, цикл «лог → сборка → прогон» — минуты.
- Офисные I/O-задержки первого поиска ([workspace-load-performance E0/task-09](../workspace-load-performance/epoch-0-stage-measurement/task-09-first-search-io-and-private-project-profile-hi.md)):
  на машинах коллег не будет отладчика и агента; нужен `dotnet-trace` с событиями исключений.
- Зависания: стеки и дампы дают `dotnet-stack` и `dotnet-dump` из командной строки.
- Поведение Roslyn: хватило декомпиляции и изолированного probe.

Единственное уникальное свойство — logpoint без пересборки с доступом к
приватному состоянию. Его выигрыш мал по сравнению с ценой: DAP-клиент,
netcoredbg на Windows и Linux, подключение к testhost (`VSTEST_HOST_DEBUG`),
привязка точек через PDB, чтение async-стеков.

## Условие возврата

Вернуться к идее, если накопятся 2–3 задокументированных случая, где работу
реально тормозила пересборка ради логов или невозможность пересобрать
(чужой процесс, офисная машина), и описать их как сценарии приёмки.

## Что используется вместо

На машине разработки установлены глобальные инструменты `dotnet-trace`,
`dotnet-stack` и `dotnet-dump` (10.0.750501, `dotnet tool install -g`):
трассировка исключений и CPU, стеки потоков, дампы при зависании.
