# Backlog документации

Отложенные программы и их историческое evidence. Эти документы не являются
активным маршрутом реализации; возвращение к программе требует отдельного
решения владельца. Backlog отличается от архива завершённых работ.

- [Workspace load cache v2](workspace-load-cache/README.md) — **заморожено 2026-11-21**
  вместе с [workspace state cache](../workspace-state-cache/README.md); документы и тесты
  удалены из `main`, история — в теге `archive/research-workspace-state-cache`.
- [Инструменты отладчика через MCP](debugger-tools.md) — **deferred,
  2026-10-22**. Решение владельца: не строить, пока не накопятся 2–3 случая,
  где отладчик дал бы больше `dotnet-trace`/`dotnet-stack`/`dotnet-dump` и логов.

- **Загрузка workspace только через solution** — **backlog, 2026-11-04;
  реализация не начата**. Нужна настройка в конфиге/опциях сервера, которая при
  включении запрещает отдельный `.csproj` как точку входа и разрешает только
  `.sln` / `.slnx`. Запрет действует для явного `load_workspace`, автозагрузки
  через `workspace-path` и автоматического поиска workspace; fallback на
  `.csproj` не допускается. Отказ должен происходить до design-time build,
  с понятной диагностикой и предложением загрузить solution. C#-проекты внутри
  решения загружаются как обычно. Причина: при открытии отдельного `.csproj`
  Roslyn не задаёт `SolutionDir`, поэтому перенаправление intermediate outputs
  через это свойство может не сработать и создать локальные `obj/`.

Актуальные планы перечисляются в [индексе docs](../README.md).
Учёт моделей и ревью ведётся по [общему стандарту](../README.md#учёт-задач-ревью-и-статистики).
