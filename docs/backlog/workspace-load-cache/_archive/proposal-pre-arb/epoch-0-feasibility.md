# Epoch 0 — Проверить возможность и измерить исходное состояние

Статус: **proposed**. Ни новых публичных параметров, ни production disk-hit.

## Задача

Ответить на два вопроса: можно ли публичными API восстановить эквивалентный
workspace для ограниченного профиля и окупается ли проверка входов на реальном
большом решении. Не начинать с собственного Merkle или SQLite.

## Работа

1. Зафиксировать версии пакетов, SDK/MSBuild, конфигурацию, TFM, оборудование и
   выбранное большое решение. Собрать baseline по [протоколу](verification.md).
2. В изолированном эксперименте загрузить решение обычным MSBuild, извлечь DTO,
   закрыть workspace и восстановить новый через публичные API.
3. Сопоставить DTO и поведение с независимой свежей MSBuild-загрузкой, включая
   diagnostics, navigation, source generator и analyzer configs.
4. Установить, откуда получать resolved DTB inputs и provenance imports/tasks.
   Для каждого поля контракта назвать публичный API или поддерживаемый способ
   получения. Не использовать reflection к внутренностям Roslyn как обход.
5. Определить конкретный первый профиль поддержки и алгоритм распознавания.
   Включить отрицательные зависимости/условные imports. Если достоверное
   распознавание невозможно, зафиксировать no-go для данного профиля.
6. Отдельно исследовать `LoadMetadataForReferencedProjects`: одинаковый граф
   через `.sln` и `.csproj`, true/false, DLL есть/нет/устарела/повреждена.
   Не считать изменение свойства доказательством ускорения или safe fallback.

Экспериментальные файлы и fixtures должны быть изолированы от production пути.
Результаты не требуют выпуска фичи и не меняют defaults.

## Приёмка

- Пройдены V01–V06 из матрицы для заявленного профиля; неподдерживаемые случаи
  явно перечислены, а не замаскированы под успешный snapshot.
- Есть таблица API -> поля DTO -> проверяемые входы -> ограничения.
- Есть измерения load + первого semantic-запроса, DTB count и peak memory.
- Проверены хотя бы обычный SDK-проект, условное членство и generator/config
  fixture; последний может закончиться обоснованным unsupported.
- Задан конкретный perf budget для Epoch 2. Предложение: median времени до
  первого полезного ответа не более 70% baseline на согласованном большом
  решении, p95 не хуже baseline. Это цель, не уже полученный результат.

## Handoff

`epoch-0-handoff.md`: go / revise / stop, профиль поддержки, воспроизводимые
команды, сырые замеры, расхождения, оценка стоимости strict probes. Если большого
решения нет, функциональный прототип допустим, но performance-gate остаётся
непройденным; нельзя объявлять полезность ускорения доказанной.
