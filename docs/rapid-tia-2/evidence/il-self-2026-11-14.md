Первая проверка [гипотезы rapid TIA 2](../README.md): граф зависимостей между типами из IL и PDB.
Сводка без имён — [il-self-2026-11-14-summary.json](il-self-2026-11-14-summary.json).

## Запуск

```bash
dotnet build RoslynMcpServer.Tests/RoslynMcpServer.Tests.csproj -c Release
dotnet spikes/TestImpactIlProbe/bin/Release/net10.0/TestImpactIlProbe.dll measure --root . --bin RoslynMcpServer.Tests/bin/Release --sample 40 --seed 7 --out il-final
```

Машина: Ubuntu 26.04.1, .NET 10.0.14, 2 процессора, 3843 МБ. Репозиторий на `88b8dd1`, спайк на момент
прогона не закоммичен.

## Сверка с обратным поиском

Старая проба (`AffectedTestsProbe impact --sample 60 --seed 7`) дала ответы для 60 членов production-кода;
51 ответ непустой. Для типа каждого члена взят ответ спайка в слое `references` и проверено, что он содержит
все тестовые классы обратного поиска.

| Результат | Членов |
| --- | --- |
| Ответ спайка содержит все классы обратного поиска | 39 |
| Не хватает одного класса `AnalyzerLifecycleHostTests` | 20 |
| `IsolatedHydratedSession.Dispose`: обратный поиск вернул все 167 классов, спайк — 3 | 1 |

- **`AnalyzerLifecycleHostTests`** запускает `RoslynMcpServer.LifecycleTestHost` отдельным процессом и
  обращается к production-коду только через него. В IL теста остаются типы протокола хоста и константа
  `AnalyzerShadowPolicy.LayoutSegment`, которую компилятор скопировал. Это граница «другой процесс» из
  [списка](../README.md#что-граф-не-видит); потеря настоящая.
- **`Dispose`**: обратный поиск поднялся через `IDisposable.Dispose` ко всем вызовам `Dispose` в solution.
  Спайк выбрал три класса, которые достигают самого типа. Расхождение разобрано по коду, прогоном тестов
  не проверено.
- В 9 случаях обратный поиск не нашёл ни одного теста, а спайк нашёл: на уровне класса тест достигает типа,
  хотя, возможно, не этого члена.

Медиана размера ответа по тем же 60 членам: обратный поиск — 8 тестовых классов, спайк — 28 из 167.

## Границы проверки

- Это не проверка полноты: обратный поиск сам не эталон. Эталон по покрытию не делался.
- Solution маленький: одна тестовая сборка, почти нет DI. Слои `discovery` и `wholeAssembly` здесь почти не
  отличаются от `references`, и о цене правил обнаружения прогон ничего не говорит.
- Правила слоёв проверены 22 тестами спайка на маленьких типах-примерах, не на настоящем контейнере.
