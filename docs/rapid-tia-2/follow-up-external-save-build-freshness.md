# Сужение после внешней правки и сборки до первой оценки

Статус: **accepted 2026-11-19**. Подхват внешней правки сохраняет байты и timestamp исходника. Первая оценка
после сборки сужает выбор, следующая правка без сборки сохраняет выбор целого проекта. Проверено на Windows
и в шести внешних пробах полного Jellyfin. [Проверка и замер](mvp/evidence/follow-ups-jellyfin-2026-11-19.md).

Задача заведена по [замеру task-06](mvp/task-06-implementation-report.md#замер-на-этом-репозитории).

На Windows в **1.8.1** последовательность «запись вне MCP → успешная сборка → первый estimate» дала
ложную причину `not newer than the last edit`. В пробе 13 выход был записан в `09:46:01.3005572Z`.
Синхронизация через `MSBuildWorkspace.TryApplyChanges` оставила mtime того же сохранённого исходника
`09:46:02.1584688Z`. В `09:46:02.169Z` сервер записал `workspace_disk_sync updated=1 write=FullSuccess`.
Оценка сравнила выход с более новым временем синхронизации.

Воспроизвести проблему на Windows через реальную загрузку, внешнюю запись и MSBuild. Исправить ложную
инвалидацию при подхвате текста, который сборка уже прочитала. В регрессии первый estimate после сборки
должен давать сужение без промежуточного запроса для синхронизации. Следующая содержательная правка того же
исходника без сборки должна вернуть целый проект по правилу свежести. Проверить сохранность пользовательских
данных и работу наблюдения внешних изменений. Выполнить Release build, SourceStructure, основной suite
и AnalyzerLifecycle, если исправление затрагивает его путь публикации workspace, по
[AGENTS.md](../../AGENTS.md).
