## Цель

Показать ступени агенту и запускать выбранную. Это единственная задача плана, которая меняет то, что видит
агент. Поверхность — по [M-01 и M-03](README.md#решения-владельца-по-плану): инструмент остаётся прототипом,
совместимость с ответом эпохи 1 не требуется.

## Конкретный результат

**Параметр.** У `estimate_affected_tests` появляется `depth`: `changed` (ступень 0), `direct` (до 1), `di`
(до 2), `all` (до 3). По умолчанию `all`. Остальные параметры прежние.

**Ответ без `run`.**

- Первая строка по-прежнему говорит, сколько изменено с загрузки; к ней добавляется число типов, код которых
  изменился в сборках.
- Для каждого суженного тестового проекта — размер каждой ступени в классах, в том числе шире выбранной, и
  фильтр для выбранной ступени. Агент видит, сколько классов добавит расширение.
- Для проекта, который остался целиком, — причина одной строкой, как в эпохе 1. Причина «сборки не
  пересобраны» сопровождается подсказкой собрать и повторить вызов (M-04).
- Проект, выбранный эпохой 1, у которого все ступени пусты, назван отдельно одной из двух строк (решение
  владельца [M-05](README.md#решения-владельца-по-плану)):
  - отпечатки не изменились — «код в сборках не изменился, тестов нет»;
  - отпечатки изменились, тестовый класс не найден — сколько типов изменилось, что ни один тестовый класс
    проекта до них не дошёл и что граф не видит типы, названные строкой или в конфигурации. Имена первых
    изменившихся типов показаны и без `includeDetails`; решение, что запускать, остаётся за агентом.
- `includeDetails: true` перечисляет классы по ступеням и изменившиеся типы.
- Предупреждение «не замена полного прогона и CI» сохраняется. Строка `State: project-level result only.`
  заменяется состоянием, которое называет выбранную ступень.

**Порядок `run: true`.** Сейчас план считается до сборки, и проект идёт целиком. Новый порядок для каждого
тестового проекта из ответа эпохи 1:

1. сборка проекта, как сейчас;
2. обновление текущего снимка (task-03);
3. сужение (task-04) для выбранной ступени;
4. запуск фильтра без повторной сборки либо проекта целиком, если он не сужен.

Сборка упала — исход прежний, сужения нет. Все ступени пусты — тестовый процесс не запускается в обоих исходах
M-05, и ответ называет, какой из них случился. Исход такого проекта не «тесты прошли», а отдельное значение
«не запускался». Отмена и таймауты ведут себя как в эпохе 1.

## Проверки

- Форматтер: суженный проект показывает четыре размера и фильтр выбранной ступени; проект целиком — причину;
  `includeDetails` перечисляет классы по ступеням.
- Форматтер, пустые ступени, два отдельных случая: при равных отпечатках — строка «код не изменился»; при
  изменившихся — число и имена изменившихся типов и строка, что тестовый класс до них не дошёл. Слов «код не
  изменился» во втором случае в ответе нет.
- `depth`: каждое значение даёт фильтр своей ступени; неизвестное значение — ошибка с перечнем допустимых.
- Правка без сборки, `run: false`: проект целиком, причина «не пересобрано», подсказка собрать.
- Настоящий MSBuild, `run: true`:
  - правка тела метода: собрано, запущены классы выбранной ступени, а не проект целиком;
  - `depth: direct` запускает меньше классов, чем `all`, на фикстуре, где ступени различаются;
  - правка комментария: собрано, тестовый процесс не запущен, в ответе названа причина;
  - правка тела типа, до которого тесты не доходят: собрано, тестовый процесс не запущен, тип назван;
  - правка, сборка через `run: true`, вторая правка другого типа, вызов с `run: false`: проект целиком с
    причиной «не пересобрано»;
  - правка `const`: класс, использующий её, запущен;
  - ошибка компиляции: исход «сборка упала», сужения нет;
  - первая правка сразу после загрузки, когда снимок «до правки» ещё не прочитан: проект целиком с причиной.
- Запуск после сужения не собирает проект второй раз (по журналу команд).
- Существующие сценарии эпохи 1 для новых и изменённых тестов, не-C# входов и разрыва наблюдения проходят с
  обновлённым текстом ответа.
