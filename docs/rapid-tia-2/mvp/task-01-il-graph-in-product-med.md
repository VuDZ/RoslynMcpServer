## Цель

Перенести в продукт чтение метаданных и IL и граф зависимостей между типами верхнего уровня из спайка
[`TestImpactIlProbe`](../../../spikes/TestImpactIlProbe/README.md) как внутренний сервис. Инструмент и ответ
`estimate_affected_tests` эта задача не меняет.

## Конкретный результат

- Внутренний сервис в `Services/Testing/Il` (модели — в `Services/Testing/Il/Models`). На входе три значения:
  пути выходных сборок загруженных проектов (`OutputFilePath`), признак тестового проекта и карта соседства
  (ниже). На выходе — граф и ответы на вопрос «до каких типов доходит тестовый класс» для каждой из трёх
  ступеней.
- Чтение одной сборки отделено от построения графа: результат чтения сборки — самостоятельное значение, из
  набора таких значений граф строится без повторного чтения файлов. task-03 перечитывает только изменившиеся
  сборки.
- **Как читается файл.** Файл открывается с общим доступом на чтение, запись и удаление
  (`FileShare.ReadWrite | FileShare.Delete`), целиком читается в память и закрывается; разбор идёт по буферу.
  `File.OpenRead` спайка не переносится: он запрещает запись, и на Windows сборка агента, попавшая в окно
  чтения, упала бы с ошибкой доступа. Отпечатки task-02 считаются из того же буфера, второй раз файл не
  открывается.
- Узел графа — тип верхнего уровня; вложенные типы, лямбды и автоматы `async` относятся к внешнему типу. Рёбра
  и правила слоёв — как в спайке: [что в графе](../../../spikes/TestImpactIlProbe/README.md#what-is-in-the-graph),
  [слои](../../../spikes/TestImpactIlProbe/README.md#layers).
- Три ступени: `references`, `discovery`, `discoveryWithLoads`. Слои `wholeAssembly`, `referencesWithLoads` и
  `discoveryWithNamedLoads` не переносятся.
- Тестовый класс определяется, как в спайке: неабстрактный тип с методами под атрибутом xUnit, NUnit или
  MSTest, унаследованные тестовые методы считаются.
- **Карта соседства** для правила загрузки по имени (решение владельца
  [M-06](README.md#решения-владельца-по-плану)): для каждого тестового проекта — сборки solution, файл с именем
  которых лежит в каталоге его выходной сборки. MSBuild копирует туда проекты, на которые тесты ссылаются;
  выходной путь самого проекта-зависимости лежит в другом каталоге и соседством не служит. Карту строит
  вызывающая сторона одним перечислением файлов каталога, без обхода вглубь; копии не читаются, код берётся из
  выходной сборки проекта. Сборки не из solution (NuGet, BCL) в карту не входят. Каталоги других проектов, куда
  скопирована тестовая сборка, не учитываются: в спайке `Deployed` их учитывал, и ступень 3 продукта может
  быть у́же измеренного слоя `discoveryWithLoads` ровно на эту разницу.
- PDB не читается.
- **Целевые платформы.** Каталоги `bin` не обходятся; в граф входят только загруженные проекты. Если workspace
  загрузил проект под несколько целевых платформ (несколько проектов с одним именем сборки), их результаты
  чтения объединяются в один узел сборки, как в спайке. Платформы, которых в workspace нет, в граф не
  попадают.
- Сборка, которой нет на диске или которую не удалось прочитать, не роняет построение: она возвращается
  отдельным списком с причиной, граф строится по остальным.

## Проверки

Тесты не зависят от выхода сборки репозитория: исходники случаев компилируются в тесте (Roslyn, сборка в
память или во временный каталог). Случаи берутся из тестов и `Fixtures` спайка.

- Рёбра: базовый тип и интерфейс, сигнатура, атрибут и его `typeof`, локальная переменная, токен типа, метода и
  поля в IL, лямбда, автомат `async`, `switch` по типу. Константа и `nameof` ребра не дают.
- `references`: тестовый класс доходит до типа по цепочке рёбер и не доходит до несвязанного типа.
- `discovery`: сборка, отданная в рефлексию (`typeof(X).Assembly`, обобщённый метод вида
  `FromAssemblyOf<T>()`), даёт реализации достигнутого типа и типы, обращённые к фреймворку; тип той же сборки
  без такого признака не даёт. `Assembly.GetEntryAssembly()` не считается.
- `discoveryWithLoads`: тестовый класс, доходящий до `Assembly.Load*`, `AssemblyLoadContext.Load*` или
  `AppDomain.GetAssemblies`, зависит от всех типов сборок рядом с его тестовой сборкой; класс без такого вызова
  сохраняет ответ `discovery`.
- Карта соседства, раздельные каталоги: `Lib` и `Tests` собраны в разные каталоги, копия `Lib.dll` лежит рядом
  с `Tests.dll`. Тест с `Assembly.Load`, который `Lib` в коде не называет, на ступени 3 зависит от типов `Lib`.
  Без копии рядом — не зависит. Сборка не из solution рядом с тестовой в ответ не входит. Каталог третьего
  проекта, куда скопирована `Tests.dll`, ответ не расширяет.
- Чтение не держит файл: пока чтение остановлено на точке остановки, другой поток перезаписывает и удаляет
  файл без ошибки доступа. Случай обязателен в прогоне на Windows.
- Сверка со спайком на сборках этого репозитория: ответы ступеней 1 и 2 совпадают с слоями `references` и
  `discovery` спайка; расхождения ступени 3 с `discoveryWithLoads` перечислены в отчёте и объясняются только
  чужими каталогами. Сверка ручная: спайк в solution не входит.
- Каждая ступень включает предыдущую: проверяется на всех случаях выше.
- Тестовые классы: xUnit, NUnit, MSTest; абстрактный класс не тестовый, наследник с унаследованными тестами —
  тестовый; тестовый класс не достигается другим тестом через рефлексию по сборке.
- Отсутствующая и повреждённая сборка: построение не падает, сборка названа с причиной.
- Граф из прочитанных значений равен графу, построенному чтением тех же файлов заново.
- На сборках этого репозитория: время построения и пиковая память записываются в отчёт. Порога нет; спайк на
  нём же дал 1,1 с и 81 МБ ([evidence](../evidence/il-self-2026-11-14.md)).
