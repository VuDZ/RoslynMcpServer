## Реализация

- `depth` принимает `changed`, `direct`, `di` и `all`. По умолчанию выбирается `all`. Те же значения
  указаны в описании инструмента и в ошибке неверного параметра. `State` отражает выбранную ступень.
- Оценка сообщает число изменившихся типов, обнаруженных в сравнённых сборках. Для суженного проекта
  видны все четыре размера и фильтр выбранной ступени. `includeDetails` показывает классы по ступеням и
  изменившиеся типы. Причина выбора целого проекта остаётся в ответе, а устаревшие сборки сопровождаются
  подсказкой собрать и повторить вызов. Для прямых фильтров в счётчик тоже попадают изменения типов,
  обнаруженные в известных и свежих сборках.
- В режиме `run: true` загрузка текущих снимков и сужение происходят после успешной сборки выбранного
  проекта. Команда VSTest получает итоговый фильтр и `--no-build --no-restore`. При ошибке сборки запуск
  тестов не начинается. Ранее выбранные прямые тесты сохраняют фильтр эпохи 1, когда расширения до проекта
  не было. У каждого процесса остаётся отдельный таймаут. Решение, карту входов, baseline и параметры
  CLI инструмент захватывает вместе после дисковой синхронизации. Сборка, чтение сборок и VSTest проходят
  за пределами блокировки workspace. Перезагрузка между проектами не меняет конфигурацию текущего запроса.
- Пустая выбранная ступень даёт `not run`. Когда пусты все ступени, ответ сообщает, совпали ли отпечатки
  или граф не нашёл тестовый класс для изменившихся типов. Во втором случае имена видны и в кратком ответе.
  По `run: true` текстовая правка, эквивалентная по синтаксису, доводится до сборки и сравнения отпечатков.
  Это позволяет установить исход для правки только комментария. Обычная оценка сохраняет правило сравнения
  таких правок эпохи 1.

Описания MCP, README EN/RU, `AGENTS.md.sample`, архитектура и CHANGELOG обновлены. Правила построения
ступеней из task-04 используются в исходном виде, включая переход на целый проект при невозможности
построить фильтр на выбранной ступени (M-11).
