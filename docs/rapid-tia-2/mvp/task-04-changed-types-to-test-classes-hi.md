## Цель

По двум снимкам task-03 и ответу эпохи 1 получить для каждого тестового проекта, выбранного целиком, тестовые
классы по ступеням либо причину, по которой проект остаётся целиком. Текст ответа и параметры инструмента эта
задача не меняет: результат — внутренняя модель для task-05.

## Конкретный результат

**Изменившиеся типы.**

- Изменившиеся, добавленные и удалённые типы берутся из сравнения отпечатков.
- Для изменившегося типа зависимые ищутся по обоим графам, «до правки» и текущему, и объединяются. Причина:
  правка может убрать саму связь. Тип, с которого сняли интерфейс или атрибут регистрации, в текущем графе
  сканированием сборки уже не находится, а тест, проверявший его регистрацию, затронут.
- Для добавленного типа зависимые ищутся по текущему графу, для удалённого — по графу «до правки».
- Тестовый класс, найденный только по графу «до правки» и отсутствующий в текущем инвентаре, в ответ не входит.
- Изменившийся отпечаток сборки (ресурс, атрибут сборки) делает изменившимися все типы этой сборки.

**Ступени** — как в [плане](README.md#ступени-ответа); каждая включает предыдущие.

- Ступень 0: тестовые классы с изменившимся отпечатком и новые или изменённые тесты эпохи 1.
- Ступени 1–3: тестовые классы, которые доходят до изменившегося типа в слоях `references`, `discovery`,
  `discoveryWithLoads`.

**Какой проект сужается.** Только тестовый проект, который эпоха 1 выбрала целиком из-за правки C#-кода в нём
или в проекте, от которого он зависит. Причина выбора становится значением в модели
([`TestImpactResult`](../../../Services/Testing/Models/TestImpactResult.cs) сейчас хранит её текстом); текст
причины код не разбирает. Проект, которого нет в ответе эпохи 1, сужение не добавляет.

**Когда проект остаётся целиком** — с названной причиной:

- у сборки на пути нет снимка «до правки» либо она неизвестна по правилу гонки task-03;
- сборка проекта с изменёнными C#-документами не пересобрана после последней правки: файл сборки не новее
  самого позднего изменённого документа этого проекта (решение владельца
  [M-04](README.md#решения-владельца-по-плану)). Условие не зависит от того, отличаются ли отпечатки от снимка
  «до правки»: после цикла «правка → сборка → ещё одна правка без сборки» отпечатки уже другие, а сборка всё
  равно старая. Изменённый документ без времени правки (удалён) оставляет проект целиком;
- сборка на пути от изменённого проекта к тестовому, включая тестовую, не пересобрана после изменения формы
  зависимости: она старше файла, по которому MSBuild решает, перекомпилировать ли зависимых. У проекта со
  ссылочной сборкой это `OutputRefFilePath`: от правки тела она не меняется, и условие не срабатывает. У
  проекта, который ссылочную сборку не создаёт (свойство пусто), это его выходная сборка: MSBuild тогда
  перекомпилирует зависимых при любой правке, и после сборки тестового проекта условие тоже не срабатывает.
  Срабатывает оно, когда собран только проект-зависимость
  ([опыт](../evidence/il-build-diff-self-2026-11-15.md#дополнение-проект-без-ссылочной-сборки)). Свойство
  задано, а файла нет — проект целиком;
- проект выбран по другой причине: не-C# вход, файл проекта, устаревший граф проектов, разрыв наблюдения;
- сборка на пути не читается, либо прочитана, но часть тел её методов не разобрана: рёбра из таких тел в
  граф не попали (уточнение по ревью task-01);
- фильтр по классам не укладывается в бюджет
  [`VstestRunPlanner`](../../../Services/Testing/VstestRunPlanner.cs).

**Пустые ступени — два разных исхода** (решение владельца [M-05](README.md#решения-владельца-по-плану)). В
обоих проект целиком не подставляется; модель называет, какой из двух случился.

- **Код не изменился.** Проект выбран эпохой 1, сборки свежие, ни один отпечаток типа и сборки на его пути не
  изменился (правка комментария).
- **Изменившиеся типы без тестов.** Отпечатки изменились, но ни один тестовый класс проекта до изменившихся
  типов не дошёл. Так выглядит и код без тестов, и связь, которой в IL нет (тип назван строкой). Модель
  содержит изменившиеся типы; что запускать дальше, решает агент.

**Сопоставление с тестами эпохи 1.** Узел графа — тип верхнего уровня. Ему соответствуют классы
[`VstestTestClass`](../../../Services/Testing/Models/VstestTestClass.cs) с тем же типом верхнего уровня,
включая вложенные. Класс инвентаря, которому узел не найден, входит в ступень 1 и шире. Правила планировщика
для класса без имени в рантайме и для фикстур с аргументами сохраняются: такой проект идёт целиком.

**Выход.** Для тестового проекта — либо ступени со списками классов и причинами, либо «целиком» с причиной.
Планировщик умеет построить фильтр по классам ступени.

## Вне scope

- Сужение без сборки по именам типов из синтаксиса.

## Порядок работы — TDD

Тесты из раздела «Проверки» пишутся первыми и падают по ожидаемой причине; красный прогон записывается в отчёт.

## Проверки

Случаи — исходники, скомпилированные в тесте в две версии, как в task-02; снимки собираются из них без диска,
времена файлов сборок и документов задаёт тест.

- Правка тела метода в `A`: ступень 1 — тесты, ссылающиеся на `A`; ступень 2 добавляет тест, получающий `A`
  через сканирование сборки; ступень 3 добавляет тест с загрузкой по имени; несвязанный тестовый класс не входит
  ни в одну.
- Правка комментария при свежих сборках: ступени пусты, исход «код не изменился», проект не идёт целиком.
- Правка тела типа, до которого не доходит ни один тест: ступени пусты, исход «изменившиеся типы без тестов»,
  тип назван, проект не идёт целиком.
- Снятый интерфейс: `Handler : IService` перестаёт реализовать `IService`; тест, который сканирует сборку и
  считает реализации `IService`, а `Handler` в коде не называет, выбран на ступени 2. То же для снятого
  атрибута, по которому тип находит фреймворк.
- Повторная правка без сборки: правка `A`, сборка, правка независимого `B` без сборки. Отпечатки отличаются от
  снимка «до правки», сборка старше документа `B`: проект целиком с причиной «не пересобрано».
- Проект без ссылочной сборки: собраны и зависимость, и тесты — сужается; собрана только зависимость —
  тестовый проект целиком. Проект со ссылочной сборкой, правка тела, собрана только зависимость — сужается.
- Правка `const`: тестовый класс, использующий её, — в ступени 0.
- Правка теста: он в ступени 0 и по эпохе 1, и по отпечатку, без дублей.
- Удалённый тип: тест, зависевший от него в снимке «до правки», выбран.
- Изменившийся ресурс сборки: выбраны тесты, зависящие от любого типа этой сборки.
- Каждая строка раздела «Когда проект остаётся целиком» — отдельный случай с проверкой причины.
- Класс инвентаря без узла графа входит в ступень 1; проект с фикстурой с аргументами идёт целиком.
- Проект вне ответа эпохи 1 в результате не появляется, даже если его тест доходит до изменившегося типа.
- Вложенность: на всех случаях ступень N содержит ступень N−1.
- Настоящий MSBuild и настоящий снимок task-03: загрузка, первое чтение снимка «до правки» завершено, правка
  тела метода, сборка — ступени непусты и совпадают с ожидаемыми. Затем вторая правка другого типа без сборки —
  проект целиком с причиной «не пересобрано». Затем сборка — ступени отражают обе правки.
