## Регрессии

- Реальный MSBuild и наблюдение за каталогом. Тест
  [`External_save_then_build_narrows_on_the_first_estimate_without_rewriting_the_source`](../../../../RoslynMcpServer.Tests/Testing/EstimateAffectedTestsDepthTests.cs#L52)
  пишет `.cs` с BOM вне MCP, собирает solution и сразу вызывает оценку. Исходная версия выдала целый
  проект с `not newer than the last edit`. Исправленная выдаёт ступени `0/1/2/3`, сохраняя байты
  и время внешней записи. Вторая правка того же файла без новой сборки снова возвращает целый проект
  по правилу свежести. Подхват текста обновляет текущий снимок Roslyn в памяти и оповещает наблюдателей
  workspace. Для этого используются защищённые API текущего Roslyn. `MSBuildWorkspace` нельзя наследовать
  снаружи. Путь записи и согласования применяется при операциях сохранения.
- [`String_attribute_arguments_preserve_unpaired_surrogates`](../../../../RoslynMcpServer.Tests/Testing/Il/IlFingerprintReviewRegressionTests.cs#L76)
  компилирует атрибут с аргументом `string` и отдельно с `object[]`, содержащим строку. Исходная версия
  отвергала обе корректные сборки. Исправление сохраняет кодовую единицу суррогата, даёт стабильный
  отпечаток после повторной компиляции и различает `\uD800` и `\uFFFD`. Соседняя проверка подтверждает
  отказ для повреждённой последовательности. Строгий UTF-8 сохраняется для имён и остального текста.

Первый прогон четырёх регрессий дал три ожидаемых отказа и один проход для повреждённой строки.
Целевой прогон после исправлений — **542/542**, без пропусков, включая все **123** теста SourceStructure.
В первом полном прогоне тест наблюдения после переименования каталога ещё ожидал отметку собственной
записи сервера. Проверка теперь подтверждает, что подхват внешней правки такой отметки не создаёт и
сохраняет BOM, timestamps и файлы проекта.

## Полный Jellyfin

Полный solution из отдельной копии локального checkout `2953ed632c` собран в Release с той же
версией SDK. Повторяется порядок task-06: шесть внешних сохранений, затем три сохранения через
`update_file_content`. Для каждой пробы исходники и выходы возвращаются к собранному baseline,
запускается отдельный MCP-процесс. Изменение вносится после завершения захвата исходников и первого
чтения DLL. Измеряется клиентское время `estimate_affected_tests`, без сборки и исполнения тестов.
Числа ступеней берутся из ответа продукта, включая соседство M-06 для `all`. Знаменатель — инвентарь
`VstestTestInventory` по тем же проектам. Часть замера выполнялась одновременно с Windows CI.

### Как повторить

После сборки сервера и копии полного solution используйте [клиент task-06](measure-task06.py) с теми же
двумя локальными списками `owner-cases.json` и `owner-mcp-cases.json` из девяти проб. Каждый элемент задаёт `file` относительно solution,
`signature` метода, `depth` со значением `direct` и путь `compare` к одному проекту для пары VSTest.
Названия проектов, типов и тестов из ответов и списков остаются в локальных результатах.
Для памяти используйте [методику двух снимков](task-06-snapshot-measurement.md) и DLL новой сборки.

```powershell
$harness = 'docs/rapid-tia-2/mvp/evidence/measure-task06.py'
$serverDll = 'bin/Release/net10.0/RoslynMcpServer.dll'
python $harness $serverDll $solution $externalCases "$results/external" --external-save |
    Tee-Object "$results/external.jsonl"
python $harness $serverDll $solution $mcpCases "$results/mcp" |
    Tee-Object "$results/mcp.jsonl"
```
