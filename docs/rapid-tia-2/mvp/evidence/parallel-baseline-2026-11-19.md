## Параллельное сравнение

На правках № 1 и № 3 проведено по две пары. Перед каждым вариантом запускали MCP на чистом workspace
и дожидались исходного снимка 41 DLL. После внешнего сохранения в обеих ветках выполняли одну
инкрементальную сборку. L0-C брал зафиксированный список проектов уровня 0 до старта таймера и запускал
каждый целиком. TIA-C после сборки получал живой план через `estimate_affected_tests` (`depth: all`,
`run: false`). Полный цикл измерялся от сохранения до получения результатов VSTest.

```powershell
dotnet build $solution -c Release --no-restore -m:1
dotnet test $project -c Release --no-build --no-restore `
  --results-directory $projectResults --logger 'trx;LogFileName=tests.trx'
```

При наличии фильтра в плане TIA к запуску проекта добавлялся `--filter $filter`. У каждого процесса
отдельный каталог результатов. Предел одновременно работающих процессов — восемь. Порядок L0-C и TIA-C
меняли между повторами. Чтобы длинные проекты запускались первыми одинаково в обеих ветках, задачи
отправляли по убыванию медианы длительности проекта из прежних замеров уровня 0. На L0-C в очереди
14 или 16 процессов, на TIA-C одновременно 4 или 6.

Справочный TIA-direct-C запущен один раз на каждой правке. Причина — `Server.Implementations.Tests`
появлялся только с `di` в восьми пробах из девяти. На правке № 2 это верно и для интеграционного проекта.

### Самый долгий процесс и загрузка ЦП

Интеграционный проект стартовал первым в обеих ветках. Остальные проекты укладывались в его окно.
Загрузка — доля занятого времени всех логических процессоров Windows за время этого процесса,
по отсчётам `GetSystemTimes` раз в 0,5 с.

| Повтор | Правка | `Jellyfin.Server.Integration.Tests`, с | Загрузка ЦП |
| --- | --- | ---: | ---: |
| 1 | 1 | 44,26 → 42,99 | 31,36% → 19,29% |
| 1 | 3 | 46,45 → 40,32 | 32,04% → 15,81% |
| 2 | 1 | 46,18 → 39,78 | 29,59% → 18,06% |
| 2 | 3 | 46,27 → 43,21 | 35,63% → 17,12% |

С более широким планом L0-C загрузка была выше во всех парах, а интеграционный процесс занимал
на 1,27–6,40 с больше. Эти данные показывают сопутствующую разницу, а точный вклад конкуренции за ЦП
в длительность интеграционных тестов потребовал бы отдельного эксперимента.
