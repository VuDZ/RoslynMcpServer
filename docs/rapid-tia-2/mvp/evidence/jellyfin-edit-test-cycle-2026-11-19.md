# От сохранения до результата тестов на полном Jellyfin

2026-11-19, Europe/Moscow. Windows x64, .NET SDK 10.0.402, Release. Полный checkout Jellyfin
`2953ed632c`, сервер 1.8.1 с обоими исправлениями. SHA-256 `RoslynMcpServer.dll` совпадает
с предыдущим замером (`0B5284A913A85D77AED1ACBAD5542E6D5A96AFC5ADFE37C5948FCB12F1DCF55F`).
Взяты те же девять правок тел методов. [Предыдущий замер](follow-ups-jellyfin-2026-11-19.md).

## Методика

- **Уровень 0.** Сохранить правку, один раз инкрементально собрать полный solution, запустить все тесты
  каждого проекта уровня 0. Список проектов берётся из предыдущих ответов на те же правки, включая
  строки `No tests`. Получение этого списка вне измерения даёт уровню 0 преимущество.
- **Rapid TIA.** Сохранить ту же правку, собрать тем же способом, вызвать `estimate_affected_tests`
  с `run: false`, `depth: all`. Воспроизвести ответ: запустить отфильтрованные или целые проекты,
  пропустить пустые ступени. Проекты живого плана должны совпасть со списком уровня 0.

Обе ветки запускают VSTest последовательно в одинаковом порядке, через проект с `--no-build --no-restore`.
Оценка измерена через MCP. Сборку и VSTest скрипт запускает напрямую.
Таймер начинается перед операцией сохранения и останавливается после последнего тестового процесса и
чтения его счётчиков TRX. Подготовка чистой сборки, старт MCP, загрузка полного workspace и захват
baseline идут до таймера. Между ветками исходный файл восстанавливается и решение снова собирается.
В нечётных пробах первым идёт уровень 0, в чётных — Rapid TIA. Первые шесть правок сохраняются вне MCP,
последние три через `update_file_content`, одинаково в обеих ветках. Параллельная стратегия запуска
проектов и встроенный `run: true`, который собирает проекты по очереди, этим замером не оценивались.

**Восемь из девяти** циклов с Rapid TIA завершились быстрее. Медианный парный выигрыш — **5,22 с**
(**5,52%**). Девятая проба заняла на **2,14 с** больше. Восьмая дала практически одинаковые времена с
разницей **0,20 с**. Медианы длительности циклов — **98,15 с** для уровня 0 и **93,64 с**
для Rapid TIA. Медиана вызова оценки — **29,60 с**.

Всего выполнено **26 742** теста уровня 0 в 128 процессах VSTest и **5775** выбранных Rapid TIA тестов
в 37 процессах. Все исполнившиеся тесты прошли. Адаптер пропустил **189** и **27** тестов соответственно.
За девять проб время тестовых этапов уменьшилось на
**329,4 с**, из них **268,1 с** заняли вызовы оценки. Сумма полных циклов сократилась с **904,4 до 842,0 с**.
Выигрыш был самым большим там, где фильтры и пустые ступени заметно уменьшали суммарное время прогонов.
В девятой пробе тестовый этап сэкономил около 27 с при оценке около 29 с.

Данные отражают одну пару на правку в выбранном порядке. Правки меняли IL тела без изменения поведения,
поэтому тесты измеряют стоимость получения результата. Ширина выбора остаётся эвристикой, а обязательный
CI выполняется перед приёмкой. Числовые логи и 165 TRX хранятся в `artifacts/rapid-tia-jellyfin-cycle/run`.
Исходный `cycles.jsonl` содержит времена и счётчики выполнения. Счётчик пропусков в нём занижен, поскольку
адаптер оставлял `Counters.notExecuted` нулевым при наличии результатов `NotExecuted`. Пропуски сверены
по всем TRX и записаны в `cycles-verified.jsonl`. Скрипт считает их по `total − executed`.
SHA-256 `cycles-verified.jsonl` — `76C1EBA65FECE649DD21591349582A577C1CE0374D73EFDEF795FD6A22029482`.
По окончании исходные байты всех девяти правок сверены с базовой копией, повторная сборка прошла.

## Инструкция для агента

Для известного класса или метода используйте `run_specific_test`. Rapid TIA оправдан после серии правок,
когда охват тестами широк или неясен. Одна сборка перед оценкой позволяет запустить фильтры и целые
проекты из ответа с `noBuild: true`. Этот сценарий зафиксирован в
[`AGENTS.md.sample`](../../../../AGENTS.md.sample) и [справочнике README](../../../../README.md).

Короткое правило в шаблоне покрывает выбор сценария. Подробности по ступеням и причинам расширения
загружаются по запросу через `get_tool_help`. Комплектный скилл имеет смысл, если станет нужен отдельный
многошаговый сценарий установки или диагностики в нескольких клиентах.

## Воспроизведение

[Скрипт прогона](measure-jellyfin-cycle.py.txt) использует [MCP-клиент task-06](measure-task06.py).
Нужны собранная отдельная копия полного Jellyfin, DLL сервера, два локальных списка правок
`owner-cases.json`, `owner-mcp-cases.json` и каталог предыдущих результатов с `external` и `mcp`.
В каждом из них используются `NN/estimate_affected_tests.txt`. Прежние пути к проектам должны указывать
на ту же копию solution. Используйте новый каталог результатов. Имена исходников, проектов и тестов
журналируются только локально.

```powershell
$env:DOTNET_PROCESSOR_COUNT = '4'
$env:NuGetAudit = 'false'
$env:MSBUILDDISABLENODEREUSE = '1'
python docs/rapid-tia-2/mvp/evidence/measure-jellyfin-cycle.py.txt `
    $serverDll $solution $externalCases $mcpCases $previousResults $newResults
```
