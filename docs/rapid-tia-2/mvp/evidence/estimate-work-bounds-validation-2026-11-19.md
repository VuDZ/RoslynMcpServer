# Проверка диагностики документов и индекса сессии входов

**2026-11-19.** Диагностика изменённых документов сократила медиану первого ответа на этом репозитории
с **4,37 до 3,74 с**. Поиск наблюдений и разрывов теперь использует индексы сессии. Эти изменения устраняют
разные источники затрат. Причина задержки после сборки Jellyfin подтверждена отдельно.
[Профиль блокировки Windows](windows-watcher-lock-2026-11-19.md).

## Состав ошибок

Оценка использует семантическую диагностику изменённых деревьев из полной компиляции загруженного проекта.
Она сохраняет разрешение символов через соседние и сгенерированные исходники, отбор по тяжести и пути, формат
строк и удаление дублей. Ошибки теперь выводятся в порядке обхода деревьев. В регрессиях сравнивался состав строк
с полной диагностикой для синтаксической ошибки, ошибки в теле, повторного объявления типа, удалённого члена
из другого изменённого файла, двух загруженных контекстов TFM и соседнего документа генератора.

Принято ограничение диагностики рамками документа. Регрессия `CS0017` фиксирует границу: конфликт точки
входа с другим файлом показывает сборка. Проверка проекта целиком остаётся частью команды сборки.
[Реализация проверки точки входа в Roslyn](https://source.dot.net/Microsoft.CodeAnalysis.CSharp/Compiler/MethodCompiler.cs.html).

## Индекс сессии и регрессии

Наблюдения индексируются по пути, роли и проекту. Повтор обновляет исходную позицию, а снимок отдельного
пути перебирает только его наблюдения. Индекс разрывов использует причину, источник и прежнюю эквивалентность
областей. Удаление разрыва обновляет индекс и список под одной блокировкой. Тесты проверяют порядок,
замену значения, повторное добавление и различие между разрывами карты и рантайма.

До исправления семантические проверки `SourceSetAnalysis` зафиксировали четыре нарушения: полную диагностику
проекта, два линейных поиска при добавлении и обход всех наблюдений для снимка одного пути. Структурная проверка
даёт воспроизводимый red без порога wall-clock.
