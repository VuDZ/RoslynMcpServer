# Встроенный параллельный запуск на полном Jellyfin

Автоматический режим сократил цикл от сохранения до ответа на **18,10 с** на правке № 1
и на **13,85 с** на правке № 3. Планы запуска, имена тестов и все исходы внутри каждой пары совпали.

2026-11-19, Windows 11 x64 25H2 (сборка 26200), AMD Ryzen 7 9800X3D
(8 физических ядер, 16 логических процессоров), .NET SDK 10.0.402. Полный Jellyfin
`2953ed632c`, Release, изолированная копия solution. RoslynMcpServer с изменениями
[задачи](../../follow-up-parallel-test-run.md) поверх `da57ff1` и временным номером **1.9.0**.
SHA-256 DLL, использованной для замера
`b5096b2ba240ec3f0cf82d6cf00b19538f47bd729dbf7f4fe814455363f7de7b`.

## Методика

Повторили тело правки № 1 (`Emby.Naming/Video/StubResolver.cs`, `TryResolveFile`) и № 3
(`src/Jellyfin.Extensions/PathHelper.cs`, `GetSafeLeafFileName`) из
[замера полного цикла](jellyfin-edit-test-cycle-2026-11-19.md). В каждый метод добавляли
`System.GC.KeepAlive(null);` внешним сохранением через `Path.write_bytes`.

Перед каждым прогоном собирали исходное solution командой
`dotnet build Jellyfin.slnx -c Release --no-restore -m:1`, запускали новый процесс MCP
и загружали workspace с `configuration: "Release"`. Дожидались завершения исходного снимка
кода и чтения **41 DLL**. Обе ветки использовали `DOTNET_PROCESSOR_COUNT=16`,
`NuGetAudit=false` и `MSBUILDDISABLENODEREUSE=1`.

Таймер запускается перед записью правки и останавливается после получения ответа MCP. Сразу после
сохранения измерительный клиент отправляет один вызов `estimate_affected_tests` с `depth: "all"`,
`run: true` и `maxParallelProjects: 1` или `0`. Цикл включает обнаружение правки, оценку, сборки,
сужение, VSTest и формирование ответа. Восстановление исходного файла и сборка восстановленного
solution идут за пределами таймера.

На правке № 1 сначала запускали последовательный режим, на № 3 — автоматический. История
длительностей между прогонами пустая. Новый сервер в каждом прогоне берёт порядок пути проекта.
У каждого процесса записывается отдельный TRX. Для сверки используется мультимножество строк TRX
по тройке «тестовая сборка, полное имя теста, исход», включая пропуски.

## Результаты

| Правка | Последовательно, с | Авто, с | Выигрыш | Тестовых проектов | Прошло | Упало | Пропущено |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 110,30 | 92,20 | 18,10 с (16,4%) | 4 | 1013 | 0 | 3 |
| 3 | 109,23 | 95,38 | 13,85 с (12,7%) | 6 | 625 | 0 | 3 |

В обоих режимах у каждой правки ещё 10 проектов остались без тестового процесса. Автоматический
предел на машине равен восьми, но запускать одновременно было четыре или шесть проектов.
Самый долгий TRX во всех прогонах принадлежал `Jellyfin.Server.Integration.Tests`. Его окно
заняло 41,36 → 45,62 с на правке № 1 и 41,39 → 44,80 с на № 3
(последовательный → автоматический). Общий цикл сократился при перекрытии тестовых процессов.
Это одна пара на каждую правку, на одной машине.

Ответы MCP, 20 TRX, логи сборок и `cycles.jsonl` сохранены локально в
`artifacts/rapid-tia-profile/parallel-run/`. После прогонов оба исходника совпали с чистой копией
по SHA-256, контрольные сборки прошли.

## Проверки реализации

- Red до реализации. Пять ожидаемых падений и два прохода. Уже работали последовательное
  чередование и продолжение после ошибки или таймаута. Red воспроизвёл ранний старт тестов, отсутствие
  двух одновременно работающих процессов при отмене, отсутствие приоритета из истории и расхождения
  контракта инструмента в двух профилях MCP.
- Целевой Release-прогон. **60/60**, включая тесты с управляемым порядком и двумя реальными VSTest
  в разных каталогах, а также отмену через MCP в последовательном и параллельном режиме.
- Первый Windows main выявил устаревшие размеры `tools/list` в `Surface_sizes_match_recorded_release_numbers`.
  Схема выросла на 255 байт в каждом профиле, до 47 557 байт в full и 21 120 в lite, при прежнем числе
  инструментов. Контрольные значения сверены целевым тестом. После правки теста повторная Release-сборка
  решения прошла, SHA-256 DLL совпал с замером Jellyfin.
- Windows main на бинарнике замера. **2649/2649**, включая все **128** SourceStructure, без пропусков.
  Фильтр `Category!=AnalyzerLifecycle&Category!=RequiresPinnedSdk`.
- Дополнительный Windows AnalyzerLifecycle. **13/13** без пропусков при `ROSLYN_MCP_ANALYZER_LIFECYCLE=1`.

Логи Release-сборки и TRX тестов сервера сохранены локально в `artifacts/rapid-tia-profile/parallel-run-tests/`.

## Проверка замечаний после ревью

До исправления все пять регрессионных проверок воспроизвели замечания. При успешном запуске и отмене
оставались каталоги результатов. В строке режима «параллельно» появлялось с нулём или одним проектом,
а при явном пределе `1` пустой план показывал один слот.

После исправления целевой Release-прогон прошёл **28/28**. В реальном VSTest сверены исходы и
изоляция TRX. После запуска каталоги отсутствуют. При отмене проверена очистка частичных результатов.
Ответ для пустого выбора проверен с `maxParallelProjects: 0` и `1`, ответ для одного проекта — с `0`.

Release-сборка решения прошла. Windows main **2650/2650** без пропусков, включая
все **128** SourceStructure. После прогона новых временных каталогов Rapid TIA не осталось.
TRX проверок хранятся локально в `artifacts/rapid-tia-profile/parallel-run-cleanup-tests/`.
