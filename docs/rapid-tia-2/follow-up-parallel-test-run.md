# Параллельный запуск тестовых проектов в `run: true`

Статус **accepted 2026-11-19**. При `maxParallelProjects: 1` сохранено чередование
сборки и тестов. В параллельном режиме все сборки и сужение завершаются до запуска тестов.
[Проверки и парный замер на правках № 1 и № 3 полного Jellyfin](mvp/evidence/parallel-run-2026-11-19.md).
**2026-11-19** проверены исправления после ревью. Временные каталоги очищаются после тестовых процессов,
а строка режима учитывает число готовых к запуску проектов. [Результаты проверок](mvp/evidence/parallel-run-2026-11-19.md#проверка-замечаний-после-ревью).

## Почему

На полном Jellyfin параллельный запуск выбранных проектов сократил полный цикл на 19,30 с по медиане
четырёх пар при одинаковых исходах тестов ([замер](mvp/evidence/test-run-strategy-2026-11-19.md)).
Выигрыш не зависит от сужения: уровень 0 при параллельном запуске тоже укладывается в окно самого долгого
процесса ([сравнение](mvp/evidence/parallel-baseline-2026-11-19.md)). Время цикла задаёт самый долгий
тестовый проект, а при последовательном запуске к нему добавляются все остальные.

До этого изменения `run: true` обходил планы по одному в порядке пути проекта. Для каждого проекта он
собирал проект, сужал выбор по свежим сборкам и запускал тесты с `noBuild`. Сборка и тесты разных проектов
шли строго друг за другом.

## Область изменения

**Фазы.** Сборки остаются последовательными, в прежнем порядке: у тестовых проектов общие зависимости, и
параллельные сборки пишут одни и те же `bin` и `obj`. При `maxParallelProjects: 1` по каждому проекту
по очереди выполняются его сборка, сужение и тесты. При значениях `0` или больше `1` тестовые процессы
стартуют после завершения всех сборок и сужения по их выходам, даже если эффективная степень равна одному.
Так сборка следующего проекта не перепишет DLL общей зависимости под работающим тестом.

**Степень.** Новый параметр `maxParallelProjects`, по умолчанию `0` — автоматически:
`min(число запускаемых проектов, max(1, Environment.ProcessorCount / 2))`. `1` — последовательный запуск
как сейчас. Замер шёл с не больше чем восемью процессами на 16 логических процессорах. Проекты без тестов
(`No tests`, ступень без классов) процесс не занимают.

**Порядок старта.** Первыми стартуют проекты с самым долгим прошлым тестовым процессом в этой сессии
сервера. Без истории — порядок пути проекта, как сейчас. Число выбранных тестов порядком не служит: на
Jellyfin 124 интеграционных теста идут 44 с, 433 других — 11 с.

**Изоляция.** Каждый тестовый процесс использует отдельный временный каталог для TRX и вложений.
Каталог удаляется после обработки результата, включая отмену и таймаут.

**Ошибки, таймаут, отмена.** Таймаут остаётся на процесс. Падение или таймаут одного проекта не
останавливает остальные. Отмена MCP-запроса останавливает деревья всех работающих процессов. Работавшие
проекты получают `Cancelled`, не начатые — `NotRun`, как сейчас.

**Ответ.** Проекты выводятся в прежнем порядке, независимо от того, какой закончил первым. Формат строк по
проекту не меняется. Одна строка сообщает эффективную степень параллелизма тестов или отсутствие проектов
для запуска. Описание инструмента и `get_tool_help`
говорят о параллельном запуске, о параметре и о том, когда ставить `1`: тесты разных проектов делят порт,
файл или базу.

Изменение входит в сборку ветки Rapid TIA **1.6.0**. Номер релиза определяется при переносе в `main`.

## Проверка

- Red до кода, на фальшивом исполнителе процессов:
  - одновременно работает не больше заданного числа тестовых процессов, и ни один не стартует до конца
    последней сборки;
  - `maxParallelProjects: 1` повторяет нынешний порядок сборок и запусков;
  - порядок проектов в ответе не зависит от порядка завершения;
  - падение и таймаут одного проекта не трогают остальные; отмена даёт `Cancelled` работающим и
    `NotRun` не начатым;
  - при истории сессии самый долгий проект стартует первым.
- Интеграционный тест на синтетическом solution с двумя тестовыми проектами: оба запущены, каталоги
  результатов разные, исходы совпадают с последовательным запуском.
- Существующие тесты `run: true` проходят без изменения ожиданий, кроме строки режима.
- Замер на полном Jellyfin, правки № 1 и № 3, по паре: `run: true` с `maxParallelProjects: 1` и `0`. Те же
  тесты и исходы, время цикла. Отчёт — `mvp/evidence/parallel-run-<дата>.md`.
- Финальные проверки по [AGENTS.md](../../AGENTS.md): Release build, SourceStructure, полный main suite.

## Вне задачи

- Сборка нескольких проектов одной командой и параллельные сборки.
- Сужение выбора и ступени `depth`.
- README, [`AGENTS.md.sample`](../../AGENTS.md.sample) и уточнение формулировок о выигрыше против уровня 0.
  Это отдельный шаг перед переносом в `main`.
