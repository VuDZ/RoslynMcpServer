# Этап 5. Хвост find_symbol_definition

Статус: сделан (v1.4.8). После этапа 1, чтобы страницы уже содержали колонку и полное имя.

## Цель

Длинный список определений можно дочитать. Сейчас после 200 мест текст обрывается советом сузить имя, остаток пропадает.

У ссылок и реализаций остаток уже лежит в `NavigationOverflowStore` и забирается аргументом `overflowCursor`. Форк кладёт полный markdown во временный файл. Для этого сервера курсор подходит лучше: удалённый клиент не читает `%TEMP%` машины сервера.

## Поведение

У `find_symbol_definition` появляются те же `maxResults` и `overflowCursor`, что у `find_symbol_references`.

Предел считает `NavigationListingHelper.ResolveMaxResults`: явный аргумент, иначе переменная `ROSLYN_MCP_MAX_RESULTS`, иначе 50, коридор 1–500.

Первая страница станет короче нынешних 200 строк. Продолжение — повторный вызов с курсором, без нового поиска. Курсор — идентификатор в памяти, не путь.

Режим с файлом и строкой обычно даёт мало мест (частичный тип). Курсор и там тот же, чтобы у инструмента была одна схема.

Поиск по решению, группировка и `FindSourceDefinitionAsync` не меняются. Режется уже собранный список мест.

## Файлы

- `Tools/NavigationTools.cs`
- Тест рядом с `NavigationOverflowStoreTests`: объявлений больше предела, второй вызов с курсором возвращает хвост и не начинает новый поиск. Временный файл не создавать и не проверять.

## Контракт

Два новых необязательных аргумента. Старый вызов без них получает первую страницу и при необходимости курсор. Клиент, который ожидал до 200 мест одним ответом, увидит 50 и строку с курсором. Это осознанное выравнивание с остальной навигацией.

Описание и `McpToolHelpCatalog` сказать: хвост не выбрасывается, его забирает `overflowCursor`.
