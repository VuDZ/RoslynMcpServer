# Response: review-ds/README.md

## review-ds/R-01

### Reviewer claim

`minHostVersion` сверяет `Version` продукта. Связывает плагин другое: версии сборок, которые загрузчик подменяет по имени (`RoslynMcpServer`, `ModelContextProtocol`, `Microsoft.CodeAnalysis.*`). Внутри мажора продукта 1 эти сборки уже менялись. Плагин проходит гейт и падает `TypeLoadException` после обещания в `get_mcp_server_info`.

### Related findings

Нет дубликата. Не про disk-sync (`review-astra/R-01`).

### Problem assessment

`PARTIALLY ACCEPT`

### Problem rationale

Принимается: гейт «тот же мажор продукта и хост не старее `minHostVersion`» не смотрит на сборки, которые эпоха 5 подставляет из хоста. `Version` в csproj и версия пакета `ModelContextProtocol` — разные числа; правило репозитория бампит только продукт. `docs/ARCHITECTURE.md` §11: активация групп чувствительна к версии MCP SDK, потому что коллекция тулов читает приватное поле SDK. Обзор версий: патч `1.0.35` сменил Roslyn на 5.9.0. Сценарий «продукт 1.5.0, MCP 1.4.x, плагин собран на 1.3.0, мажор продукта тот же» гейт эпохи 2 пропускает. Это дыра.

Не принимается тезис, что `Version` продукта годится только как подсказка человеку. Она по-прежнему нужна как минимум хоста: плагин, собранный против сервера новее запущенного, не должен грузиться. Это другая ось, и она в спеке уже есть.

### Correction assessment

`MODIFY`

### Correction rationale

Не заменять продукт версиями пакетов целиком. Оставить `minHostVersion` как нижнюю границу продукта (тот же мажор, хост не старее). Добавить вторую сверку с фактически загруженными сборками контракта.

Политика, которую можно вывести из сценария ревьюера и из §11:

- `ModelContextProtocol`: пропуск, если `Major.Minor` загруженной сборки хоста не равен той, против которой собран плагин. Сценарий 1.3 против 1.4 закрывается. Точный патч SDK не обязателен этим finding.
- `RoslynMcpServer`: плагин всегда исполняется на сборке хоста. Пропуск, если мажор ссылки плагина другой или ссылка новее хоста. Совпадение патча не требуется: иначе каждый патч сервера без смены Roslyn/MCP отвергает плагин, а такого требования не было.
- `Microsoft.CodeAnalysis`: разный мажор — пропуск. Совпадение minor (5.0 против 5.9) имеющимся требованием не доказано. Это `U-001`, не молчаливое exact-равенство.

Откуда брать версии ссылок плагина: его `deps.json` рядом с entry, до `Load` entry. Отдельные поля в `plugin.json` не обязательны, если deps.json уже содержит эти ссылки. Если deps.json молчит о контракте хоста (из-за `ExcludeAssets=runtime`), спека должна назвать запасной явный список в `plugin.json`. Это уточнение реализации внутри той же правки, не третий гейт.

### Evidence

README, абзац «Совместимость». Эпоха 2, правила `minHostVersion`. Эпоха 5, подмена сборок по имени. `RoslynMcpServer.csproj`: `Version` 1.4.15 и `ModelContextProtocol` 1.3.0. `.cursor/rules/roslyn-mcp-version-bump.mdc`: бампится продукт. `.cursor/rules/roslyn-mcp-overview.mdc`: Roslyn 5.9.0 в патче 1.0.35. `docs/ARCHITECTURE.md` §11.

Контекст, которого не было в тексте спеки как отдельного требования: обсуждение зафиксировало сверку мажора продукта до загрузки. Это contemporaneous decision, и оно не покрывает ось SDK. Защита не считает ту сверку опровержением finding.

### Classification

`ARCHITECTURE DEFECT`

### Severity

High у ревьюера. Совпадает для оси MCP. Для «любой патч Roslyn равен несовместимости» evidence слабее, поэтому exact-match всего списка не принимается.

### Required outcome

Плагин, собранный против другого `Major.Minor` пакета MCP, чем загружен в хосте, не проходит discovery. Продуктовый `minHostVersion` остаётся нижней границей сервера.

### Proposed specification change

README, абзац совместимости; эпоха 2, правила пропуска до `Load`; `authoring.md`, строка таблицы `minHostVersion`. Не писать, что продукт один гарантирует типы Roslyn и MCP.

### Downstream consequences

Discovery читает deps.json до загрузки entry. Шаблон зелёный только на том MCP, что у хоста. Патч продукта без смены MCP плагин не отвергает.
