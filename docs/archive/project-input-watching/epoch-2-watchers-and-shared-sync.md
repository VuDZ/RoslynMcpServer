# Эпоха 2. Watchers и синхронизация linked/shared файлов

Статус: **готово**. Требует принятого результата эпохи 1:
[план](_archive/epoch-1-input-map.md), [отчёт](_archive/epoch-1-results.md).

## Цель и изменения

- Создать покрытие известных внешних путей и областей потенциального
  membership. Рекурсия разрешена для project directories и membership regions
  внутри них. Для внешнего linked-файла, walk-up props и imports — нерекурсивный
  watcher на каталог самого файла с фильтром точечных путей либо точечное
  наблюдение. Рекурсивный watcher на каталог предка запрещён, даже если предок
  не является корнем диска. Объединение подписок не расширяет их recursion/scope.
  Ограничения watcher, внешний glob без полного evidence и неполный startup
  отражать в coverage unknown; не компенсировать их широким ancestor watcher.
- Использовать отдельные списки/API для search roots и watcher descriptors.
  `search_code` сохраняет прежний набор корней, включая explicit path/fallback.
  Linked-файлы и ancestor props не добавляют каталогов к поиску.
- Фильтровать события по карте входов и ролям. WPF-временные проекты
  обрабатываются по контракту соседней серии. Событие unrelated файла не
  инвалидирует Solution при доказанной нерелевантности.
- Ожидаемый эффект — ограничить наблюдение чужих деревьев и адресно покрыть
  внешние linked inputs. Новый `.cs` внутри SDK project directory по-прежнему
  консервативно значим. Отсутствие пути в обратном индексе не доказывает
  Compile Remove/нечленство: новые glob-items подтверждаются оценкой MSBuild.
- Для пользовательского `.cs` читать один подтверждённый текст на физический
  путь и применять
  его ко всем соответствующим `DocumentId` в candidate Solution.
  Проверить весь write/publication путь: он не должен сводить результат
  обратно к одному документу или перезаписывать linked-файл разными текстами.
- New/Delete/Rename в значимой области помечают composition stale для
  последующей оценки MSBuild. Оба пути Rename учитываются; callback не
  выполняет загрузку проекта или запись `.csproj`. Rename каталога внутри
  membership region переводит coverage в unknown, а не только refresh известных
  текстов. Directory.Exists не является единственным evidence старого пути:
  удалённая/перемещённая область тоже могла содержать неизвестные glob-items.
- Не-C# входы получают роль и уведомление. Их автоматическая текстовая
  синхронизация исключена из всей этой серии: `AdditionalDocument` и
  `AnalyzerConfigDocument` остаются в `non-csharp-input-tracking`.
  Graph/generated-role не маскируется операцией `WithDocumentText` обычного
  C# документа.
- Generated intermediates/outputs текущего build классифицируются отдельно;
  включение в Compile и путь в `obj` не превращают их в пользовательский input.
  Их события не порождают input revisions производящего build. Явные inputs
  и другие подтверждённые роли пути сохраняются; недоказанная роль даёт unknown.
- Сохранить lock/publication, cancellation и analyzer admission contracts.
  Error/Rename callbacks не должны обрушать процесс при ошибке логирования.

## Проверки и приёмка

- Реальный FSW доставляет изменение linked-файла вне всех project directories.
  Следующий semantic call видит его во всех проектах, использующих путь.
- Shared-файл с различающимися compilation options обновляет текст во всех
  memberships; специфичные для проекта результаты не смешиваются.
- Добавление glob-файла, исключённого файла, удаление и file/directory rename
  дают соответствующее состояние; новый документ не добавляется через writer.
  Новый `.cs` внутри project directory вне обратного индекса вызывает
  консервативный composition stale. Ignore исключённого файла допустим только
  по актуальному evidence; watcher сам не заявляет новое членство.
- Реальный нерекурсивный watcher замечает внешний linked-файл и walk-up props;
  подписка на предка не получает события чужих вложенных деревьев. Проверить
  появление ранее отсутствующего props и unknown при непокрытом внешнем glob.
- Directory Rename внутри membership region переводит coverage в unknown;
  повторное чтение известных `.cs` не восстанавливает его полноту.
- Явный вход в обычно игнорируемом каталоге обрабатывается адресно; фоновые
  генерируемые `.g.cs`, AssemblyInfo и outputs не увеличивают input revisions
  текущего build и не вызывают бесконечную инвалидацию. Проверить также mixed role
  и неизвестную provenance, для которой blanket generated-ignore запрещён.
- Backing `.csproj`, Solution и BOM/encoding сохранены. Существующий
  набор `search_code` roots совпадает с прежним: не расширен и не сужен.
  Fixture с linked-каталогом, содержащим дополнительный loose `.cs`, проверяет,
  что файл доступен watcher по роли, а соседний loose-файл не вошёл в поиск.

## Результат

Отчёт включает реальные FSW-сценарии и regression проверки write boundary.
Тест прямого callback отдельно не доказывает покрытие корней watcher.
