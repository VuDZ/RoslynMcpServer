# Task 01. Загрузка и сборка через solution

- Рекомендуемые модели — GPT-6.2 Sol или Astra.
- Рекомендуемый reasoning — medium.
- Примерная сложность — 3/5.
- Риск ошибки — средний, семантические инструменты могут загружать workspace неявно.
- Необходимые способности — C#, Roslyn/MSBuild, тестирование MCP.
- Статус на 2026-11-25 — принято в 1.6.4, задача архивирована.
- Зависимости — нет.
- Модель, реализовавшая задачу — GPT-6 (сабагент).
- Модель, проводившая ревью — GPT-6 (координатор).
- Раунды исправлений — 2 (ревью пути, ожидания интеграционных тестов).
- Принятый объём — Загрузка и сборка через решение, подсказка для прямого `.csproj` и настройка её текста. [Отчёт о проверках](validation.md).

Прямое открытие проекта не передаёт контекст решения, включая свойство
`SolutionDir`. Из-за этого могут отличаться MSBuild-вычисления и расположение
промежуточных файлов. Владелец разрешил реализацию 2026-11-25.

## Критерии приёмки

- `require-solution` по умолчанию имеет значение `false`. При `true` прямое
  открытие `.csproj` отвергается до design-time build, а прямая сборка через
  `run_dotnet_build` — до запуска процесса.
- Проверка охватывает явную загрузку, загрузку через `workspace-path` и
  автоматические пути загрузки. Решения `.sln` / `.slnx`, их проекты и
  сборка проекта через `projectName` решения сохраняют обычное поведение.
- В разрешённом режиме прямый вызов получает рекомендацию использовать решение
  в конце ответа, в том числе если в основном результате есть ошибки.
- `direct-project-guidance` заменяет стандартную рекомендацию в разрешённом и
  запрещённом режимах. Штатные диагностика и коды результатов сохраняются.
- В версиях сборки отражено изменение. Перед приёмкой проходят Release build,
  SourceStructure, основной CI-набор и AnalyzerLifecycle.
