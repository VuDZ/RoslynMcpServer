# ARB-005 — Generation binding первоначального capture

Sources:
- [review-astra/F-001](../../review-astra/findings/F-001.md)

Independent corroboration: no. Class: CONSENSUS.

## Underlying issue

Stable post-load hashes могут соответствовать новым inputs, а options — старому evaluation.

## Relevant requirements / constraints

[E1 spec](../../epoch-1-disk-cache-mvp/spec.md), «Store и поведение»:
пригодный reusable base и обнаружение значимых изменений.
[E1/task-00](../../epoch-1-disk-cache-mvp/task-00-input-manifest-hi.md) требует capture evidence.

## Evidence

[Manager](../../../../../Services/Workspace/SolutionManager.cs), 2049 и 2098: open до watcher.
[Capture service](../../../../../Services/Analyzers/AnalyzerProvenanceCaptureService.cs),
ReplayOne: properties/analyzer items не являются consumed-byte manifest.
[E2/task-04](../../epoch-2-content-refresh/task-04-refreshed-envelope-capture-med.md)
уже требует consumed-byte binding для другого, более позднего capture.

## Reviewer positions

### review-astra/F-001

Major; зафиксировать evaluation→capture binding и props-after-consumption negative control.

## Author position

[ACCEPT](../../defense/findings/review-astra-F-001.md); третий post-load probe не исправляет проблему.

## Analysis

Если MSBuild прочитал props A, затем файл стал B до первого probe, два hashes B
не проверяют происхождение options A. Новый watcher session также начинается поздно.
Это допустимый interleaving по коду; runtime-воспроизведение не заявляется.
Problem assessment: **CONFIRMED**. Correction assessment: **ACCEPTABLE**.

## Decision

**ACCEPT**.

## Rationale

Original и arbitration severity: **major** — устойчивый ложный hit после restart.
Принят минимальный outcome binding, без навязывания универсального filesystem snapshot.

## Remaining uncertainty

Механизм binding для выбранного профиля должен быть доказан при implementation.
Равенство pre/post hashes само по себе также не доказывает отсутствие ABA.
