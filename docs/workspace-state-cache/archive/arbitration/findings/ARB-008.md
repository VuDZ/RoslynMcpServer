# ARB-008 — Явная cache policy для lazy entry

Sources:
- [review-ds/F-005](../../review-ds/findings/F-005.md)

Independent corroboration: no.

## Underlying issue

Benchmark explicit tool и proposed opt-in не описывают observable disabled outcome
при config-driven первом semantic call.

## Relevant requirements / constraints

[README](../../README.md): useDiskCache=false, без чтения/записи cache при false;
изменение default требует отдельного решения. [Task-06](../../epoch-1-disk-cache-mvp/task-06-load-save-and-restore-hi.md)
ограничен opt-in manager/tool wiring.

## Evidence

[EnsureWorkspaceFromConfigAsync](../../../../../Services/Workspace/SolutionManager.cs),
427–458, передаёт FileSettings.Configuration/Platform/TargetFramework и ConfigFile source.
[FileSettings](../../../../../Config/RoslynMcpFileSettings.cs), KnownKeys и 82–84:
load properties существуют, cache opt-in key не определён.

## Reviewer positions

### review-ds/F-005

Minor; выбрать config key либо explicit-only scope. Утверждения о полном отсутствии
globals у lazy entry и о неопределённом значении флага слишком сильны.

## Author position

[ACCEPT WITH MODIFICATION](../../defense/findings/review-ds-F-005.md): рекомендует
explicit-only E1, считает extension config scope owner choice.

## Analysis

Default false уже определяет безопасное поведение при отсутствии opt-in. Сам факт
общего manager не включает feature. Новый config key не является обязательным условием
текущего MVP, поэтому отдельный UNRESOLVED сейчас не нужен. Следует явно документировать
этот существующий default для ConfigFile и не приписывать ему explicit benchmark speedup.
Будущее расширение opt-in возможно отдельным изменением; постоянного запрета нет.

Problem assessment: **PARTIALLY CONFIRMED**. Correction assessment: **MODIFY**.

## Decision

**ACCEPT WITH MODIFICATION**.

## Rationale

Original и arbitration severity: **minor** — scope/reporting gap, а не неизбежная
ошибка конфигурации или обязательность zero-touch caching.
