# ARB-004 — Overlay fallback разрешён текущим контрактом

Sources:
- [review-ds/F-002](../../review-ds/findings/F-002.md)

Independent corroboration: no.

## Underlying issue

Текущий fresh provenance получается через MSBuild open. Disk-only adapter не доказан;
поддержка overlay и измерения должны отражать actual fallback, не обещанный hit.

## Relevant requirements / constraints

[E1 spec](../../epoch-1-disk-cache-mvp/spec.md), «Интеграция» прямо разрешает whole-request
ordinary fallback без fresh admission. [Task-05](../../epoch-1-disk-cache-mvp/task-05-fresh-session-preparation-hi.md)
прямо допускает adapter **либо** support/fallback classifier, требует sticky overlay matrix
и real positive E1 control. Обязательность именно overlay-on positive там не задана.

## Evidence

[OpenAndCaptureAsync](../../../../../Services/Analyzers/AnalyzerProvenanceCaptureService.cs),
181–284: источник snapshot выполняет Open*.
[Gate](../../../../../Services/Analyzers/AnalyzerProvenanceCaptureGate.cs), 19–38:
missing/foreign/incomplete snapshot непригоден.
[Manager](../../../../../Services/Workspace/SolutionManager.cs), 901–923: overlay-off return,
blocking-load ban и unsuitable-capture Unavailable различаются.
[Benchmark](../../benchmark.md): mode входит в compare key, отдельного overlay case нет.

## Reviewer positions

### review-ds/F-002

Major; объявить overlay disk hit неподдержанным в E1 и добавить fallback control.
Утверждает отсутствие fallback в task checks и недостижимость hit by construction.

## Author position

[UNRESOLVED](../../defense/findings/review-ds-F-002.md): нужен owner choice о включении
overlay hit в MVP; до adapter рекомендует ordinary fallback.

## Analysis

Отсутствие fallback во всех tasks опровергается task-05. Текущий код показывает
отсутствие готового adapter, но не невозможность предусмотренного будущего adapter.
Главное: выбор fallback уже разрешён нормативным текстом. Для соблюдения текущего scope
не требуется заново спрашивать владельца, обязателен ли дополнительный hit mode.
Author UNRESOLVED здесь избыточен: безопасный минимальный outcome уже определён.

Нужно сделать mode-support matrix и new-PID control явными: при отсутствии доказанного
fresh binding выполнить ordinary load **до** публикации hydrated candidate. Это не
постоянный архитектурный запрет overlay hit. Реальный ordinary Banned/Unavailable
сохраняется; нельзя гарантировать успех запрещённого ordinary request.

Problem assessment: **PARTIALLY CONFIRMED**. Correction assessment: **MODIFY**.

## Decision

**ACCEPT WITH MODIFICATION**.

## Rationale

Existing alternative закрывает обязательный outcome без нового product choice.
Original severity: **major**; arbitration: **major** для incorrect publication,
ограничение ускорения само по себе defect не является.

## Remaining uncertainty

Будущий disk-only fresh-admission adapter не проверен и не требуется для fallback route.
Его отдельное принятие расширит supported mode matrix; этот арбитраж его не разрешает.
