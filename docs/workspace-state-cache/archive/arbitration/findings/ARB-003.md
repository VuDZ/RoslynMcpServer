## Underlying issue

«Effective properties / semantic modes» не определяет вычислимое равенство контекста
нового request и envelope. Requested-only и старые evaluated defaults дают разные ошибки.

## Relevant requirements / constraints

[README](../../README.md), «Поведение первого MVP»: разные graphs не склеиваются;
RAM omitted semantics сохраняются; base DTO не содержит shadow paths/session;
BuildArgs отделены от graph identity. [E1/task-06](../../epoch-1-disk-cache-mvp/task-06-load-save-and-restore-hi.md)
требует не смешивать request/effective values.

## Analysis

Raw omitted configuration при FileSettings=Debug и FileSettings=Release одинаков,
но ordinary loader inputs различны. Поэтому requested-only equality недостаточна.
Взять default из найденного envelope тоже нельзя: это круговое обоснование hit.
Сравнивать необходимо независимо разрешённые текущие globals с явным отсутствием;
проектные defaults покрывают проверенные inputs/environment, а не догадка lookup.

Grok-сценарий cached shadow paths уже запрещён DTO contract. Ошибка fresh admission
возможна, но отдельный overlay storage key сам по себе её не устраняет. Можно разнести
ключи по mode либо разделять clean base при обязательном fresh prepare каждого request.
Сохранение sticky RAM поведения не разрешает cold disk wildcard.

Problem assessment: **PARTIALLY CONFIRMED** для совокупности claims.
Correction assessment: **MODIFY** для обоих исходных prescriptions.

## Decision

**ACCEPT WITH MODIFICATION**.

## Rationale

Нужен один контракт lookup/admission, а не два несовместимых рецепта key.
Original severities: DS **major**, Grok **minor**; arbitration: **major** для риска
false hit, **minor** для одного лишь отсутствия перечня diagnostic flags.
