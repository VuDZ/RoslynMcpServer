# F-003 — Новый ancestor analyzer config не входит в правило invalidation

Severity: major

Category: correctness

Confidence: high

## Target

- `docs/workspace-state-cache/README.md`, «Индекс входов»
- `docs/workspace-state-cache/epoch-2-content-refresh/spec.md`, «Приёмка»
- `docs/workspace-state-cache/epoch-2-content-refresh/task-05-content-and-graph-mutations-med.md`
- `Services/Workspace/WorkspaceInputMapBuilder.cs`, walk-up и membership regions

## Claim

Уже загруженный analyzer config хешируется как документ, но появление нового ancestor `.editorconfig` или `.globalconfig` не описано как обнаруживаемое событие. Disk hit тогда сохраняет старые diagnostics/options, которые ordinary load увидел бы.

## Evidence

- README перечисляет walk-up кандидаты: `Directory.Build.props`, `Directory.Build.targets`, `Directory.Packages.props`, `global.json`, применимый NuGet.Config. Analyzer-config documents входят в индекс независимо от расширения, то есть уже известные файлы. «Каталоги возможного появления source/config inputs» и «новый ancestor config» не называют `.editorconfig` / `.globalconfig` и не говорят, хешируется ли ancestor directory целиком.
- E2 spec в приёмке называет новый `Directory.Build.props`. E2/task-05 шире: `new ancestor file` обязан дать ordinary fallback. Эти две формулировки не задают один набор.
- Текущая карта: membership region — только каталог проекта. Walk-up — четыре имени файла, точечно по ancestor directories. Для analyzer configs записано: «Hierarchical discovery of a new .editorconfig beyond the evaluated documents is unknown.»
- Обход spec ограничен каталогами проектов, ancestor candidates и explicit dependencies. Ancestor candidate в текущем коде — конкретное имя, не все файлы каталога.

## Why it matters

Обычный load в новом PID подхватывает новый корневой `.editorconfig`. Cache hit, который не видит этот файл, расходится с fresh ordinary load по severity и части compiler/analyzer options. Это регрессия относительно текущего restart, а не заранее принятый blind spot вроде `mvp-fast`.

## Failure scenario

Проект лежит в `src/App`, решение — в корне репозитория. После capture в корне появляется `.editorconfig` с `root = true` и `dotnet_diagnostic` severity, либо `.globalconfig`. Каталог проекта не изменился. Walk-up probe смотрит только `Directory.Build.*`, `Directory.Packages.props` и `global.json`. Следующий PID с `useDiskCache=true` не видит новый файл, считает graph неизменным и отдаёт snapshot без этого config. Тот же workspace без cache получает config из ordinary MSBuild/Roslyn load. E2/task-05 требует fallback на new ancestor file, но не говорит, что этот файл входит в probe.

## Violated requirement / constraint

E2/task-05: new ancestor file → ordinary fallback, результат сравнивается со fresh ordinary load. README: новый ancestor config должен обнаруживаться. Явного требования именно на `.editorconfig` в README нет; расхождение README и task-05 — само по себе неопределённый contract.

`Неявный / отсутствует — требуется уточнение` для конкретного списка ancestor config имён. Требование task-05 «new ancestor file» уже есть и не операционализировано.

## Recommended change

В индексе входов перечислить ancestor analyzer config, который обязан инвалидировать request: как минимум `.editorconfig` и `.globalconfig` на пути от каталога проекта к корню, включая known absence. Согласовать с этим список в E2 spec и в task-05. Каталоги, которые не сканируются, явно оставить unsupported, а не hit.

## Alternatives

Нет второго разумного варианта с другой архитектурой. Либо эти файлы входят в probe, либо новый файл такого типа честно даёт fallback/unknown, но не hit.

## Notes for arbitration

Проверить, кладёт ли ordinary load выбранного контроля родительский `.editorconfig` в `AnalyzerConfigDocuments`. Если да, смена уже известного файла закрыта content hash, и finding касается только появления файла после capture. Это не отменяет сценарий нового файла. Spike не нужен.
