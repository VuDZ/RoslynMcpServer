# F-002 — Не определена валидация evaluation environment между PID

Severity: major

Category: requirements

Confidence: high

## Target

- [README — Индекс входов и Поведение первого MVP](../../README.md).
- [E1 spec — Стартовая проверка](../../epoch-1-disk-cache-mvp/spec.md).
- [E1/task-00](../../epoch-1-disk-cache-mvp/task-00-input-manifest-hi.md) и [E1/task-09](../../epoch-1-disk-cache-mvp/task-09-restart-and-failure-integration-med.md).

## Claim

Дисковые inputs, версии SDK и configuration/platform/TFM не определяют все evaluation inputs нового процесса. В контракте отсутствует правило для ambient environment: что сравнивается на lookup, что закрепляется при ordinary load, а какие зависимости требуют unsupported/fallback. Сохранить прежние effective values недостаточно: необходимо получить независимые текущие значения до разрешения reuse.

## Evidence

- README перечисляет файлы/каталоги и effective load properties; E1 отдельно добавляет SDK/MSBuild/Roslyn/schema/resolution identity. Ни один из этих разделов не определяет environment identity либо отказ от env-dependent evaluation.
- [MsBuildWorkspaceProperties.cs](../../../../../Services/Workspace/MsBuildWorkspaceProperties.cs), `Create`, задаёт только Configuration, Platform и TargetFramework. [SolutionManager.cs](../../../../../Services/Workspace/SolutionManager.cs), строки 2028–2055, передаёт эти properties в ordinary workspace/capture.
- MSBuild использует environment variables как исходные properties при инициализации property collection. Project properties могут их переопределить; environment values способны участвовать в conditions без custom task. Это документированное поведение: [MSBuild properties — Environment properties](https://learn.microsoft.com/en-us/visualstudio/msbuild/msbuild-properties?view=visualstudio#environment-properties), проверено 2026-10-07.
- E1/task-09 перечисляет configuration/platform/TFM и file/version changes, но не содержит restart с изменением environment при идентичных project bytes.

## Why it matters

Основной сценарий оптимизации — новый PID. Он может быть запущен из другой shell/IDE с другим окружением. Disk hit с прежними evaluated options тогда отличается от ordinary load того же request. Запрет неизвестных custom targets не покрывает обычную property expansion.

## Failure scenario

В неизменном проекте `DefineConstants` дополняется значением `$(WorkspaceFlavor)`. Процесс A получает `WorkspaceFlavor=FLAVOR_A` и сохраняет options. Процесс B запущен с `WorkspaceFlavor=FLAVOR_B`; файлы, Configuration/Platform/TFM и SDK не изменились. Lookup, основанный только на перечисленных inputs, возвращает старые parse options, хотя fresh ordinary evaluation выбирает другой conditional compilation branch.

Это сценарий по документированной семантике MSBuild; production cache ещё не реализован, динамическое воспроизведение его false hit не заявляется.

## Violated requirement / constraint

README: разные графы не объединяются одним hash key; E1 unsupported inputs должны приводить к fallback.

Неявный / отсутствует — требуется уточнение: предполагается ли неизменность окружения между процессами и как это предположение проверяется.

## Recommended change

Добавить явную environment policy поддержанного профиля: независимо перепроверяемые значения релевантных variables, контролируемое окружение ordinary evaluation либо консервативный отказ при неподтверждённой зависимости. Включить absent→present и changed-value restart controls. Не записывать необработанные секреты окружения в reports/envelope.

## Alternatives

Широкий fingerprint окружения проще, но даёт лишние misses; выборочная зависимость точнее, однако требует evidence полноты. Controlled environment меняет ordinary semantics и потому требует отдельного совместимого product решения. Это варианты, а не требование реализовать их все.

## Notes for arbitration

Нужно определить, включает ли термин effective load properties environment, и откуда значения берутся в новом PID без повторной evaluation. Если конкретный профиль исключает такие проекты, требуются явный support predicate и negative test. Общий closure research отложенного v2 не требуется.
