## Основание и принятая граница

Владелец уточнил в текущем чате: чат мало связан с MCP; по его наблюдению,
Cursor пытается переиспользовать MCP, Codex запускает новые, а `dsh` держит один.
Эти наблюдения фиксируются как сведения владельца, не как проверенный контракт
трёх клиентов и не как установленный production-дефект этого репозитория.

Единицы серверного контракта — MCP-подключение/сессия, привязка к workspace,
совместимый ключ и процесс host. Чат не является ключом совместимости или
достоверным сигналом отключения. Изучать либо исправлять клиентскую политику
создания процессов эта тема не должна. Цель удерживать workspace при
переподключении сохраняется; конкретный механизм и предел гарантий входят в task-04/task-01.

Для уточнённого scope собраны: шесть GC runs / 30 точек памяти, два inventory
сборок и GC, группа 20 MCP с параметрами 16 загрузок, Windows/WSL process controls
и три сценария Codex app-server. Методы, n, версии, исходные JSON и ограничения
сохранены в результате. Текущий режим измерен; idle unload и shared-модели имеют
условные оценки экономии. Недоказанные выгоды варианта B не зачтены.

Job/breakaway относится к конкретному проверенному запуску. Оно передаёт риск
механизма в task-04, не отвергает все способы запуска отдельного host.
Завершение агента, закрытие чата, EOF и смерть процесса не отождествляются.
Исторические данные о сабагентах и ручном перезапуске оставлены без изменения.

Обновлены task-05, его результат, три индекса, входные формулировки task-01,
сценарий lifecycle task-04 и README probe. Граф Depends on и обязательный выбор
проверяемых моделей владельцем перед task-04 сохранены. Исключённая UI-матрица
