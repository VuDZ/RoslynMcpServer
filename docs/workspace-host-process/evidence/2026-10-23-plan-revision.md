- Статус документационного обновления: **выполнено, 2026-10-23**.
- Основание: обсуждение с владельцем после [независимого ревью](2026-10-23-independent-review.md)
  версии `dc1b1c5` и явный запрос поправить документацию темы без изменения кода.
- Принятый scope: task-05, сравнение моделей процессов, U-C-07/U-C-08, базовая
  гипотеза владения ключом, граница маршрутизации, требование «proxy не загружает
  лишнего», зависимости task-01/task-04, индексы.

  Независимое ревью этих дополнений не проводилось.

## Уточнения владельца

- Около 20 MCP-процессов суммарно на 10–20 ГБ — реальная ситуация на другом
  компьютере владельца, а не гипотетический пример. Не разобрано, какая часть
  памяти приходится на дубликаты совместимого workspace.
- Пустой MCP без workspace занимает около 18 МБ. Вес процесса без workspace не
  считается препятствием для proxy, но proxy должен не загружать ничего лишнего.

## Изменения

- [README темы](../README.md): новое наблюдение вместо «примера»; противоречие
  цели «пережить Reload» с моделью ролей при единственном клиенте; раздел
  [сравниваемые модели](../README.md#сравниваемые-модели-и-проверки-применимости-2026-10-23)
  (роли в MCP — основной кандидат, отдельный host — только по явному выбору
  владельца, нулевой вариант: выгрузка по простою и вариант B); U-C-07/U-C-08;
  маршрут, точка входа и учёт.
- Новый [task-05](../epoch-0-design-and-spike/task-05-applicability-checks-med.md):
  судьба MCP, дочерних и отделённых процессов при закрытии чата, Reload и выходе
  реальных harness; разбор памяти наблюдаемой ситуации; подтверждение веса пустого процесса.
- [Карта E0](../epoch-0-design-and-spike/README.md): task-05, порядок, зависимости,
  сквозные критерии выбора модели и лёгкого proxy, отметка о том, что ревью
  охватывало `dc1b1c5`.
- task-00: старт процесса в `Program.cs` до выбора роли; таблица инструментов
  по месту исполнения.
- task-01: раздел 0 «Выбор модели», лёгкий proxy, граница маршрутизации, проверка
  выбора модели и цели Reload; зависимость от task-05.
- task-02: проверка загруженных сборок proxy, сравнение с оценкой task-05,
  задержка при конкуренции клиентов.
- task-03: роль `host` без локального клиента моделирует и отдельный host.
- task-04: зависимость от task-05 и решения владельца; базовая гипотеза
  блокировки ОС; прогон сценариев для отдельного host, если он оставлен;
  поведение harness берётся из task-05.
- [Общий docs index](../../README.md): строка темы.

Требования согласованного scope от 2026-10-23 не изменены: модель ролей остаётся
основным кандидатом, отдельный host описан как альтернатива для явного решения.
