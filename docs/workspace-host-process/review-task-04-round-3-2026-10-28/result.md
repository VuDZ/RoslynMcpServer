## Вердикт

`routing-checks all` повторена на нативном Ubuntu 26.04.1 (не WSL): 32 записи, exit 0,

## Главное

1. **Switch задерживает ответы уже выполняющихся вызовов A до конца загрузки B (F-01).**
   В пробе вызов `slow` длительностью 1 с, начатый на A до switch, ответил через 6,2 с,
   только после открытия барьера загрузки B. С Roslyn это минуты; отмена ожидание не снимает.
   Проверка в серии переключается только на уже загруженный B, поэтому эффекта не видит.
2. **Окно подключения 250 мс включает handshake и MCP initialize (F-02).** Отчёт пишет
   «initialization до 3 с». На деле proxy массово бросают подключения и переподключаются:
   в первом поколении холодного старта 10–20 подключений на 10 proxy в raw Codex и 31–56
   на нативном Linux. С нагруженным Roslyn host это риск ложного «host unavailable» по
   истечении 8 с.
3. **Cooldown 2 с пишется при каждом запуске, а не только после отказа (F-03).** Убийство
   host в первые 2 с после старта даёт клиентам немедленную ошибку вместо recovery.
   Все проверки recovery ждут 2,1 с и этим маскируют поведение. Текст ошибки «Outcome
   may be unknown» выдаётся и для запроса, который не отправлялся.
4. **На Linux `FileStream.Lock` — POSIX `fcntl` lock (F-04).** Такой lock принадлежит
   процессу: закрытие любого другого дескриптора того же файла в этом процессе снимает
   его молча. Spike это не задевает, потому что каждый процесс открывает файл один раз.
   Для production-кода и отложенной модели ролей (host и proxy в одном процессе) это
   ловушка; в отчёте не отмечена.
5. **Неудачная общая загрузка «залипает» на поколение (F-05).** Повторить её можно,
   только когда отключатся все клиенты. Это решение для task-01 и владельца, а в «Главном»
   отчёта его нет.

Модели: всё перечисленное относится к выделенному host. F-01–F-03 и F-05 касаются
любой shared-модели, F-04 особенно важен для модели ролей. Нулевой вариант не затронут.

## Независимая проверка полноты

- `/proc/locks` во время серии — тип lock (F-04).
- Подсчёт `connected` по поколениям в raw Codex и в своём прогоне (F-02).
- Проба вне серии: переключение на B с барьером загрузки и вызов сразу после kill (F-01, F-03).
- Поиск задержек `Task.Delay(2100)` в проверках recovery (F-03).
