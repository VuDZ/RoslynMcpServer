- Дата: 2026-10-29.
- Объект: [task-01](../epoch-0-design-and-spike/task-01-architecture-decision-hi.md), [design](../design.md), [отчёт](../epoch-0-design-and-spike/evidence/task-01-architecture-decision.md), правки task-02 и индексов в `b2a7b80..e9de5ee`.
- База: `e9de5ee`, сервер 1.5.18. Рабочее дерево чистое; production-код с `b2a7b80` не менялся.
- Рецензент: `claude-opus-5-5` (Claude Code). Отдельный проход по поручению владельца «провалидируй». Прежние ревью Codex (раунды 1–2, 4) и Grok (раунд 3) прочитаны после основного прохода. ID `F-01`…`F-05` здесь новые и не продолжают их нумерацию.
- Итог: **требуются исправления до выбора O-01…O-04**. Технические контракты раундов 1–4 не опровергнуты; три major касаются того, даст ли выбранная модель выигрыш на реальной установке владельца.

## Главное

- **Под Claude Code ключи не совпадут никогда (F-01).** На этой машине два MCP из двух сессий Claude Code получили одинаковый набор из 40 переменных среды, но значения 11 из них разные: `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_TOKEN`, `TMUX`, `SSH_CONNECTION`, `XDG_SESSION_ID`, `PWD` и другие. Design хеширует полный environment и отклоняет только три имени `CODEX_*`. Значит, каждый чат Claude Code получит свой host и свой proxy, а это хуже обычного режима. Добавить новые имена в preflight не поможет: по правилам design такой контекст станет ineligible. Пути к схлопыванию в таком harness design не даёт.
- **Образ host на Linux лежит в RAM (F-02).** Unix root — `/tmp/roslyn-mcp-<euid>/v1`, и туда же уходят immutable image и логи host. В Ubuntu 26.04 `/tmp` — это tmpfs: здесь 1,9 ГБ памяти. Образ сервера занимает 93 МБ (build output) или около 300 МБ (publish одного RID), и каждая пересборка при dogfood добавляет новый экземпляр. Функция, которая должна экономить память, тратит её на копии сборки и может заполнить `/tmp` для всех программ.
- **Общий reset снимет host у всех, а агентам reset советуют регулярно (F-03).** `AGENTS.md.sample` и README просят вызывать `reset_workspace` после rename, после создания или удаления `.cs` и после build со сгенерированными исходниками. По O-02 каждый такой вызов любого из N агентов завершает общий host: чужие вызовы получают outcome-unknown, все платят холодную загрузку. Это ровно то замедление, которого владелец опасается. У design уже есть дешёвый механизм — согласованная перезагрузка того же ключа с новой epoch; retire нужен только для restart-required analyzer.
- Минорное: стоимость хеширования полного манифеста образа не размещена в бюджетах (F-04). Предложение: учесть уже существующий у владельца launcher-снимок (F-05).
- Подтверждено: 54/54 публичных инструментов в таблице §5 (ещё 9 имён каталога скрыты до v2 и не публичны), S01–S42 — 42/42. Выборочные ссылки на код верны. Нового production-дефекта нет.

## Что не опровергнуто

Контракты раундов 1–4 — switch вне gate, single-flight и retry по failure id, epoch invalidation после package/rename, stage RPC и OS output gates, abandoned-writer, раздельные бюджеты и cooldown только после отказа, один lock-дескриптор на процесс — прочитаны и внутренних противоречий не дали. Это приёмка текста, а не runtime pass; V-01…V-06 остаются у task-02/E1.
