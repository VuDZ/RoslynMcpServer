# Эпоха 2. Манифест и пути

Статус: не начата.

## Цель

Хост знает, какие плагины грузить, не открывая их DLL и не ища
`IRoslynMcpPlugin` перебором файлов. Результат — список планов и список
пропусков с причинами. Сборку не загружает, файлы не копирует.

## Манифест

`plugin.json` рядом с entry. Поля все обязательны: `id`, `entry`, `pluginType`,
`toolPrefix`, `minHostVersion`. Кодировка UTF-8. Комментарии JSONC в этом файле
не поддерживаются: это не `RoslynMcp.jsonc`. Полей версий ссылок в манифесте нет.

Пропуск плана, причина в результате, до любого `Assembly.Load` плагина:

- нет файла, битый JSON, поле отсутствует или пустое после `Trim`;
- `entry` не имя файла (есть каталог или `..`);
- `toolPrefix` пустой;
- `minHostVersion` не разбирается как `System.Version`;
- мажор `minHostVersion` не равен мажору `Assembly.GetExecutingAssembly()`;
- версия хоста меньше `minHostVersion` при том же мажоре.

`minHostVersion` остаётся нижней границей продукта. Одна `Version` продукта не
гарантирует типы MCP и Roslyn.

До `Load` entry читается версия ссылки, в том числе когда runtime-ассеты
контракта исключены. Носитель — compile-запись в `deps.json` рядом с entry.
Конкретный разбор файла не нормирован. Нет записи, из которой версию прочитать,
— пропуск с причиной.

Дополнительный пропуск до `Load` entry:

- `Major.Minor` ссылки на `ModelContextProtocol` не равен загруженной сборке
  хоста (патч MCP может отличаться);
- мажор ссылки на `RoslynMcpServer` не совпал или ссылка новее хоста;
- мажор `Microsoft.CodeAnalysis` не совпал;
- при том же мажоре `Version` ссылки `Microsoft.CodeAnalysis` новее загруженной
  сборки хоста. 5.10 и 5.9.2 на хосте 5.9.0 — пропуск. 5.8 на 5.9.0 — план есть.
  Exact-равенство minor не требуется. Другой мажор — пропуск в обе стороны.

Гейт `Microsoft.Extensions.*` эта эпоха не добавляет.

## Откуда пути

Обхода cwd и профиля нет. Относительный явный путь резолвится
`Path.GetFullPath` (текущий каталог процесса), вверх по диску хост не ищет.

Порядок, первое вхождение `id` побеждает, повтор пропускается:

1. Непосредственные подкаталоги `{baseDirectory}/plugins/`. Нет каталога —
   ноль планов, не ошибка. Вложенные каталоги (`runtimes/`, зависимости) не
   плагины. Имя подкаталога совпадает с `id` ординально, иначе пропуск.
2. Массив `plugins` из `RoslynMcp.jsonc`. Ключ становится известным. Два файла
   настроек сливаются как остальные ключи: cwd заменяет массив exe целиком.
   Пустой массив — ноль явных путей.
3. `ROSLYN_MCP_PLUGINS`, если переменная задана и не пустая. Разделитель —
   `Path.PathSeparator`. Пустые сегменты пропускаются.

Ошибка типа известного ключа, включая `plugins` (значение не массив, элемент не
строка), становится `ParseFailures`. Разбор не бросает исключение наружу. Хост
при таком файле стартует. Успешно прочитанный второй файл сливается прежним
правилом: cwd заменяет массив exe целиком. Встроенные тулы и исправные плагины
из другого источника (drop-in, переменная, успешно прочитанный файл) при этом
живы. Текст сообщения в `ParseFailures` эпоха не нормирует. Это не изоляция
битого плагина: её делает эпоха 5.

Элемент шагов 2 и 3:

- каталог — читать `plugin.json` внутри. Имя каталога с `id` не сравнивать:
  dev-выход называется `net10.0`;
- файл — это entry. `plugin.json` в том же каталоге. Имя файла совпадает с
  полем `entry`, иначе пропуск. Соседние DLL не открывать.

План помнит: id, каталог, полный путь entry, `pluginType`, `toolPrefix`,
признак теневой копии. Drop-in — без копии. Явные пути — с копией. Саму копию
делает эпоха 3.

## Файлы

- `Plugins/PluginManifest.cs`
- `Plugins/PluginLoadPlan.cs`
- `Plugins/PluginDiscovery.cs` — метод, которому передают базовый каталог,
  список из настроек, строку переменной окружения и версию хоста. `baseDirectory`
  аргумент, не зашитый `AppContext.BaseDirectory`: тесты подставляют временный каталог.
- `Config/RoslynMcpFileSettings.cs` — ключ `plugins`, свойство со списком строк.
  Ошибка типа известного ключа пишет `ParseFailures` и не бросает.
- `RoslynMcpServer.Tests/PluginDiscoveryTests.cs`
- `RoslynMcpServer.Tests/RoslynMcpFileSettingsTests.cs` — только сценарии ключа
  `plugins`.

`Program.cs` не подключать. Версию не менять. Контракт темы не переписывать.
В таблице эпох — только строка эпохи 2.

## Тесты

На временных каталогах:

- drop-in `plugins/sample/plugin.json` даёт один план без теневой копии, entry
  собран из каталога и поля `entry`;
- подкаталог `plugins/sample/runtimes/win` планом не становится;
- имя подкаталога не равно `id` — пропуск, DLL не нужна;
- нет `plugin.json` — пропуск, файлы `*.dll` в каталоге не читаются;
- чужой мажор и хост старее `minHostVersion` — пропуск;
- тот же мажор и хост не старее — план есть;
- `deps.json` с другим `Major.Minor` у `ModelContextProtocol` — пропуск, `Load`
  entry не вызывается;
- мажор ссылки `RoslynMcpServer` другой или ссылка новее хоста — пропуск;
- другой мажор `Microsoft.CodeAnalysis` — пропуск; 5.9.2 при хосте 5.9.0 —
  пропуск; 5.8 при хосте 5.9.0 — план есть;
- два источника с одним `id` — один план, второй пропуск;
- путь к DLL берёт entry только если имя совпало с полем `entry`;
- `ROSLYN_MCP_PLUGINS` из двух путей даёт два плана с теневой копией;
- ключ `plugins` больше не попадает в `UnknownKeys`; cwd заменяет массив exe;
- `plugins` не массив или элемент не строка — запись в `ParseFailures`,
  исключение из разбора не летит; успешно прочитанный второй файл по-прежнему
  сливается правилом cwd поверх exe.

## Вне эпохи

Копирование файлов, `AssemblyLoadContext`, регистрация из эпохи 1 на живой
сборке, старт `Program.cs`.
