# Эпоха 3. Теневая копия

Статус: не начата.

## Цель

План с признаком теневой копии грузится не из `bin` плагина. Хост копирует
каталог плана во временный каталог этого запуска и подменяет в плане путь
entry на копию. Drop-in остаётся на исходном пути. Сборку по-прежнему не
загружает.

Исходный каталог после копирования можно перезаписать. Копия этому не мешает.
Тест байтов этой эпохи доказывает копирование, не живой `AssemblyLoadContext`.
Замок файла на загруженной копии — эпоха 5.

## Куда и что копировать

Каталог копии — `Path.GetTempPath()` / `RoslynMcpServer` / `plugins` / новый
guid на каждый план. Не внутрь `bin` плагина и не в `{BaseDirectory}/plugins`.

Копируется дерево каталога плана целиком, включая `runtimes/` и PDB. Это не
поиск плагинов: вложенные папки не читаются как отдельные `plugin.json`.
Копирование файла в `runtimes/` не резолвит native и не обещает P/Invoke.
`LoadUnmanagedDll` эта серия не добавляет.

Файл не копируется, если это `.dll` или `.pdb` и простое имя сборки (имя файла
без расширения):

- `RoslynMcpServer`;
- `ModelContextProtocol` или начинается с `ModelContextProtocol.`;
- начинается с `Microsoft.CodeAnalysis`;
- начинается с `Microsoft.Extensions.`.

Остальные зависимости плагина копируются. `plugin.json` и `deps.json` копируются.
Список исключений эта эпоха не расширяет: частная managed-зависимость в копию входит.

Ошибка копирования одного плана — пропуск этого плана с причиной. Остальные
планы копируются. Старые временные каталоги эпоха не удаляет.

После копирования путь entry в плане указывает на файл с тем же именем внутри
копии. Исходный путь в плане не остаётся единственным: результат хранит и
исходный каталог, и каталог копии, чтобы `get_mcp_server_info` позже мог
показать путь, с которого сборка реально загружена.

## Тесты

Временный каталог с `plugin.json`, произвольным entry-файлом (достаточно байтов,
это не сборка), вложенным `runtimes/win/native.bin` и подложенными
`RoslynMcpServer.dll`, `Microsoft.CodeAnalysis.CSharp.dll`,
`ModelContextProtocol.Core.dll`, `Microsoft.Extensions.Logging.dll`.

`native.bin` проверяет, что файл скопирован. Вызова native и резолва P/Invoke
в этом тесте нет.

- План с теневой копией указывает entry внутрь нового каталога. В копии есть
  `plugin.json`, entry и `runtimes/win/native.bin`.
- Перечисленные сборки хоста и их `.pdb` в копии отсутствуют. Чужой
  `Their.Heuristic.dll` в копии есть.
- После копирования запись в исходный entry удаётся. Байты копии не меняются.
  Это не доказательство, что загруженный ALC держит путь копии.
- Два плана получают разные каталоги.
- План без признака копии возвращается с тем же путём entry, временный каталог
  для него не создаётся.
- Исключение ввода-вывода на одном плане не отменяет копию второго. В тесте
  для этого достаточно пути entry, которого нет на диске, при живом соседнем плане.
