# F-002 — Не определён канонический workspace key перед HMAC

Severity: major

Category: correctness

Confidence: high

## Target

`docs/usage-statistics/README.md:25–26,87–90,97–100`: идентичность workspace и её хеширование.

## Claim

Перечислены компоненты ключа, но не определено, какие значения и в каком каноническом представлении хешируются. В частности, аргументы вызова отличаются от фактически удерживаемой конфигурации. После HMAC агрегатор уже не сможет исправить ложное разделение одного workspace.

## Evidence

- README:25–26 определяет ключ как абсолютный путь плюс Configuration, Platform и TargetFramework. README:97 требует хранить его только как HMAC.
- `Services/Workspace/SolutionManager.cs:869,877–910` нормализует путь и свойства и наследует пропущенные значения из текущей загрузки/конфига.
- `Services/Workspace/SolutionManager.cs:2029–2059` допускает cached load с пропущенными свойствами; `LoadedConfiguration/LoadedPlatform/LoadedTargetFramework` при этом сохраняются.
- `Services/Workspace/MsBuildWorkspaceProperties.cs:61–97` сравнивает переданные свойства без учёта регистра, а `Services/Build/DotNetConfigurationArguments.cs:43–50` сводит `Any CPU` к `AnyCPU`.
- `Services/Workspace/SolutionManager.cs:3187–3190` сравнивает пути без учёта регистра на Windows и с учётом регистра на остальных ОС.
- `RoslynMcpServer.Tests/Workspace/SolutionManagerPassedLoadArgsTests.cs:51–101` подтверждает наследование свойств; `MsBuildWorkspacePropertiesTests.cs` — canonical Platform и семантику omitted arguments.

## Why it matters

M3 и M5 требуют совпадения ключей между процессами; M2 группирует по ключу время загрузки. Семантически равные значения, записанные разными байтами, дадут разные HMAC и скроют дубликаты.

## Failure scenario

Процесс A загружает `App.sln` с `Release / Any CPU`, затем вызывает load без свойств. Процесс B держит тот же файл с `Release / AnyCPU`. Если хешировать входные аргументы каждого события, у A меняется ключ после cache hit, а B попадает в третью группу. Даже хеширование текущих свойств не устраняет различия регистра Windows-пути без оговорённой нормализации.

## Violated requirement / constraint

Определение workspace в README:25–26; Q-02 и основанные на равенстве ключей M2, M3, M5.

## Recommended change

Определить каноническую сериализацию кортежа перед HMAC, включая null/default, регистр и OS-семантику путей. Для resident state брать фактически загруженные свойства после нормализации и наследования; явно отличать ключ запрошенной загрузки от текущего удерживаемого ключа при ошибке. Стабилизировать этот контракт между версиями, пишущими в общий каталог, и добавить примеры ожидаемого равенства/неравенства.

## Notes for arbitration

Не предлагается расширять выбранный владельцем descriptor переменными среды, buildArgs или другими настройками. Finding касается одинакового кодирования уже согласованных четырёх компонентов. Эквивалентность omitted default и явно заданного Debug — отдельный выбор; её следует явно задать, а не молча предполагать.
