# F-007 — Не определено поведение MCP при отказе необязательной статистики

Severity: major

Category: lifecycle

Confidence: medium

## Target

`docs/usage-statistics/README.md:55–67,87–91,97–100,160–172`: запуск сборщика, I/O и граница влияния на сервер.

## Claim

Спецификация добавляет запись, создание секрета и периодическую задачу в lifecycle каждого MCP, но не определяет, допустимы ли отказ запуска, задержка tool response или остановка сервера при ошибке статистики. Это существенный отсутствующий контракт для функции, предлагаемой к включению по умолчанию.

## Evidence

- O-01 предлагает включить сбор по умолчанию; решение ещё не принято.
- Новый поток должен переживать publish, обслуживать несколько процессов и создавать общий секрет, то есть добавляет операции с диском при старте и работе.
- Для ошибок доступа, исчерпания диска, занятого межпроцессного writer, ошибки sampler и завершения с pending-записями поведение не описано.
- `Program.cs:36–120` запускает MCP через Generic Host; `Hosting/RoslynMcpServiceCollectionExtensions.cs:41–48` регистрирует stdio transport. Размещение новой задачи/записи в host lifecycle или request pipeline способно сделать её отказ отказом всего сервера.
- Существующий fallback probe в `Diagnostics/HarnessSessionId.cs:13–23` явно сохраняет запуск при ошибке определения родителя. У нового потока аналогичная гарантия пока не заявлена.

## Why it matters

Исследовательская статистика не должна незаметно стать обязательной зависимостью работы инструментов. Реализация без заданного failure contract может оказаться формально соответствующей документу и при этом ухудшить доступность обычного MCP.

## Failure scenario

Каталог usage становится недоступен или диск заполнен. Ошибка создания/чтения секрета проходит из startup либо исключение записи проходит из tool-finally. Пользователь получает отказ MCP или ошибку уже успешно выполнившегося инструмента из-за статистики. Другой вариант — завершение ждёт writer без предела и мешает harness остановить процесс.

## Violated requirement / constraint

Неявный / отсутствует — требуется уточнение: является ли сбор best effort и как ограничено его влияние на доступность и задержку MCP. В документе нет явного разрешения ломать основную функцию ради исследования.

## Recommended change

Зафиксировать fail-open для статистики, ограничения ожидания записи/завершения и безопасное отключение сборщика при ошибке. Если секрет недоступен, пропускать статистику без fallback к открытым путям или простому SHA-256. Предусмотреть краткую диагностируемую ошибку вне stdout и проверки отказа каталога/диска и завершения. Конкретная модель writer или очереди может оставаться implementation choice.

## Notes for arbitration

Это пробел требований, а не утверждение о дефекте ещё не написанного кода. Confidence medium относится к неявному требованию non-interference. Если владелец сознательно допускает остановку MCP ради сохранности статистики, этот trade-off должен стать явным; для локального исследования такой выбор требует обоснования.
