# F-010 — Промежуточный прогон меняет схему, а уже записанные строки не имеют правила чтения

Severity: minor

Category: requirements

Confidence: high

## Target

`docs/usage-statistics/README.md`: поле `v`; абзац о синтетике и промежуточном прогоне через 2–3 дня; шаг 4 порядка работы.

## Claim

Поле версии схемы есть, а поведения агрегатора на смеси версий нет. Порядок работы специально ищет недостающие поля на второй-третий день, то есть предполагает правку схемы, пока первые дни уже лежат в каталоге с хранением две недели.

## Evidence

- Общие поля включают `v`, без значения первой версии и без правила, что делает инструмент с неизвестным или предыдущим `v`.
- «Промежуточный прогон — через 2–3 дня реального сбора, чтобы рано найти недостающие поля.» Найденное недостающее поле — это изменение строки, которую первые дни уже записали.
- Каталог общий для всех версий сервера. После publish нового патча старые и новые процессы дописывают одни и те же дневные файлы.

## Why it matters

Итог исследования считается по всему окну, не только по дням после исправления. Агрегатор, который понимает только последнюю схему, молча выбрасывает начало окна. Агрегатор, который читает новое поле как нуль у старых строк, занижает M1 или долю lazy. Оба прочтения сейчас допустимы.

## Failure scenario

1. Два дня пишется схема без отдельного ряда BuildHost или без признака полного открытия.
2. Промежуточный прогон показывает дыру, в main уходит патч, `v` увеличивается.
3. Финальный отчёт считает только новые строки либо подставляет нули в старые. Вывод «простой мал» относится к хвосту окна после того, как сервер уже перезапускали для publish.

## Violated requirement / constraint

Неявный / отсутствует — требуется уточнение.

Допущение: одна программа подсчёта одинаково читает каталог до и после правки полей, которую спека сама планирует на второй-третий день.

## Recommended change

Для каждой правки по ходу сбора выбрать одно, до publish патча.

- Добавление поля: старые строки остаются допустимыми, отсутствующее поле не превращается в нуль метрики. Метрика, которой без поля нельзя верить, в отчёте помечается как посчитанная только с даты новой `v`.
- Ломающее изменение смысла поля: новая `v` и отсечение в отчёте, а не перечитывание старых байтов по-новому.
- Первое опубликованное значение `v` записать в спеке, чтобы синтетика и агрегатор ссылались на него.

## Alternatives

Заморозить схему на все две недели и недостающие поля учесть только в следующем исследовании. Это согласовано с одноразовостью ряда, но отменяет пользу промежуточного прогона, которую спека уже объявила.

## Notes for arbitration

Если владелец решит, что первые дни — черновик и в решение не входят, это достаточно написать в шаге 4. Тогда смешение версий перестаёт быть дефектом, а промежуточный прогон явно обнуляет корпус.
