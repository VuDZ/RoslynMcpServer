# F-008 — Сбор расходится с опубликованным обязательством о телеметрии и с собственным HMAC

Severity: major

Category: requirements

Confidence: high

## Target

`docs/usage-statistics/README.md`: приватность, событие `start` («имя родителя»), O-01 и O-04, шаг 2 порядка работы. Действующие `README.md`, `PRIVACY.md`, `docs/ARCHITECTURE.md`.

## Claim

Черновик считает локальный JSONL без содержимого ответов совместимым с текущей политикой сервера и при этом кладёт в тот же файл путь родителя без HMAC. Опубликованные README и PRIVACY говорят, что сервер телеметрию не собирает. Порядок работы публикует логирование без обновления этих текстов.

## Evidence

- README репозитория: «RoslynMcpServer does not collect telemetry or transmit user data automatically.» `PRIVACY.md` повторяет это первым абзацем и отдельно определяет нынешний `ToolTelemetry` как локальный файловый лог, не канал продуктовой телеметрии. `docs/ARCHITECTURE.md` в модели наблюдаемости: сервер не отправляет продуктовой телеметрии и содержимого workspace на свой удалённый сервис.
- O-01 предлагает включение по умолчанию, потому что «данные локальные и без содержимого». Ни O-01, ни шаг 2 (логирование, версия, publish) не называют правку `PRIVACY.md`, корневого README и абзаца ARCHITECTURE.
- Локальная запись использования — сбор, даже без отправки по сети. Нынешняя формулировка запрещает сбор, а не только передачу: «does not collect … or transmit».
- Раздел приватности спеки: пути, cwd и ключи workspace — только HMAC; аргументы, тексты ответов, имена символов, среда и командные строки не пишутся. Событие `start` рядом с хешем cwd содержит «имя родителя» без HMAC. Сейчас родитель — это `ParentProcessSnapshot.ImagePath`: полный путь образа (`Cursor.exe`, `node` из каталога пользователя), а не короткое имя harness. Поле `harness` и так несёт класс harness.
- O-04 верно запрещает коммитить сырые файлы коллег. Это не чинит текст, который пользователь читает до установки, и не чинит путь родителя в файле, который остаётся на машине и может быть скопирован целиком вместе с солью.

## Why it matters

Политика приватности — действующее обязательство продукта, не черновик этой темы. Публикация сервера со включённым по умолчанию сбором при старом PRIVACY делает обязательство ложным в тот день, когда начинается сбор. Путь родителя ломает уже внутреннее правило «пути только в виде HMAC»: файл, который спека считает безопасным для локального хранения, содержит путь в профиле пользователя.

## Failure scenario

1. Владелец принимает O-01 как в таблице и публикует сервер. `PRIVACY.md` остаётся прежним.
2. Коллега по O-04 соглашается на агрегаты, опираясь на публичную фразу «телеметрию не собираем», и ставит тот же бинарь. Сбор на его машине уже идёт до отдельного разговора, потому что значение по умолчанию — включено.
3. В `start` лежит путь вида `C:\Users\<имя>\AppData\Local\...\node.exe`. Каталог usage, скопированный для разбора «без путей», этот путь содержит.

## Violated requirement / constraint

`README.md` и `PRIVACY.md`: сервер не собирает телеметрию автоматически. Внутренний раздел приватности спеки: пути только HMAC.

## Recommended change

Сделать сверку с публичной политикой частью шага 2, до publish.

- O-01 решать вместе с новой формулировкой: что именно собирается, что остаётся на машине, как выключить, что в файл не входит. Пока формулировка не принята, публикация с включённым сбором не начинается.
- «Имя родителя» писать как уже вычисленное короткое имя harness либо не писать отдельно. Полный `ImagePath` в JSONL не класть. Командную строку родителя по-прежнему не читать в этот файл: резолвер и так не логирует её для не-node.
- Агрегаты, которые можно коммитить, не содержат ни сырого пути, ни хеша, который при известной соли и списке путей обратим. Соль в репозиторий не попадает.

## Alternatives

Оставить сбор строго opt-in и не менять первое предложение PRIVACY, описав новый файл как выключенное расширение. Это выбор владельца в O-01. Даже тогда шаг publish должен обновить документ: абсолютное «не собирает» перестаёт быть правдой в момент, когда механизм появляется.

## Notes for arbitration

Замечание не выбирает за владельца opt-in или значение по умолчанию. Оно запрещает считать текущий PRIVACY уже выполненным только потому, что сеть не используется. Юридическую квалификацию слова telemetry арбитр может сузить; техническое противоречие с первым абзацем PRIVACY и утечка `ImagePath` от этой квалификации не зависят.
