# F-003 — HMAC одного и того же workspace не сойдётся у живых копий

Severity: blocker

Category: isolation

Confidence: high

## Target

`docs/usage-statistics/README.md`: определение workspace, общие поля, приватность (HMAC-SHA256 и соль), M3 и M5.

## Claim

Ключ для M3 — HMAC строки, но каноническая строка не задана, а соль создаётся «один раз» без правила гонки. Копии одной загруженной solution получают разные хеши, и пересечение в метриках пропадает. Восстановить его из JSONL нельзя: путь в файл не пишется.

## Evidence

- Спека задаёт ключ как абсолютный путь `.sln`/`.slnx`/`.csproj` плюс Configuration, Platform и TargetFramework и требует HMAC-SHA256 с солью из каталога статистики. Простой SHA-256 отвергнут именно потому, что известные пути подбираются.
- Загрузка сравнивает путь через `InputPathCanon`: `Path.GetFullPath`, на Windows сравнение без учёта регистра. Симлинки и прочие алиасы сознательно остаются разными ключами. HMAC сырой строки это сравнение не повторяет: `E:\Devel\App.sln` и `e:\devel\app.sln` для сервера один workspace, для хеша — два.
- Configuration, Platform и TargetFramework в кэше одного процесса сравниваются без учёта регистра и только если аргумент действительно передан (`MsBuildWorkspaceProperties.MatchesPassedLoadArguments`). Между процессами тот же пропуск уже признан другим ключом. На ветке `research/workspace-host-process` владелец 2026-10-29 выбрал WorkspaceKey = абсолютный путь + Configuration + канонический Platform + TFM (`design.md`: `WorkspaceKey = (absolute workspace path, Configuration, canonical Platform, TFM)`). Отсутствующее global property там кодируется как «не передано MSBuild; project defaults», без подстановки единого Debug/TFM. Спека статистики эту сериализацию не повторяет: явный `Debug` и пропущенный Configuration могут быть склеены или разведены в зависимости от того, хеширует реализация переданный аргумент, эффективное значение или null.
- Platform хранится дважды. `LoadedPlatform` — канон `Any CPU` → `AnyCPU`. `LoadedPlatformRaw` сохраняет исходное написание для CLI solution. В ключе спеки поле одно, без выбора ряда.
- Соль «создаётся один раз на пользователя» в каталоге, который общий для всех версий и процессов. Не заданы исключительное создание и запрет перезаписи. Одновременный старт нескольких копий после publish — обычный момент начала сбора: каждая может создать свою соль, последняя запись затирает файл, уже записанные строки подписаны другим ключом.
- Потеря или пересоздание файла соли посередине двух недель разрезает тот же путь на две несопоставимые серии.

## Why it matters

M3 — потолок выгоды общего процесса, M5 и цена возврата M2 тоже группируют по ключу. Ложное разведение копий уменьшает M3 и толкает таблицу к «оставить как есть» или к trim там, где копии одного workspace реальны. Повторный прогон агрегатора по тем же файлам ошибку не лечит.

## Failure scenario

1. Две копии открывают один и тот же файл: одна получает путь `E:\Devel\App.sln`, другая `e:\devel\app.sln` с платформой `Any CPU`.
2. Каждая хеширует свою исходную строку. Соль при совместном старте ещё и разъехалась.
3. M3 по этому ключу равен нулю, хотя для выбранного владельцем WorkspaceKey это один workspace. Отчёт не видит дублирование, ради которого собирались данные.

## Violated requirement / constraint

Q-02 и определение workspace в спеке. Неявное допущение: любая строковая запись абсолютного пути и тройки MSBuild-свойств стабильна между процессами.

## Recommended change

Зафиксировать одну сериализацию до HMAC и правило соли.

- Взять ту же сериализацию, которую владелец уже записал для общего host, а не вторую. Путь: `Path.GetFullPath`; на Windows для ключа — одно invariant-case представление, нормализованные разделители и конечный separator, корень сохранён; symlink/junction не склеивать. Platform — канонический (`Any CPU` → `AnyCPU`). Пропущенное global property — явный токен «не передано», без подстановки Debug. `buildArgs` в ключ не входят.
- Привести в спеке пары «равны / не равны»: регистр и слеши пути, `Any CPU` против `AnyCPU`, пропущенный Configuration против явного `Debug` (не равны), другой TargetFramework.
- HMAC с локальной солью оставить для файла статистики. Не подменять его unsalted SHA-256, которым research-дизайн считает HostKey для встречи процессов: у файла статистики другая угроза, у ключа — та же строка.
- Соль создавать исключительным созданием файла. Существующий файл не перезаписывать. Процесс, проигравший гонку, читает уже записанную соль и ею подписывает свои строки.
- Смена соли — новый каталог или явный разрыв серии, не тихая перезапись.

## Alternatives

Отдельный устойчивый идентификатор workspace в каталоге статистики вместо HMAC пути. Ему нужна та же канонизация, чтобы вторая копия нашла уже выданный id. Приватности это не добавляет.

## Notes for arbitration

Канон пути и токен пропущенного свойства уже написаны в design общего host; design целиком при этом не принят как реализация. Если владелец хочет для статистики другое равенство, чем для WorkspaceKey, это отдельное решение: иначе M3 и будущий host считают «один workspace» по-разному. Версию сериализации стоит включить в `v`.
