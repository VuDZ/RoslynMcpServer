# F-006 — Каталог JSONL не сохраняет полный ряд на длину исследования

Severity: major

Category: recovery

Confidence: high

## Target

`docs/usage-statistics/README.md`: каталоги usage, файл `usage-YYYYMMDD.jsonl`, хранение 14 дней, предел размера, порядок работы (сбор около двух недель и промежуточный прогон).

## Claim

Метрики — интегралы по непрерывному ряду `mem` и границ вызовов. Контракт файла не обеспечивает ни целую строку при нескольких процессах, ни сохранность этого ряда до итогового отчёта.

## Evidence

- Файл один на день на всех процессов, «запись с общим доступом». Для текстового лога сервер уже включает `shared: true` у Serilog (`Program.cs`), потому что несколько процессов пишут в один дневной файл. Для JSONL аналога атомарной строки нет: обычный append открывает файл, смещается в конец и пишет. Два таких писателя на Windows перемешивают байты одной строки.
- Предел размера назван целью («зациклившийся процесс не забил диск») и не имеет ни числа, ни поведения: остановить запись, выкинуть старые строки, перейти на следующий файл. Остановка записи после насыщенного дня отрезает ночные `mem`. Ночной простой — основная масса M1.
- Хранение «по аналогии с текстовым логом (14 дней)». Сбор — «около двух недель», отчёт в конце. Окно хранения равно окну исследования. Старт процесса на пятнадцатый день удаляет первый день, если реализация копирует `retainedFileCountLimit: 14`.
- Каталог Linux — `$XDG_CACHE_HOME`, по умолчанию `~/.cache/roslyn-mcp/usage/`. По XDG Base Directory это каталог несущественных файлов, которые приложению положено уметь восстановить. Ряд usage из реальной работы не восстанавливается. На машине владельца логи уже лежат рядом, в `~/.cache/roslyn-mcp/logs`, и неделя 2026-10-21…28 оттуда использована для решения O-02 общего host (ветка `research/workspace-host-process`, запись reset-decision). Соседний `usage/` с этим опытом согласован, но очистка cache по-прежнему уничтожает ряд, который нельзя пересоздать. Каталоги Cache на macOS система тоже имеет право чистить. `%LOCALAPPDATA%` так не объявлен.
- Промежуточный прогон через 2–3 дня и синтетика «смена суток» предполагают, что агрегатор склеивает дни по `proc`. В определении входа этого требования нет, оно есть только внутри фразы про синтетические логи.

## Why it matters

Повреждённая или обрезанная середина ряда тихо меняет M1 и M3. Это не ошибка, которую видно по падению тестов на коротком синтетическом файле: синтетика из спеки не включает двух одновременных писателей и не включает файл, упёршийся в предел в середине дня.

## Failure scenario

1. Днём несколько копий MCP дописывают один `usage-YYYYMMDD.jsonl`. Две строки `tool` и `mem` записываются одним и тем же куском файла и перемешиваются.
2. Агрегатор пропускает битую строку либо обрывает разбор дня. Вечерних и ночных `mem` в итоге нет.
3. M1 занижен, отчёт рекомендует оставить как есть. Либо на Linux очистка `~/.cache` на десятый день удаляет каталог целиком, и промежуточный вывод «данных мало» на самом деле означает, что ряда уже нет.

## Violated requirement / constraint

M1–M3 требуют непрерывный ряд по процессам на время сбора. Неявное допущение: дневной append-файл в cache-каталоге с хранением на 14 дней этот ряд сохраняет.

## Recommended change

Дописать контракт корпуса отдельно от текстового лога.

- Одна запись JSONL — один append, который на целевых ОС атомарен для размера строки (одна системная запись, файл открыт на добавление). Порванная хвостовая строка при разборе пропускается, предыдущие остаются.
- При пределе размера начинать следующий файл того же дня, а не останавливать `mem`. Предел задать числом.
- Срок хранения сделать длиннее сбора, либо явным шагом порядка работы копировать каталог в постоянное место до любой ротации и до очистки cache. Корень `~/.cache/roslyn-mcp/usage/` можно оставить рядом с уже существующими Linux-логами; единственная копия ряда в cache — нет.
- Агрегатор читает все файлы каталога одной машины как одну ленту и склеивает `proc` через границу суток. Это требование к инструменту, не только сценарий теста.

## Alternatives

Писать JSONL рядом с текстовым логом exe. Спека это отвергает: каталог exe на Windows заменяется publish. Устойчивый пользовательский каталог нужен. Менять Linux-корень на `XDG_STATE_HOME` не обязательно: логи владельца уже в `~/.cache/roslyn-mcp/`. Обязательна вторая копия вне cache на время сбора.

## Notes for arbitration

Часовой пояс в имени `usage-YYYYMMDD` (UTC против местного, как у дневного Serilog) на склейку по `proc` не влияет, если агрегатор читает каталог целиком. Отдельного замечания из этого не делаю. Фраза спеки про Linux launcher подтверждается не этим checkout, а веткой исследования: внешний `~/.local/share/roslyn-mcp/launch.sh` и логи в `~/.cache/roslyn-mcp/logs` (L-01, открыт 2026-10-29). В `Program.cs` этого репозитория путь лога по-прежнему `AppContext.BaseDirectory/logs`.
