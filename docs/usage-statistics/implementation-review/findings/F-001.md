# F-001 — `requires_workspace` шире каталога и фактического lazy load

Severity: major

Action: исправить до сбора

## Target

Событие `tool` / поле `requires_workspace`. Метрика M2.

## Claim

Спецификация задаёт флаг как статическое свойство каталога плюс фактический lazy load.
Код ставит его в true при любом обращении к снимку решения, даже когда workspace уже загружен и lazy load не было.
Каждый такой вызов после простоя дольше T становится эпизодом M2 и умножается на медиану полного открытия.

## Evidence

Норма, `docs/usage-statistics/README.md`, события `tool`:

> «Нужен ли workspace» — статическое свойство инструмента из каталога (semantic и graph-инструменты — да; `get_tool_help`, чтение файла, git — нет) плюс фактический lazy load.

Каталог этому соответствует: `RequiresWorkspace` у Navigation / Ast / CodeFix / Refactoring и у перечисленных имён (`load_workspace`, `list_projects`, `get_project_graph`, `get_test_list`, …). `run_specific_test`, `run_dotnet_test`, `run_test_by_filter` и `decompile_type` в этот список не входят (`Hosting/McpToolCatalog.cs`).

Дальше флаг расширяется:

- `EnsureWorkspaceFromConfigAsync` вызывает `MarkWorkspaceRequired()` до проверки, что решение уже есть (`Services/Workspace/SolutionManager.cs`).
- `GetSanitizedPublishedSolution` вызывает `MarkWorkspaceRequired()` при каждом входе.
- `BeginLoad` вызывает `MarkWorkspaceRequired()` для любой загрузки, не только для lazy.
- `EndTool` записывает `requires_workspace = call.RequiresWorkspace || call.LazyLoad` (`Diagnostics/UsageStatistics/UsageStatisticsService.cs`). Анализатор берёт последнее значение вызова, то есть уже расширенное.
- `run_specific_test` всегда читает снимок через `GetSanitizedPublishedSolutionAsync` (`Tools/TestTools.cs`). Без решения фильтр строится по именам; загрузка для этого вызова не обязательна.
- Маршрут DLL у `run_dotnet_test` / `run_test_by_filter` читает снимок через `GetPublishedSolutionAfterDiskSyncAsync` (`ExecuteDllTestsAsync`).
- `UsesWorkspace` для группы Decompile возвращает true, если в аргументах нет `assemblyPath` (`Hosting/UsageStatisticsFilters.cs`). Это читается на `tool_start`, до какого-либо lazy load. Тест `Decompiler_requires_workspace_only_without_an_explicit_assembly_path` закрепляет это расширение.

`get_changed_files` вызывает `GetCurrentSolution`, но `MarkCurrentSolutionAccess` не поднимает флаг инструменту, который уже есть в каталоге. Git-вызов спецификация относит к «нет»; этот путь сам по себе флаг не портит.

## Why it matters

M2 — цена выгрузки. На агентской нагрузке `run_specific_test` и прогоны тестов идут часто. После простоя они выглядят как вызовы, которым нужна перезагрузка workspace, хотя каталог этого не говорит и lazy load не было. Выгрузка кажется дороже, чем по правилу спецификации.

## Failure scenario

1. Процесс держит workspace и простаивает дольше T.
2. Приходит `run_specific_test`. Решение уже опубликовано, `EnsureWorkspaceFromConfigAsync` выходит сразу, `lazy_load` остаётся false.
3. `MarkWorkspaceRequired` всё равно ставит `requires_workspace: true`.
4. Анализатор считает эпизод M2 и прибавляет медиану полного открытия этого ключа.

## Violated requirement

Абзац «Нужен ли workspace» и определение M2: эпизод — простой дольше T, затем вызов, которому нужен workspace.

## Recommended change

На событии `tool` поле `requires_workspace` равно биту каталога или фактическому lazy load этого вызова. Обращение к уже загруженному снимку флаг не меняет.

- Убрать `MarkWorkspaceRequired()` из входа `EnsureWorkspaceFromConfigAsync` и `GetSanitizedPublishedSolution`.
- `BeginLoad` не помечает текущий вызов нуждающимся в workspace. Lazy по-прежнему ставит `LazyLoad`, когда источник — файл конфигурации.
- `EndTool` пишет каталожный бит, переданный в `BeginTool`, или `LazyLoad`. Промежуточное расширение флага не становится значением события.
- `decompile_*` без `assemblyPath` остаётся false, пока этот вызов сам не сделал lazy load. Аргумент `assemblyPath` в поток не пишется.
- `MarkCurrentSolutionAccess` для имён вне каталога не расширять и не использовать как способ пометить `run_specific_test`.

## Tests

- Инструмент с `RequiresWorkspace == false` вызывает `EnsureWorkspaceFromConfigAsync` / `GetSanitizedPublishedSolution`, когда решение уже загружено: у `tool` оба поля `requires_workspace` и `lazy_load` равны false. Покрыть путь `run_specific_test`.
- Тот же класс инструмента доводит загрузку из конфигурации до `load` с `source=lazy`: на конце вызова `lazy_load` и `requires_workspace` равны true.
- Существующая проверка `get_tool_help` и `read_file_range` остаётся false. `Decompiler_requires_workspace_only_without_an_explicit_assembly_path` обновить под норму, а не сохранять как контракт.
- Убедиться, что аргумент `assemblyPath` по-прежнему не попадает в JSONL.

## Out of scope

Не переносить `run_dotnet_test` в каталожный список «нужен workspace»: спецификация относит туда semantic/graph-инструменты и фактический lazy load, а не любой код, который умеет прочитать снимок, если он уже есть.
