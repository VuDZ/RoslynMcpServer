# Критика реализации usage-statistics

Создано: **2026-10-30**. Состояние обновлено: **2026-10-30**.
Статус: **fixed** для F-001/F-002 в версии 1.5.20; F-003 **resolved** уточнением M2.
[`.status`](.status), [результат и проверки](result.md), [validation](validation.json).

Исходные findings относятся к коду **1.5.19**. Их доказательства и рекомендации
сохранены как история ревью. Норма для текущей реализации — [спецификация](../README.md)
и [схема](../schema.md); текущие статусы ниже заменяют исходные указания исправить
F-001/F-002 и ждать решения по F-003.

## Текущее состояние

- **F-001 — fixed.** `requires_workspace` равен биту каталога или фактическому lazy
  load. Snapshot access и аргументы decompile больше не расширяют флаг.
- **F-002 — fixed.** Пробелы относятся к процессу, неполная копия исключает свой ключ
  из M3/M3a/M3r. Знаменатель — объединение годных наблюдений; `gap_hours` — отдельная
  диагностика. Правило внесено в нормативное
  [восстановление интервалов](../README.md#восстановление-интервалов), включая пример
  `usable_hours = 10/60`, `gap_hours = 1/60`.
- **F-003 — resolved.** Фактические времена сохраняются, M2 явно определена как
  оценка дополнительных загрузок. [Уточнение](result.md#уточнение-f-003).

## Подтверждение и границы

Многопроцессная синтетика — **49 сценариев / 161 assertion PASS**. Проверки decompile
и `run_specific_test` приведены к норме. Windows/Linux проверки исправлений 1.5.20
сохранены в [результате](result.md#исправления-1520).

Последующий [Codex/Windows smoke 1.5.21](../codex-smoke.md) с двумя сабагентами прошёл
после исправления отдельного дефекта `Failed: 0` → `success=false`.
Затем выполнен [Claude Code/Linux smoke 1.5.21](../claude-code-smoke.md), включая Linux
PowerShell; D-01/D-02 исправлены в [1.5.22](../implementation.md#исправления-ревью-1522),
повторный native Linux smoke ещё нужен. Cursor, dsh, OpenCode и длительный сбор остаются
впереди. Закрытие findings не объявляет приёмку всего пакета и не включает автоматический
выбор стратегии.
