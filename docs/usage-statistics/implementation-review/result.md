# Критика реализации 1.5.19

Дата: **2026-10-30**. Норма: [README.md](../README.md), [schema.md](../schema.md).
Код: ветка `usage-statistics`, версия **1.5.19**. Validation: [implementation.md](../implementation.md).

## Verdict

Запись JSONL, ключ, счётчики памяти, fail-open и отчёт без автовыбора стратегии соответствуют спецификации.
Два расхождения меняют метрики, по которым владелец выбирает стратегию. Их надо исправить до сбора.
Третье исходно требовало выбора владельца; после обсуждения оно закрыто [уточнением измерений и модели M2](#уточнение-f-003) без изменения кода.

## Что сходится и в этот пакет не входит

- Каталог `usage/`, JSONL v1, ротация 32 MiB, хранение 60 дней, строка до 4 KiB, пропуск порванной последней строки.
- Ошибка статистики не ломает инструмент; `seq` растёт до записи; ожидание записи на выходе ограничено 1 с.
- Ключ: фактически удерживаемые Configuration, Platform, TargetFramework; пропуск — токен `-1`; `Any CPU` = `AnyCPU`; Windows-путь в одном регистре; symlink не раскрывается. Неуспешный load и отменённый reset оставляют прежний ключ.
- Память: Windows private bytes, Linux `RssAnon` + `VmSwap`, BuildHost тем же правилом, что reaper; неизвестный ребёнок — null, не ноль; снимок без GC.
- `tool_start` хранит оборванный вызов. Агрегаты заменяют ключи на `K1`, `K2`. Численных порогов и автовыбора стратегии нет.
- Граница validation про harness и macOS runtime остаётся верной и этим пакетом не закрывается.

## Уточнение F-003

Дата: **2026-10-30**. Статус: **resolved** после обсуждения измерений и поручения
«поправь если надо». Сохранён текущий расчёт; неоднозначность снята в спецификации.

`tool_start` / `tool` уже сохраняют начало и завершение вызова, `load` — начало
попытки, измеренную длительность, ожидание lock и связь с вызовом. Схема дополнена
описанием существующих `call` / `start_ts`, без новых полей и изменения JSONL v1.
Фактические загрузки сохраняются в сыром ряду и отчёте, включая исключённые из M2.

M2 явно определена как оценка дополнительных загрузок при будущей выгрузке по
таймауту. Вызов, уже выполняющий некешированную попытку открытия, не добавляет
эпизод M2; успешная попытка при этом входит в измеренную медиану цены. Неуспешные
попытки и смена ключа остаются в фактических наблюдениях и не получают выдуманной
дополнительной загрузки прежнего ключа. Точную добавочную задержку выгрузки нужно
измерять отдельным сравнительным экспериментом, когда сама выгрузка будет реализована.

Код collector и анализатора, тесты и версия 1.5.20 не изменены. Повторный запуск
`Test-McpUsage.ps1` — **49 сценариев / 161 assertion PASS**, включая baseline-fresh,
failed-fresh и cached-same-key. Фактические начала/длительности и протокол уже проверены
в validation 1.5.20 выше; docs-only уточнение не требует повторных C# suites.
Runtime SHA256 проверены до/после; `git diff --check` — PASS. Настоящие harness и
сбор данных остаются следующим этапом и этим уточнением не запускались.
