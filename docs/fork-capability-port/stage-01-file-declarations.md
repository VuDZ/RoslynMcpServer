# Этап 1. Объявление в файле и координаты определения

Статус: сделан (v1.4.4). Читать перед кодом: [navigation-definition-references.md](navigation-definition-references.md).

## Цель

`find_symbol_references` с `filePath` и без `line` выбирает объявление в этом файле явно. `find_symbol_definition` в том же виде больше не требует строку. У каждого места определения есть колонка и полное имя.

Позиционный разбор VuDZ, `FindSourceDefinitionAsync` и группировка перегрузок по решению не меняются.

## Поведение

Общий сбор объявлений по файлу, сравнение идентификатора порядковое, с учётом регистра (как сейчас у токенов на строке). Имя по решению по-прежнему без учёта регистра. Эти два режима не выравнивать.

Виды: класс, struct, record, интерфейс, enum, метод, конструктор, деструктор, свойство, событие, поле, поле события. Оператор, индексатор и локальная функция в этот список не входят: их по-прежнему выбирают строкой и колонкой.

Одно совпадение — этот символ. Несколько — ошибка, без поиска ссылок и без определения. В списке полное имя и строка:колонка идентификатора, не начала объявления с атрибутами и модификаторами. Ноль совпадений — прежняя ошибка «не найдено».

`find_symbol_definition` с файлом и без строки при одном совпадении печатает все исходные места этого символа. Частичный тип в двух файлах даёт оба места. Форк печатает только первое и пишет «найдено 1» — так не делать.

К каждому месту определения добавить колонку и полное имя (`SymbolDeclarationResolver.GetSymbolFqn`, без `global::`). Номер строки остаётся.

`find_symbol_definition` с файлом и строкой по-прежнему идёт через `SourcePositionHelper` и `FindSourceDefinitionAsync` на очищенном снимке. Запасной поиск по телу метода не добавлять. `SourcePositionHelper` не подменять версией форка: та не видит параметр и локальную функцию.

`directOnly` на этом этапе нет.

## Файлы

- `Tools/NavigationTools.cs` — файловый режим обоих инструментов, вывод определения.
- При росте метода сбор объявлений вынести в `Services/` рядом с `SourcePositionHelper`, внутренний тип. Второй резолвер полного имени не заводить.
- Тесты в `RoslynMcpServer.Tests/`: новый класс на файловый режим. Существующие `SourcePositionHelperTests` и `SymbolDeclarationResolverTests` должны остаться зелёными.

Смысл проверок взять из форка `PositionSymbolTests` (свойство, поле, событие, конструктор рядом с классом, два одноимённых метода). Фикстуры форка не копировать. Добавить: struct или record находится; частичный класс по имени решения по-прежнему показывает оба файла; позиция на параметре по-прежнему даёт символ; позиция на использовании по-прежнему уходит в исходное определение, если оно есть в решении.

## Контракт

Новых параметров нет. `symbolName` остаётся первым.

Меняется текст:

- несколько объявлений в файле больше не молчат и не берут первое;
- свойство, поле, событие, конструктор, struct, record, enum в файле без строки начинают находиться;
- определение с файлом и без строки при одном объявлении успешно;
- в блоке определения появляются колонка и полное имя.

Поиск по решению без файла и режим «строка без колонки» остаются прежними.

## Инварианты

Опубликованный снимок, перепривязка символа перед `SymbolFinder`, очистка битой ссылки на анализатор, курсор ссылок, токен вместо `IndexOf`.
