# F-004 — У collection fixture корнем назван только конструктор

Severity: minor

Category: correctness

Confidence: medium

## Target

`docs/rapid-tia/README.md`, корни тестового класса: цепочка `[Collection]` → `ICollectionFixture<T>` → конструктор `T`. Раунд 1, `review-grok` F-009 закрыл поиск определения коллекции; этот пробел в той же цепочке.

## Claim

Для тестового класса корни включают `IAsyncLifetime` и `Dispose`/`DisposeAsync`. Для фикстуры коллекции корнем назван только конструктор `T`. Создание в `InitializeAsync` фикстуры в граф не входит. Если в том же контексте уже есть хоть какое-то создание, откат на CHA не включается.

## Evidence

- Корни тестового класса: `IClassFixture<T>` — конструктор `T`; отдельно `IAsyncLifetime`, `Dispose`/`DisposeAsync`.
- Collection fixture: цепочка доходит до «конструктор `T`». `IAsyncLifetime` фикстуры не упомянут. Ненайденное определение коллекции по-прежнему даёт ограничение и CHA; найденное определение этот путь не открывает.
- R-05 и раздел диспетчеризации: CHA только когда нет ни одной созданной реализации, включая моки. Одно создание в конструкторе фикстуры или в тесте CHA для этого класса выключает.
- Каталог «Корни» требует collection fixture с определением и без него и не требует `InitializeAsync` фикстуры.

## Why it matters

Связь коллекции, которой не хватало в раунде 1, теперь есть, но обрывается на конструкторе. Асинхронная подготовка фикстуры — обычное место, где создаётся реализация, которую тест потом вызывает через интерфейс.

## Failure scenario

`Database` в конструкторе только сохраняет строку подключения, а `InitializeAsync` делает `new SqlRepo(...)`. Тест в коллекции вызывает `SqlRepo` через интерфейс и больше ничего не создаёт. Конструктор фикстуры создания реализации не содержит, но другое создание в досягаемом коде класса есть (`new` тестовых данных). CHA не включается. Методы `SqlRepo` в битсет теста не попадают. Правка `SqlRepo` тест не выбирает.

Если конструктор пуст и других созданий нет, CHA тест сохраняет. Дыра появляется, когда создание уже есть где-то ещё в том же контексте.

## Violated requirement / constraint

Неявный / отсутствует — требуется уточнение. Для тестового класса жизненный цикл xUnit перечислен, для `T` из `ICollectionFixture<T>` — нет, хотя цепочка как раз делает `T` частью контекста теста.

## Recommended change

На `T` из `IClassFixture<T>` и `ICollectionFixture<T>` распространить те же корни жизненного цикла, что и на тестовый класс: конструктор, `IAsyncLifetime`, `Dispose`/`DisposeAsync`. Ненайденное определение коллекции оставить как ограничение и CHA.

## Notes for arbitration

Если владелец сознательно берёт только конструктор, это нужно написать одной фразой: создания в `InitializeAsync` фикстуры не видны, CHA их не подменяет, когда в контексте уже есть другое создание.
