# F-001 — Условие про extension из метаданных не на чем проверить

Severity: major

Category: correctness

Confidence: high

## Target

`docs/rapid-tia/README.md`, «Изменения связывания (R-14)», абзац про новый метод в обычном типе. Рядом — «Узлы», «Хранение» и R-02.

## Claim

Новый метод расширяет ответ до проекта, если в битсетах есть одноимённый extension-лист из метаданных. Битсеты определены как множества узлов, а узлы — только члены исходников solution. У листа из NuGet нет проекта solution, поэтому в битсет он не входит. Условие, которым как раз ловят прежнюю цель в метаданных, на этой модели не выполняется. Если лист всё же класть в битсет, та же фраза без указания, в чьём битсете, расширяет проект почти на каждый новый метод с распространённым именем — то, от чего этот абзац в следующей фразе отказывается.

## Evidence

- R-02: разбор только исходников solution; сборки NuGet и прочий metadata-код — листья графа.
- «Узлы» — члены типов из исходников solution. Идентификатор узла — пара «проект + `ISymbol.GetDocumentationCommentId()`». Проект — ключ экземпляра вроде `SnapshotProjectKey`, не произвольная сборка.
- «Достижимость»: битсеты достижимых узлов тестового класса и метода. Запрос ищет тесты, чьи битсеты содержат изменённый узел.
- Новый метод: изменёнными считаются одноимённые члены типа и иерархии и все одноимённые extension-методы в исходниках solution. Дальше: «Если в битсетах есть одноимённый extension-лист из метаданных (прежней целью мог быть extension из NuGet), — проектное расширение проекта типа».
- Следующая фраза того же пункта: «Проектное расширение на любой новый метод не выбрано: добавление метода — самая частая правка, и ответ огрубел бы почти всегда».
- Каталог «Изменения связывания» держит extension в исходниках (другой статический класс, Library через App, extension в тестовом проекте и другой `partial`-файл). Ряда, где прежняя цель — extension из NuGet, нет.

## Why it matters

Пункт добавлен, чтобы не пропустить перепривязку на новый метод, когда прежний extension объявлен в NuGet или в проекте, который из проекта типа не виден. Вторая половина для исходников solution выразима: это узлы. Половина про метаданные ссылается на битсет, в котором такого узла нет. Реализация либо никогда не расширяет ответ для NuGet, либо, чтобы условие хоть раз сработало, считает листом любой достижимый `Enumerable.Where` и поднимает до проекта почти всякое добавление метода с таким именем.

## Failure scenario

В solution тесты вызывают `items.Count()`, цель — extension из BCL. Агент добавляет в тип приложения метод `Count(...)`. Узла «extension-лист `Count`» в битсетах нет: это не член исходника и не пара «проект solution + идентификатор». Проектного расширения нет. Вызовы, которые перепривязались на новый метод, в ответ не попадают.

Обратное чтение той же фразы: лист всё-таки записывают в битсет каждого теста, который до него дошёл. `Enumerable.Count` есть почти в любом тестовом проекте. Новый `Count` на типе приложения даёт проектное расширение проекта типа. Абзац выше как раз отверг такое расширение для обычного нового метода.

## Violated requirement / constraint

Вводный абзац R-14: пометить прежнюю цель или расширить ответ. R-02 и определение узла не дают листу из метаданных места в битсете. Соседняя фраза того же пункта отвергает проектное расширение на любой новый метод.

## Recommended change

Не искать лист в битсетах. Опереть условие на ребро фактов: у вызова, который новый метод может вытеснить, цель baseline — extension из метаданных с тем же именем. Для такого ребра задать ключ листа (идентификатор документации без проекта solution). Проектное расширение — только если такое ребро есть, а не если одноимённый лист встретился в любом битсете solution. В каталог добавить этот ряд и отрицательный: другой тест вызывает `Enumerable.Count`, но вызовов, которые новый метод вытесняет, нет — проект из-за этого не расширяется.

## Alternatives

Считать любой одноимённый metadata-лист в графе достаточным поводом для проектного расширения. Тогда надо убрать фразу, что на любой новый метод расширение не выбирается: для обычных имён это расширение и будет.

## Notes for arbitration

Спайк не нужен. Вывод меняется только если в модели графа листья уже являются узлами битсета и это где-то записано. В текущем README узлы — члены исходников, битсет — множество узлов.
