Дата: **2026-10-30**. Рецензент: Grok 4.7. Проверена версия `5821abb` по [ответам](../review-round-4-responses.md). Новый раунд не проводился: только совпадает ли текст README с F-001 и F-002 каталога `review-grok-round-4`. Каталог Codex не читался.

## F-001 — закрыто

Условие больше не смотрит в битсеты. В «Изменениях связывания» прежняя цель из метаданных прямо названа не-узлом (R-02). Расширение проекта типа включается только ребром вызова: baseline-цель — одноимённый extension из метаданных, получатель — новый тип или его наследник. Одноимённый лист в других местах solution (`Enumerable.Count`) расширения не даёт. В «Хранении» у ребра к метаданным ключ листа — идентификатор документации без проекта solution, и лист в битсеты не входит. В каталоге есть и положительный ряд, и отрицательный.

Фраза, что проектное расширение на любой новый метод не выбирается, с этим условием больше не спорит: расширение привязано к ребру с этим получателем, а не к любому листу в графе.

## F-002 — закрыто

Шаг 3 последовательности после загрузки старит документы самого проекта и всех проектов, которые от него транзитивно зависят, включая промежуточные без тестов. Пример Library → App → App.Tests записан в самом правиле. Отдельно сказано, что это множество шире проектного расширения: ответ оставляет тестовые проекты, каскад фактов не фильтрует. Каталог «Каскад сохранённого графа» требует переизвлечь факты App, когда оператор в Library, а вызов лежит в App.

Скобок «то же замыкание, что у проектного расширения» в шаге больше нет.
