# F-002 — Новые тесты не могут попасть в ответ через baseline-битсеты

Severity: major

Category: correctness

Confidence: high

## Target

docs/rapid-tia/README.md:69–73, 89–92, 148–152, 240–242, 319–323 — раннее отбрасывание файлов, достаточность baseline, алгоритм запроса.

## Claim

Утверждение «новые тесты сами изменены» не обеспечено алгоритмом. Новый корень отсутствует в baseline и в его битсетах. Раннее отбрасывание файлов без достижимых узлов может удалить его ещё до распознавания теста; добавление теста в старый файл тоже не создаёт соответствующий baseline-битсет.

## Evidence

- Строки 70–71 без исключений отбрасывают файл без узлов, достижимых из тестов.
- Строки 89–92 используют изменённость новых тестов как обоснование достаточности старого графа.
- Единственный описанный запрос в строке 152 выбирает тесты по наличию изменённых узлов в уже построенных битсетах. Непосредственное добавление новых/переименованных корней в результат не определено.
- Граф в сессии не обновляется (240–242).
- В текущем workspace появление файла на диске само по себе даже не добавляет Roslyn Document: Services/Workspace/WorkspaceDocumentDiskSync.cs:97–110. Это закреплено тестом ApplyAsync_does_not_add_new_cs_under_project_directory в RoslynMcpServer.Tests/Workspace/WorkspaceDocumentDiskSyncTests.cs и описано в docs/ARCHITECTURE.md, «Workspace». Reload может включить файл, но по данному плану baseline сохранится.
- Каталог проверки прямо включает добавление/переименование членов и файлов (319–323), однако отдельное правило включения новых корней отсутствует.

## Why it matters

Самая обычная задача «добавить регрессионный тест» может дать ноль затронутых тестов или оставить только старых соседей. Это противоречит собственному обоснованию алгоритма и не относится к перечисленным слепым зонам.

## Failure scenario

В существующий Tests.cs с уже достижимым TestOld добавляется TestNew с атрибутом Fact. Файл проходит первый этап, но TestNew не содержится ни в одном baseline-битсете. Нет правила, которое добавит его непосредственно. Вариант с новым TestsNew.cs отбрасывается ещё раньше; после reload документ появляется, но baseline остаётся прежним.

## Violated requirement / constraint

Строки 89–92 — новые тесты должны учитываться за счёт собственной изменённости. R-03/R-04 и сохранение baseline при reload не разрешают незаметно заменить baseline новым графом.

## Recommended change

До отсечения по baseline-достижимости выделять новые и изменённые корни тестов и включать их текущие исполняемые имена напрямую. Для новых/удалённых путей, ещё не представимых текущим workspace, сохранять уровень 0 и сообщать о необходимости reload. Проверить добавление теста в старый файл, новый файл до/после reload, переименование теста и превращение обычного метода в тест.

## Notes for arbitration

Нужен контракт различения «тест отсутствует в baseline» и «существующий тест не затронут». Перестройка всего графа при каждом edit не требуется. Finding снимается явным отдельным путём обработки текущих корней, выполняемым до раннего pruning.
