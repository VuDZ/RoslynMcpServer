# F-003 — Правки using и другого контекста вне членов теряются

Severity: major

Category: correctness

Confidence: high

## Target

docs/rapid-tia/README.md:61–75, 133–138, 185–202 — синтаксическое сравнение членов, исключения связывания и актуализация сохранённых фактов.

## Claim

Изменение файла, которое меняет связывание, но не синтаксис членов и перечисленные свойства типа, не получает ни изменённого узла, ни обязательного отката. Обычный using alias и global using — конкретные примеры. Файл только с global using дополнительно не имеет достижимых member-узлов и может быть отброшен на первом этапе.

## Evidence

- Baseline хранит checksum файла и хеши синтаксиса членов (61–68).
- После обнаружения файла решение сужается до изменённых членов; откат до файла задан только для невозможности разобрать файл до членов (69–73).
- Список исключений связывания содержит новые перегрузки, extension-методы, overrides и изменения атрибутов/partial/базовых типов/интерфейсов (133–138). Изменений imports/aliases/global usings в нём нет.
- Сохранённые факты актуализируют чужие документы только при изменении поверхности объявлений, определённой как сигнатуры, иерархия и атрибуты (185–202). Замена global using alias может не изменить ни одну из этих поверхностей, хотя меняет связывание других документов.

## Why it matters

Предлагаемый fast path выдаёт отсутствие изменений для корректной правки обычного C#, меняющей поведение достижимого метода. Этот класс пропусков не обозначен как сознательная слепая зона и легко устраняется консервативным откатом без semantic model на запросе.

## Failure scenario

В A.cs alias «using Worker = First.Worker;» заменяется на «using Worker = Second.Worker;». Тело достижимого Run, вызывающее Worker.Execute(), не меняется. Checksum файла другой, все member-хеши прежние, синтаксис корректен, перечисленных изменений типа нет. Результат второго этапа пуст, хотя тесты Run должны быть выбраны.

Если alias объявлен через global using в Imports.cs, сам файл может не содержать ни одного узла; смена alias также меняет факты неизменённых файлов при восстановлении кеша.

## Violated requirement / constraint

Заявленное различение комментариев/пробелов и содержательных правок (74–75); обработка изменений связывания неизменённого кода (133–138); объяснение достаточности baseline (89–92).

## Recommended change

В синтаксическом снимке отдельно учитывать контекст файла вне членов. Для обычных using/alias применять как минимум откат до файла, для global using — до затронутого проекта и зависимых тестовых проектов. Этот же контекст должен участвовать в инвалидации сохранённых semantic facts. Добавить случаи обычного alias и отдельного файла global using; при удалении trivia сохранять смысл директив препроцессора.

## Notes for arbitration

Полный semantic diff не требуется. Достаточно определить консервативную обработку изменений, которые не укладываются в member hashes. Namespace/type-header изменения также должны иметь явное правило, но finding доказан уже на using alias и не зависит от полноты этого дополнительного списка.
