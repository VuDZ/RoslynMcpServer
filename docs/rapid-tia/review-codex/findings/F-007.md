# F-007 — Точное множество запущенных тестов не следует из contains-фильтра

Severity: minor

Category: testability

Confidence: high

## Target

docs/rapid-tia/README.md:302–303, 313–315, 337–339 — TestFilterHelper и требование выбрать «ровно эти тесты» в интеграции.

## Claim

Интеграционный acceptance требует точного соответствия выбранному множеству, но предложенная опора на текущие правила TestFilterHelper допускает дополнительные совпадения даже для обычных негeneric методов. Нужно явно различить предсказанное множество и фактическое множество, выбираемое фильтром.

## Evidence

- Строки 302–303 отсылают к правилам TestFilterHelper.
- Services/Testing/TestFilterHelper.cs:28–33 намеренно использует FullyQualifiedName~ даже для полностью разрешённого имени; причина — совместимость с параметризованными FQN и синтаксисом VSTest.
- Оператор contains не задаёт границу имени метода: фильтр для Ns.C.Check также совпадёт с Ns.C.CheckExtra.
- В строках 337–339 требуется прогон фильтра, «который выбирает ровно эти тесты». Эквивалентность из текущего helper не следует.

## Why it matters

Можно получить ложную приёмку на специально удачных именах или невыполнимое общее требование к roundtrip-тесту. Дополнительные запуски допустимы по R-01; проблема в несогласованном acceptance, а не в самом разрешении false positives.

## Failure scenario

Предсказан только Ns.C.Check. В той же сборке есть CheckExtra, не зависящий от изменённого production-члена. Составленный по существующим правилам фильтр выбирает оба теста; точное множество анализа и реально запущенные тесты различаются.

## Violated requirement / constraint

Точность integration roundtrip в строке 339 против правил повторно используемого helper. R-01 допускает более широкий запуск, поэтому это локальное противоречие проверки, а не blocker для архитектуры.

## Recommended change

Уточнить acceptance: либо отдельно учитывать разрешённое расширение множества фильтром и проверять отсутствие пропусков, либо определить более точное кодирование выбранных случаев для поддержанных адаптеров. В любом варианте добавить fixture с Check/CheckExtra, а не проверять только непересекающиеся имена.

## Notes for arbitration

Не предлагается безусловно заменить contains на equals: текущий helper объясняет, почему это ломает часть параметризованных случаев. Выбор зависит от того, требуется ли точный запуск или консервативный superset; для заявленного rapid TIA второй вариант выглядит совместимым с R-01.
