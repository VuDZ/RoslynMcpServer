# F-009 — Для run не определена актуальность сборки, а переиспользуемый путь пропускает rebuild

Severity: major

Category: integration

Confidence: high

## Target

docs/rapid-tia/README.md:425–492, 614–619, 667–670 — запуск набора через существующий runner, минимальные параметры и интеграционная проверка.

## Claim

Не определено, как run: true получает binaries, соответствующие изменениям, по которым выбран набор. Простое наследование поведения run_test_by_filter запускает существующую сборку без rebuild. При этом новый инструмент не предлагает параметра noBuild/buildPolicy и не задаёт обязательного pre-build или проверки свежести.

## Evidence

- Run запускает оценённый набор тем же runner, что run_test_by_filter (425–429, 667–668).
- Из параметров запуска названы таймаут и наследуемые configuration/platform; тонкая настройка вынесена в отдельный ручной вызов run_test_by_filter (490–492).
- В Tools/TestTools.cs:41–42 FilterTestOmitSkipsRebuild равен true. RunTestByFilter передаёт его в общий исполнитель (275–284).
- Services/Build/TestBuildRoute.cs:27–43 для обычного project route и отсутствующего noBuild выбирает именно этот historical default.
- Tools/TestTools.cs:550–557 передаёт route.NoBuild в DotNetTestArguments.BuildPlan. Services/Build/DotNetTestArguments.cs:109–115 при true не задаёт pre-test build и передаёт --no-build.
- Существующий тест BuildPlan_noBuild_true_skips_pre_test_build в RoslynMcpServer.Tests/TestRunner/DotNetTestArgumentsTests.cs закрепляет это поведение.
- DLL route имеет отдельную политику build proof; из плана не следует, что run автоматически использует этот route. Его требования к binariesPath нельзя молча перенести на обычный csproj.

## Why it matters

Можно правильно выбрать затронутый тест и получить зелёный результат на старом production-коде. Это не допустимая приблизительность TIA: ошибка находится в исполнении уже выбранного набора, а не в оценке зависимости.

## Failure scenario

Baseline-сборка содержит Value(), возвращающий 1, и проходящий тест на 1. После load тело Value меняется на 2. TIA правильно выбирает существующий тест. Реализация run переиспользует historical defaults RunTestByFilter: процесс получает --no-build, загружает старую DLL с Value() == 1 и сообщает passed. Отдельный build агент не вызывал: пользователь запросил оценить и запустить набор одним вызовом.

Альтернативная реализация делает pre-build; обе совместимы с текущим описанием. Существенный execution contract оставлен выбору implementer.

## Violated requirement / constraint

Неявный / отсутствует — требуется уточнение политики актуальности binaries для run: true. Цель инструмента — запуск тестов после обнаруженных правок (14–20); R-13 добавляет автоматический запуск за один вызов. R-01 не объявляет запуск старого кода разрешённым ограничением.

## Recommended change

Явно определить build policy до тестовых процессов: свежая сборка проекта/его зависимостей либо доказательство пригодности готовых outputs. Для нескольких MTP-процессов достаточно одного успешного pre-build перед --no-build запусками; при неуспехе тесты этого проекта не стартуют, другие проекты обрабатываются по общей политике. Если владелец сознательно выбирает обязательную внешнюю сборку, зафиксировать этот precondition и явный статус непроверенной свежести.

Добавить интеграционный случай: исходники изменены, старые binaries уже существуют; run обязан исполнить новый код либо явно отказаться от утверждения, что проверил его.

## Notes for arbitration

Finding не утверждает, что ещё не написанный run обязательно унаследует wrong default. Доказан существующий default и отсутствие выбора в specification. Новая публичная настройка или подсистема сборки не требуются: достаточно явного внутреннего контракта и переиспользования текущего механизма.
