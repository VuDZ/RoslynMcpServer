## API-проба F-005: extension из проекта-зависимости

Среда: PowerShell 7.6.5, установленные Microsoft.CodeAnalysis.Common и CSharp **5.9.0**, lib/net10.0, отдельный collectible AssemblyLoadContext. MSBuild и сетевое восстановление пакетов не использовались.

Построены отдельные компиляции с OutputKind.DynamicallyLinkedLibrary:

- Library объявляет в namespace Shared статический OldExtensions с Render(this object), возвращающим 1.
- App ссылается на Library и объявляет NewExtensions.Existing. Во втором варианте App добавляет Render(this string), возвращающий 2, в тот же статический класс NewExtensions.
- Tests в обоих вариантах ссылается на Library и App. Его Check вызывает Render на строковом литерале; CheckExisting вызывает NewExtensions.Existing.
- Компиляции соединены через CompilationReference, поэтому у каждого target symbol сохраняется реальный владелец. Все компиляции обеих конфигураций проверены через GetDiagnostics: **0 ошибок**.
- Через SemanticModel.GetOperation прочитана TargetMethod одного и того же синтаксиса invocation; проверены ожидаемые ContainingAssembly.

Получено:

    before: Library / M:Shared.OldExtensions.Render(System.Object)
    after: App / M:Shared.NewExtensions.Render(System.String)

Проба подтверждает смену target между исходными проектами. Она не запускает будущий TIA: его пропуск выведен из явно заданного scope пометки в README:218–220.

## API-проба F-006: зависимости не содержат собственный проект

Среда: те же PowerShell и Roslyn **5.9.0**, дополнительно Workspaces.Common.

Созданы ProjectId App и Tests. В изолированной пробе через внутренний двухаргументный конструктор ProjectDependencyGraph передан точный DAG с единственной ссылкой Tests → App. Для App список ссылок пуст. Проверено поведение публичного GetProjectsThatThisProjectTransitivelyDependsOn:

    Deps(App) contains App: False
    Deps(Tests) contains App: True

Проверки ожидаемых false/true прошли. Использование внутреннего конструктора — только способ задать тестовый граф без MSBuild/MEF; не предлагается как production-решение.

Это соответствует публичному [контракту API Roslyn](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.projectdependencygraph.getprojectsthatthisprojecttransitivelydependson?view=roslyn-dotnet-5.0.0): возвращаются зависимости проекта. Для правила README:336–338 отдельно нужен сам проект.
