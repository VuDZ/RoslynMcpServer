# Эпоха 4 — сохранение графа и актуализация

- Статус плана: **описание этапа, 2026-10-30; задачи заводятся при подготовке эпохи**.
- Статус исполнения: **planned, depends on [эпоха 3](../epoch-3-level1-production/README.md)
  и на слияние ветки `usage-statistics` с каталогом пользователя в `main`**.
- Канон: [программа rapid TIA](../README.md) — R-09, R-12, разделы «Сохранённый граф»,
  «Последовательность после загрузки», «Ответ на сохранённом графе до актуализации».

## Цель

Сохранять факты графа на диск, чтобы после загрузки большого solution сразу был
рабочий ответ, а актуализация шла в фоне по устаревшим документам, а не с нуля.

## Содержание

- Формат файла: версии формата, сервера и Roslyn; хеш связывания по проекту; по
  документу — хеш содержимого, факты, хеш поверхности объявлений, набор используемых
  имён. Атомарная запись, повреждённый файл отбрасывается.
- Каталог `tia/` в `ServerUserDirectories.StateDirectory` (R-12); строка `tia/` в
  [user-data-directory](../../user-data-directory/README.md); [PRIVACY.md](../../../PRIVACY.md) —
  сервер хранит локально факты о коде solution.
- Последовательность после загрузки: устаревшие документы, ответ сразу по сохранённым
  фактам с правилом устаревших документов, частичная актуализация, каскад по
  поверхности объявлений, `using`, операторам и атрибутам сборки на все транзитивно
  зависящие проекты.
- Политика полной перестройки — по решению O-06 из эпохи 2.
- Каталог случаев: несовпадение версий, повреждённый файл, устаревшие документы,
  каскад, изменение options проекта, удалённый документ, промежуточный проект без
  тестов.

## Ориентир нарезки

2–3 задачи: формат и атомарная запись; актуализация и каскад; каталог `tia/` и
PRIVACY. Точный состав — при подготовке эпохи.
