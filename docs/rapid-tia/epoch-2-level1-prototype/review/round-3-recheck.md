## E2-03 — CLOSED

В проверенном коммите «Годность пары прогонов», строки 254–262, требует полноты runtime cases **до** свёртки
в метод: сравниваются число терминальных исходов и мультимножество FQN; потери, лишние строки и дубликаты
дают `missing results`. Поэтому контрпример прошлого раунда «две baseline-строки, один passing-результат»
больше не проходит критерий годности. Сырые `TestCase.Id` между сборками сравнивать не требуется;
связь discovery → результат внутри прогона сохранена в строках 284–296.

Исключение из строгого подсчёта относится только к потерянным строкам **того же уже упавшего метода**.
Оно согласовано с единицей полноты (строки 277–282): метод входит в O, как только упала хотя бы одна его строка.
Отсутствие остальных строк этого метода не может убрать его из O или изменить факт его попадания в предсказание.
Исключение не разрешает терять результаты других методов и не отменяет запреты crash/timeout/cancel.
Поэтому оно не возвращает прежнее занижение O из-за потерянного passing-метода.

Строки 298–302 требуют перед замерами проверить оба граничных случая: одна оставшаяся прошедшая строка
делает пару негодной, одна упавшая сохраняет метод в O. Условия N/A для пустого O и достаточности выборки сохранены.

**Логическая самопроверка — 9/9.** Использована форма двух реальных строк
`xunit-v2 / ParameterTests.Rows` из [сохранённого discovery task-06](../../epoch-1-project-level/evidence/task-06-adapter-names/catalog.json).
Выполнены assert-проверки модели нового условия, без запуска адаптера:

- обе строки прошли — данные полны, O пусто;
- из двух осталась одна прошедшая — `missing results`;
- из двух осталась одна упавшая — метод входит в O;
- исчезли обе строки — `missing results`;
- у одного метода осталась упавшая строка, другой метод исчез — пара негодна;
- появилась лишняя упавшая строка — пара негодна: исключение разрешает только потерю остальных строк;
- один within-run identity записан дважды — пара негодна;
- сырые id между прогонами изменились, состав FQN и исходов полон — пара годна;
- мультимножество FQN изменилось без падения метода — пара негодна.

Это проверка логики спецификации, а не новой реализации валидатора. Специфическое поведение xUnit v2 при
исключении в `MemberData`, приведённое автором как пример, отдельным runtime-прогоном здесь не подтверждалось.
Его пример не нужен для доказательства допустимости исключения при метрике по методам.
Неполный набор строк уже упавшего метода также не выдаётся этим отчётом за полный case-level прогон.

## E2-05 — CLOSED

- ряд первого запроса содержит только первый запрос свежего процесса на каждый член;
