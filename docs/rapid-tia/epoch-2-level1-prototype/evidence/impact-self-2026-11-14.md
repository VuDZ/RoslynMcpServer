## Пустые ответы

Проверка — текстовый поиск по тестовому проекту: имя члена, имена его вызывающих и имя инструмента MCP. Прогоном
тестов не подтверждалась.

| Член | Причина пустого ответа |
|---|---|
| `ClassSkeletonWalker.SanitizeMethod` | тестов нет |
| `TestDiscoveryHelper.GenerateTestMethodStubAsync` | тестов нет |
| `AstModificationHelper.MutateAsync` | тестов нет |
| `InterfaceImplementationHelper.ClassAlreadyImplementsMember` | тестов нет |
| `InProcessAnalyzerAssemblyLoader.ResolveHandlerRegistered` (get) | тестов нет |
| `SolutionManager.RequestRefreshAllDocumentsForTests` | вызывается из `RoslynMcpServer.LifecycleTestHost`, который тесты запускают отдельным процессом, — известная слепая зона |
| `WorkspaceSnapshotCodec.ProjectKeyComparer.GetHashCode` | **вероятный пропуск** |

`ProjectKeyComparer.GetHashCode` реализует `IEqualityComparer<T>` из метаданных. Вызывает его `Dictionary` из BCL:
`ValidateSnapshot` создаёт словарь с этим comparer, а `ValidateSnapshot` вызывают `Encode` и `Decode`, которые
покрыты `WorkspaceSnapshotCodecTests`. Ссылки на `GetHashCode` в исходниках нет, поэтому обратный поиск до тестов
не доходит. Этого класса нет ни в правилах рёбер программы, ни в списке слепых зон: реализация члена интерфейса и
override члена из метаданных, который вызывает код вне solution (`IEqualityComparer`, `IComparer`, visitor,
`BackgroundService`). Правило по R-21: предшественники такого члена — места создания его типа.

## Границы

- Один production-проект и один тестовый; DI, интерфейсов и моков в тестах почти нет. На solution владельца с
  десятками проектов цифры не переносятся.
- Потеря точности на интерфейсах и моках и цена первого запроса на большом solution здесь не видны.
- Полнота не измерена: один вероятный пропуск найден чтением кода, а не эталоном.
