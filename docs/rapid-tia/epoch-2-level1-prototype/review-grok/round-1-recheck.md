## F-002 — частично

Абзац «Ключи проектов» делает то, о чём была находка: у члена записываются все ключи (путь, TFM, конфигурация, платформа), в чьих компиляциях лежит файл с телом; предсказание — объединение этих ключей; эталон берёт тесты уровня 0 всех этих ключей; у partial мутируется файл с телом.

Рядом остаются два более ранних предложения, которые этот абзац не отменяют:

- прогон эталона — тестовые проекты уровня 0 «для этого члена», для Roslyn «в пределах выбранного scope»;
- годная пара — «одна конфигурация, TFM, раннер и набор тестовых проектов».

Scope спайка на Roslyn — 2–4 тестовых проекта. Файл члена может входить в компиляции вне этого scope (второй TFM, linked-проект). По абзацу ключей их тесты входят в O и в объединение предсказания. По предложению про scope они в прогон не входят. Прямой граф при этом строится только от корней выбранного scope, так что тестов вне scope в F нет. Если побеждает scope, объединение «всех ключей» молча сужается. Если побеждают все ключи, в O попадают падения, которых нет в графе scope, и полнота снова занижается при правильных рёбрах. Единственное число «TFM» в условии пары читается и как «один TFM на прогон»: тогда `-f` отрезает остальные ключи, которые абзац велел объединить.

Нужна одна фраза: в предсказание и в O входят только ключи, чьи тестовые проекты уровня 0 лежат в выбранном scope. Ключ вне scope не участвует ни там, ни там. В годности пары — тот же набор TFM у контроля и мутации, а не один TFM на член.

## F-003 — закрыто

Источник данных — корень метода с атрибутом и наследников, которые наследуют метод вместе с атрибутом. Разворот на весь класс только для источника, который фреймворк запускает на класс, и только если такой атрибут есть в корпусе; случай записывается отдельно. Общие корни класса перечислены без источника данных. Лишний тест разбирается так же, как пропуск. Проверка до замеров требует найти член, вызываемый только из источника данных одного метода, и только у этого метода.

## F-006 — частично

Пустая страта больше не добирается чужими членами. Полнота solution без DI-разреза публикуется. Условие «хотя бы одна пара» относится к непустым стратам. Создание в фикстуре и generic-регистрация помечены отдельно и не выдаются за слепое DI. Это закрывает прежнюю петлю добора.

Правило членства сдвинулось относительно дыры. Страта требует, чтобы вызов члена через тип интерфейса или базы был **в production-коде**, и чтобы в тестовом scope не было прямого `new` этой реализации. Корпус офисного solution в том же плане — «DI и интерфейсы в тестах»: типичный вызов через интерфейс сидит в тесте (`Resolve<IFoo>()` / параметр фикстуры), а не в production. Такой член в страту не входит. Если других вызовов нет, страта пуста, разрез RTA/CHA по DI не снимается, хотя владелец как раз подтверждает, что DI в этом solution есть. Подтверждение владельца план просит для непустой страты и не говорит, что делать, когда владелец видит DI, а правило по production-коду даёт ноль.

Нужно считать вызов через интерфейс или базу и в тестах scope, и в production. Запрет прямого `new` конкретной реализации в тестовом scope оставить. Пометку фикстуры и generic-регистрации оставить отдельной, но не заменой страты, если вызов через интерфейс в тесте есть.

## F-008 — частично

Абстрактные члены, интерфейс без тела, `extern`, `const` и синтезированные члены из выборки исключены. Если такой член попал в список, исход `not mutable`, пара негодна, вместо него берётся другой член той же страты, счётчик есть в метриках эталона. Исходный сценарий «throw во все override абстрактного метода» закрыт.

Инициализатор поля при этом назван членом, «в который можно вставить throw по правилам эталона», и страта «статические» включает инициализатор статического поля. Правила эталона по-прежнему описывают только начало тела, accessor, конструктор после `base`/`this` и expression-bodied член, переписанный блоком. Для инициализатора поля блока нет. Два реализации разойдутся: `not mutable`, замена выражения на `throw …`, либо правка статического конструктора вместо поля. Страту можно набрать одними статическими методами, поэтому дыра узкая, но правило выбора и процедура мутации друг другу противоречат.

Нужна одна строка в эталоне: выражение инициализатора заменяется на `throw new InvalidOperationException("tia-probe")`. Либо инициализатор убирается из страты, пока этой строки нет.
