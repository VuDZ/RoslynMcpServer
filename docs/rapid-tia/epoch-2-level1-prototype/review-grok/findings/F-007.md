# F-007 — Четыре пути проверки указаны на фикстурах, в которых этих путей нет

Severity: minor

Category: documentation

Confidence: high

## Target

`task-01-forward-reverse-probe-hi.md`, «Проверка перед замерами»; `RoslynMcpServer.Tests/Workspace/WorkspaceInputMapTests.cs`, `GraphFixture`; `RoslynMcpServer.Tests/Workspace/WorkspaceInputWatcherDeliveryTests.cs`, `DeliveryFixture`.

## Claim

План утверждает, что в этом репозитории уже есть пути, на которых production-член вызывается только из конструктора `IClassFixture<T>`, из `InitializeAsync` фикстуры, из статического конструктора типа, к которому обращается тест, и из инициализатора поля экземпляра, и указывает `GraphFixture` и `DeliveryFixture`. В этих типах такого набора исключительных вызовов нет.

## Evidence

- `WorkspaceInputMapTests` реализует `IClassFixture<GraphFixture>`. Конструктор `GraphFixture` собирает временные файлы и вызывает `WorkspaceInputMapBuilder.Build`. Тот же `Build` вызывается из тестовых методов этого файла (и из других тестовых классов workspace), то есть не «только из конструктора фикстуры».
- `DeliveryFixture` реализует `IAsyncLifetime`, и `InitializeAsync` вызывает `SolutionManager.LoadAsync`. Тесты класса работают с тем же `Manager` и сессией. Это пример фикстуры, а не член, достижимый только из `InitializeAsync`.
- В обоих типах нет статического конструктора и нет инициализатора поля, из которого вызывается production-член. Инициализаторы там — пустые строки, `null!` и `Array.Empty`.
- Сама проверка при этом задана на «маленьком solution прототипа», а не на этих классах. Ссылка нужна как существующий образец путей.

## Why it matters

Проверка до замеров — единственный заранее названный способ поймать потерю фикстурных и инициализационных корней. Образец, в котором член ещё и вызывается из тестов, не отличает «корень фикстуры работает» от «член достижим прямым вызовом из теста». Статический конструктор и инициализатор поля по этой ссылке нельзя даже скопировать: их там нет. Реализатор либо ослабит проверку до «в репозитории есть IClassFixture», либо потратит время на поиск, которого текст не требует.

## Failure scenario

В маленькое solution копируют `GraphFixture` и считают проверку выполненной, потому что оба направления находят `WorkspaceInputMapBuilder.Build`. Находят они его из тестовых методов, где `Build` тоже вызывается. Ребро из конструктора фикстуры можно удалить, и проверка останется зелёной. Ошибка всплывает уже на офисном solution как «RTA не видит объект из фикстуры», без локального теста.

## Violated requirement / constraint

Неявный / отсутствует — требуется уточнение.

Проверка в плане normative: оба направления должны находить член, вызываемый только из каждого из четырёх мест. Ссылка на репозиторий этому условию не соответствует. Сами четыре места остаются нужными.

## Recommended change

Убрать утверждение, что все четыре исключительных пути уже есть в `GraphFixture` и `DeliveryFixture`. Оставить эти типы как примеры `IClassFixture<T>` и `IAsyncLifetime`, если пример фикстуры ещё нужен. Четыре члена «вызывается только отсюда» собрать в маленьком solution прототипа и проверить, что из тестового метода прямого вызова нет.

## Alternatives

Нет.
