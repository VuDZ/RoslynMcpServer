# F-002 — Один throw в файле и узлы «проект + TFM» попадают в разные совокупности

Severity: major

Category: correctness

Confidence: high

## Target

`task-01-forward-reverse-probe-hi.md`, разделы «Эталон: сломать член и прогнать», «Единица сравнения», «Прямой граф»; канон `docs/rapid-tia/README.md`, «Уровень 1», идентификатор узла и уровень 0 для C#-документа.

## Claim

Канон идентифицирует узел парой «проект + документационный id». Проектный ключ включает путь, конфигурацию, платформу и TFM, потому что один файл Roslyn входит в несколько проектов при multi-targeting и linked files. Эталон вставляет один `throw` в исходный текст и собирает все тестовые проекты, которые уровень 0 выбирает для члена. План не говорит, F и O какого проектного ключа сравниваются. На корпусе Roslyn это даёт систематически заниженную полноту при правильном графе либо молчаливое объединение узлов, которого канон не делает.

## Evidence

- Канон: узел — «проект + `ISymbol.GetDocumentationCommentId()`»; id сам по себе неуникален; факты документа хранятся отдельно для каждого проекта, в который он входит. Ключ проекта включает target framework (`SnapshotProjectKey`).
- Уровень 0 для C#-документа — все проекты, в которые документ входит, плюс транзитивно зависимые тестовые проекты.
- План: мутация — правка тела в исходнике; прогон — тестовые проекты уровня 0 для этого члена, на Roslyn внутри выбранного scope. O — упавшие единицы этого прогона. Единица теста уже несёт проект/TFM, единица измеряемого production-члена — нет.
- R-20 называет Roslyn обязательным корпусом спайка. Канон приводит multi-targeting Roslyn как причину проектного ключа, а не как редкий край.

## Why it matters

Полнота — главная цифра спайка. Если член выборки — один узел (например net10.0), а `throw` в общем файле роняет тесты и net10.0, и второго TFM, чужие падения входят в O и не входят в F. Recall падает примерно до доли одного TFM при безошибочном графе. Если реализатор молча объединяет все узлы одного исходного объявления, он измеряет не тот граф, который канон будет хранить, и расхождения F-CHA ↔ R-CHA зависят от того, кто как склеил ключи.

Та же развилка на linked file: тестовый проект компилирует файл сам и не ссылается на библиотеку. У библиотеки и у тестового проекта разные узлы. Уровень 0 по пути файла запускает оба. O шире любого одного узла.

## Failure scenario

Scope — два TFM одного тестового проекта Roslyn, оба зависят от общего исходника. В выборке узел net10.0 метода `M`. Оба направления правильно находят только тесты net10.0. Прогон после `throw` роняет те же тесты и на втором TFM. В отчёте полнота около половины, пропуски не попадают ни в слепую зону, ни в дефект рёбер. Вывод «статика не окупается» делается на артефакте протокола.

Вторая реализация объединяет TFM в одну метку члена, получает полноту около 100% и несовместимый отчёт.

## Violated requirement / constraint

Канон, хранение фактов: ребро и достижимость считаются по проектному ключу, а не по пути файла. R-20: эталон и предсказание сравниваются на Roslyn. План требует одну единицу сравнения и не задаёт её для члена, который в этой единице существует в нескольких экземплярах.

## Recommended change

В выборе члена записать проектный ключ (путь проекта, TFM, конфигурация, платформа) вместе с документационным id. O для этого члена — только упавшие единицы тестов, которые уровень 0 относит к этому ключу. Если нужно измерить все TFM общего файла, это несколько членов выборки либо заранее описанное объединение узлов; оба варианта записать в отчёт одним способом. Частичные объявления в нескольких файлах мутировать в файле с телом и включать в O все ключи, в чьи проекты этот файл входит, только если предсказание — объединение тех же ключей.

## Alternatives

Гонять и строить граф ровно на одном TFM всего solution. Это честный протокол, но его надо назвать ограничением корпуса Roslyn, а не оставлять реализатору.

## Notes for arbitration

На однотаргетном офисном solution без linked files дефект не проявляется. Это не отменяет его для Roslyn, которого R-20 требует. Проверять, сколько TFM у выбранных тестовых проектов, спайку не нужно: расхождение совокупностей уже следует из канона и текста плана.
