## Изменение scope по R-21 (2026-11-14)

Способ уровня 1 — обратный поиск от изменённого члена при вызове инструмента. Разделы «Цель», «Содержание» и
«Ориентир нарезки» ниже написаны под прямой граф и действуют только в том, что этому не противоречит.

Снято:

- прототип фактов по документам, RTA и битсетов; замеры извлечения фактов и сохранённого графа;
- стенд полноты на истории коммитов и эталон `throw` с пересборкой на каждый член;
- кампания замеров [task-01](task-01-forward-reverse-probe-hi.md): прямой граф, рамки А и Б, сравнение F ↔ R;
- вопрос O-06.

Остаётся прототип `spikes/AffectedTestsProbe` с командой `impact` и проверкой правил рёбер (`precheck`).

Шаги, по порядку. Файлы задач заводятся при подготовке шага; до цифр шага 1 планы на ревью не отправляются.

1. **`impact` на офисном solution** — время запроса, память, размер ответа против уровня 0, доля срабатываний
   лимитов. Сборка и git не нужны. Статус: **не сделан**.
2. **Два слоя ответа в прототипе**: тесты, достигнутые напрямую, и тесты, достигнутые только через переход
   «реализация → член интерфейса или базового класса». Показывает, сколько ответа дают интерфейсы и моки.
   Статус: planned.
3. **Эталон полноты по покрытию**: прогон нескольких тестовых классов с coverlet, пары «исполненный член —
   тестовый класс» сравниваются с ответом обратного поиска. Нужен solution, который собирается. Статус: planned.
4. **Правила поиска**: предшественники реализации или override члена из метаданных — места создания типа;
   поиск только по проектам, от которых зависят тестовые. Статус: planned.

Критерий перехода к эпохе 3 — в R-21.

Первый прогон — [на solution этого репозитория](evidence/impact-self-2026-11-14.md), 2026-11-14: 40 членов, медиана
119 мс и 2,6 % уровня 0, пик памяти около 450 МБ, один вероятный пропуск (реализация интерфейса из метаданных).
Это лёгкий случай без DI; на офисный solution цифры не переносятся.

## Цель

Проверить до production, окупается ли граф вызовов от тестов (уровень 1), и снять
числа, от которых зависят открытые решения программы. Код прототипа живёт в
`spikes/`, а не в production.

## Содержание

- Прототип уровня 1: факты по документам, корни тестового класса, ребра, RTA по
  тестовому классу с откатом на CHA, битсеты достижимости.
- Стенд полноты по процедуре программы: загрузить родительский коммит, применить
  правку как изменения сессии, `throw` в изменённые и добавленные члены, сравнить
  предсказание с упавшими тестами. Метрики: полнота, доля suite, которую не пришлось
  запускать, доля ответов с расширением R-14; сравнение CHA и RTA.
- Замеры на большом solution: полное извлечение фактов, извлечение по одному
  документу, вывод достижимости, размер и время чтения сохранённого графа, память и
  влияние на первый поиск.
- Отчёт с решениями по открытым вопросам: O-03 (порог охвата), O-06 (политика полной
  перестройки), O-07 (source generators), O-08 (корпус стенда) и необходимость VTA.
