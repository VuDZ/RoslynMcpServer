# F-011 — Каталог tia/ на Linux не совпадает с двумя корнями каталога пользователя

Severity: minor

Category: integration

Confidence: high

## Target

R-12 в `docs/rapid-tia/README.md`. Зависимость эпохи 4 от `docs/user-data-directory/README.md`.

## Claim

R-12 кладёт сохранённый граф на Linux в `$XDG_STATE_HOME/roslyn-mcp/tia/`. Спецификация каталога пользователя, от которой зависит эпоха 4, делит Linux на два корня и относит к state только логи. Пункт `tia/` висит в общем списке содержимого одного каталога, без корня.

## Evidence

- R-12: Windows `%LOCALAPPDATA%\RoslynMcpServer\tia\`, Linux `$XDG_STATE_HOME/roslyn-mcp/tia/` (по умолчанию `~/.local/state/roslyn-mcp/tia/`), macOS `~/Library/Application Support/RoslynMcpServer/tia/`. Эпоха 4 зависит от каталога пользователя.
- `docs/user-data-directory/README.md`, таблица каталогов: на Linux конфиг и plugins — `$XDG_CONFIG_HOME/roslyn-mcp/`, логи — `$XDG_STATE_HOME/roslyn-mcp/`. Список содержимого одним перечнем: `RoslynMcp.jsonc`, `plugins/`, `logs/`, `usage/`, `tia/`. Для `usage/` и `tia/` корень на Linux не назван.
- Код каталога пользователя ещё не начат (статус того README). Общего помощника пути, который уже реализует R-12, нет.

Windows и macOS в обоих текстах совпадают: один корень.

## Why it matters

Эпоха 4 не должна заводить второй, свой, смысл «каталога пользователя». Если помощник из user-data-directory вернёт на Linux config-home, графы окажутся в `~/.config`, вопреки уже принятому R-12. Если TIA заведёт отдельный путь, два спецификации разойдутся в PRIVACY и в переменной переопределения корня (O-04 того документа).

## Failure scenario

Реализация каталога пользователя даёт один метод «корневой каталог» и на Linux возвращает `$XDG_CONFIG_HOME/roslyn-mcp`, потому что так записаны конфиг и plugins, а state упомянут только для логов. Эпоха 4 пишет `tia/` через этот метод. R-12 нарушен, файл графа лежит рядом с конфигом. Переменная вроде `ROSLYN_MCP_HOME` из O-04 user-data-directory переносит конфиг и не переносит state, либо переносит оба, и граф снова оказывается не там, где его ищет сервер после обновления.

## Violated requirement / constraint

R-12. Эпоха 4 объявляет зависимость от каталога пользователя, но тот документ путь из R-12 не содержит.

## Recommended change

В спецификации каталога пользователя явно положить `tia/` (и заодно `usage/`, если он в том же положении) в state-корень на Linux и в единственный корень на Windows и macOS. В rapid-tia оставить R-12 как решение и не вводить свой helper пути. До этой строки эпоху 4 не считать разблокированной одной лишь фразой «зависит от user-data-directory».

## Notes for arbitration

Это правка соседней спецификации, не развитие алгоритма TIA. Пока user-data-directory тоже ещё план, достаточно одной согласованной строки в обоих README.
