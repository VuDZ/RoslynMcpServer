# F-004 — Синтаксический ключ члена не связан с идентификатором узла графа

Severity: major

Category: correctness

Confidence: high

## Target

`docs/rapid-tia/README.md`: снимок «путь → checksum» и ключ члена; «Узлы идентифицируются `ISymbol.GetDocumentationCommentId()`»; снимок хешей считается синтаксически, без компиляции.

## Claim

Обнаружение изменений и граф используют разные идентификаторы, и переход между ними не задан. Ключ изменений — синтаксический (тип, имя, синтаксис параметров) и считается без semantic model. Узел графа — documentation comment id, для которого нужны метаданные-имена типов. Пока снимок не хранит doc id, изменение тела нельзя наложить на битсет. Отдельный пробел того же стыка: у `partial`-члена несколько объявлений на один символ, а способ свести их хеши не записан.

## Evidence

- Снимок: для каждого члена ключ (тип, имя, синтаксис параметров) и хеш синтаксиса. Снимок хешей «только синтаксис, без компиляции» и идёт первым в той же фоновой задаче.
- Факты и достижимость идентифицируют узлы через `ISymbol.GetDocumentationCommentId()`.
- Documentation comment id нормализует типы к метаданным (`System.Int32`, а не `int` или alias), иначе узел не совпадёт. Без semantic model восстановить эту строку из синтаксиса параметров нельзя. Деградация «файл не разбирается до членов → все узлы файла» срабатывает только когда разбора нет, а не когда синтаксический ключ не находится среди doc id.
- Каталог требует точное множество для правки тела, сигнатуры, переименования и `partial`.
- Сигнатура в doc id входит в идентификатор (`M:…Method(System.Int32)` против новой арности). Смена сигнатуры выглядит как удаление старого узла и появление нового только если у старого синтаксического ключа был записан прежний doc id.

`partial`: один символ, несколько синтаксических объявлений в разных файлах. Если ключ один на словарь, второе объявление затирает хеш первого, и правка затёртой части не видна.

## Why it matters

Эпоха 1 строит синтаксическое обнаружение, эпохи 2–3 связывают его с графом. Без общего ключа каталог «точное множество тестов» нельзя ни реализовать однозначно, ни проверить: тело изменилось синтаксически, а битсет индексирован другим идентификатором.

## Failure scenario

В baseline метод `void M(int x)`. Снимок хранит синтаксический ключ и хеш тела, без doc id. Агент меняет тело; код по-прежнему разбирается, поэтому файл не деградирует до всех узлов. Реализация ищет узел `M:Ns.C.M(System.Int32)` и не находит его по ключу `M(int x)`. Битсеты тестов, вызывающих `M`, не срабатывают.

Вариант с `partial`: объявление в одном файле, тело в другом. В снимке остаётся хеш объявления. Правка тела не меняет сохранённый хеш. Тесты не выбираются.

## Violated requirement / constraint

Неявный / отсутствует — требуется уточнение. Дизайн одновременно требует синтаксическое сравнение без semantic model и выбор тестов по семантическим идентификаторам узлов. Это разные пространства ключей. Каталог случаев считает их уже сопоставленными.

## Recommended change

Пока факты не извлечены, ответ остаётся проектным. Когда semantic model члена уже есть, записать doc id в запись снимка рядом с синтаксическим ключом. Дальнейшие правки сравнивают хеш синтаксиса и возвращают сохранённые doc id изменённых и исчезнувших записей. Не вычислять doc id из исходного текста заново.

Для `partial` хранить все объявления одного doc id и считать член изменённым, если изменилось любое. До появления doc id не схлопывать объявления словарём синтаксического ключа.

«Тип» в синтаксическом ключе задать так же, как он будет сопоставляться с doc id: вложенность, generic-арность, explicit interface implementation.

## Notes for arbitration

Проверить, не считается ли допустимой деградация всего файла при любой неудаче сопоставления ключа. Это снимает ложный пропуск, но должно быть написано в правиле деградации: сейчас она только про неразобранный файл.
