# F-002 — Правила изменений связывания не покрывают перепривязку неизменённого кода

Severity: major

Category: correctness

Confidence: high

## Target

`docs/rapid-tia/README.md`, раздел «Изменения связывания»; каскад актуализации по «набору используемых имён» и «хешу поверхности объявлений»; R-05.

## Claim

Раздел обещает отдельно обработать правки, которые меняют поведение неизменённого кода. Перечисленные правила не покрывают обычную перепривязку: директивы `using` / `using static` / alias / global using, новый extension-метод в другом статическом классе, новый оператор или implicit-преобразование. Каскад сохранённого графа ищет затронутые документы по именам и поверхности объявлений и эти правки тоже не видит.

## Evidence

- Правило новой перегрузки и extension-метода помечает одноимённые члены «типа и его иерархии». Для extension-метода объявляющий тип — статический класс, в котором метод только что появился. Его иерархия не содержит уже существующий метод, к которому привязаны неизменённые вызовы. Какой тип имеется в виду, предложение не определяет.
- Смена `using` не меняет синтаксис членов. Ключ члена — тип, имя, синтаксис параметров, хеш синтаксиса члена. Директива снаружи члена в этот хеш не входит.
- Ребра уровня 1 включают операторы и неявные преобразования, но раздел связывания не помечает неизменённые места использования при появлении нового оператора или conversion. В выражении `a + b` нет имени `op_Addition`, поэтому и компактный набор имён документа его не содержит.
- Поверхность объявлений для каскада — сигнатуры, иерархия, атрибуты. Набор `using` в неё не входит. Полная перестройка, которая должна снимать накопленную ошибку, — открытый O-06.
- R-04 фиксирует граф на baseline: ребро ведёт туда, куда вызов был привязан до правки. После перепривязки тест обязан найтись через помеченный старый член. Если старый член не помечен, битсет ничего не даёт.

Оговорка зависимости: если любой C#-файл с изменившейся контрольной суммой всё равно расширяется до тестовых проектов (см. F-001), ложного пропуска нет, есть расширение до проекта. Текущий текст этого расширения не задаёт, а правила связывания написаны как точечная замена такому расширению.

## Why it matters

Новый extension и правка global usings — обычные изменения агента. Инструмент как раз обещает не терять тесты на перепривязке, не перестраивая граф. Пропуск здесь бьёт по основной метрике эпохи 2 (полнота), а не по редкому краевому случаю.

## Failure scenario

Вызовы `foo.ToJson()` привязаны к `JsonExt.ToJson(this object)`. Агент добавляет `Better.ToJson(this Foo)` — более специфичный extension. Тексты вызывающих методов те же, baseline-рёбра по-прежнему ведут в `JsonExt.ToJson`. Новый метод в baseline ни из одного теста не достижим. Правило помечает одноимённые члены `Better`, а не `JsonExt`. Ни один прежний тест в ответ не попадает, хотя все они теперь выполняют другой метод.

Тот же пропуск: в файле глобальных using `using Old;` заменено на `using New;`, и `Save()` перепривязывается. Хеши членов не меняются.

Новый `implicit operator` меняет применимость перегрузки в неизменённых файлах. Имени оператора в этих файлах нет, каскад сохранённого графа их не переизвлекает.

## Violated requirement / constraint

Раздел «Изменения связывания»: такие правки «меняют поведение неизменённого кода и обрабатываются отдельно». R-01 разрешает пропуски, но не отменяет уже записанное правило. Каталог случаев прямо включает новую перегрузку, extension-метод и override при неизменном вызывающем коде.

## Recommended change

Для каждой правки, способной изменить привязку неизменённого кода, записать узел, который уже есть в baseline-битсетах:

- новая перегрузка или extension — все уже достижимые члены с тем же именем во всей компиляции, не только в иерархии объявляющего типа; имя extension брать и по типу первого аргумента;
- изменение набора `using` / alias / global using — все члены затронутых документов, а при global using — документы, чья привязка зависит от этого файла (на первом шаге допустимо расширение до проектов, если оно явно входит в ответ);
- новый оператор или conversion — проектное расширение либо члены, чьи вызовы вообще способны использовать оператор; не полагаться на набор идентификаторов.

Отдельно записать, что виртуальный вызов кладёт в битсет объявленную цель, а не только RTA-реализации. Иначе правило «новый override помечает базовый член» не попадает ни в один битсет, если в битсете лежат только реализации.

Каскад по именам не считать каналом для `using` и операторов. До закрытия O-06 эти правки обрабатывать проектным расширением.

## Alternatives

Проектное расширение на любой файл, у которого изменилась контрольная сумма или поверхность `using`, проще точечных правил и честно грубее. Точечные правила имеют смысл только если они действительно помечают старый член.

## Notes for arbitration

Если владелец сознательно оставляет эти пропуски внутри R-01, это нужно написать вместо раздела, который обещает отдельную обработку. Иначе эпоха 2 будет сравнивать CHA и RTA на полноте, которую правила связывания не обеспечивают.
