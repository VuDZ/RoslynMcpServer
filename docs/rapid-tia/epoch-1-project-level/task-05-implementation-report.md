## Реализация

`TestImpactComposer.Compose` принимает `Solution`, результат mapper, текущие снимки
документов с изменениями task-02, тесты второй части и множество простых имён базовых
типов. Инвентарь текущих тестовых документов включает неизменённые partial-части: корень
в одном файле выбирает тесты того же класса из другого. `Changes=null` означает
неизвестный baseline; `Current=null` — отсутствие текущего документа.

Сначала входят текущие новые/изменённые тесты, включая promoted/renamed и тесты с
запретом сужения. Собственный корень выбирает текущие тесты своего класса. Затем
добавляется вход второй части; одинаковые `(ProjectId, BaselineMemberKey)` объединяют
причины. Тесты остаются в результате и при проектном расширении.

`ProjectImpactResult.Paths` сохраняет владельцев каждого изменённого пути. Только
собственные изменения, все факты которых разрешают сужение task-02/R-17, исключаются
из семян расширения. Простой класс из входного множества базовых имён запрещает
сужение независимо от квалификации/generic-арности исходного base-list. Неизвестный
baseline, удалённый документ, обычный/helper/fixture-член, file/project fallback и
прочие входы сохраняют расширение. Оно вызывает единственное существующее определение
`ProjectImpactMapper.ExpandProjects`; расширение от другого изменённого проекта или
от другого входного пути того же проекта не подавляется тестовым изменением.

`AffectedTest` хранит текущий синтаксический ключ и причины. Формат имён адаптера, фильтры
и план запуска остаются последующим задачам. `TestImpactResult` возвращает также причины
проектных включений, `NotCoveredPaths`, stale и reload.

## Передача task-04

Mapper принимает оба актуальных флага существующего watcher. Только
`ProjectGraphStaleFromGraphFile` расширяет ответ до всех тестовых проектов и сохраняется
в результате для composer. Агрегированный stale управляет советом reload.

Неизвестный `.cs` по-прежнему относится к ближайшему проекту. Отсутствие документа в
карте после reload не доказывает новый compile item: файл мог быть удалён либо исключён
через `Compile Remove`. Поэтому совет reload берётся из текущего watcher-состояния, а
не из самого отсутствия `.cs` в карте. Владение удалённого `.cs` не теряется.

Неизвестный не-C# путь и путь каталога остаются uncovered, даже если устарел только
состав проекта. Настоящий watcher поднимает reload, но не добавляет независимые тестовые
проекты. Каталог, перенесённый внутрь проекта/из него либо удалённый и восстановленный,
не исчезает из ответа.

`SolutionManager`, watcher, load/prepare/publication и baseline lifecycle не менялись.
