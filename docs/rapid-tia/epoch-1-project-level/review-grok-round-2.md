## F-001 — Исключение затирает расширение из другого проекта

Severity: major

Target: программа, «Без графа»; [task-05](task-05-response-composition-med.md).

Исключение написано как весь ответ по тестовому проекту: если в нём менялись только тестовые методы и собственные корни, «ответ состоит из этих тестов» и «ответ по этому проекту сужается до этих тестов». Расширение, пришедшее из другого проекта, в этой фразе места не имеет. Обычный совместный случай — правка метода библиотеки и одного теста — тогда запускает только этот тест. Остальные тесты проекта, которые вызывают библиотечный метод, из ответа выпадают. Это как раз пропуск, из-за которого инструмент заводят.

Исключение должно гасить проектное расширение только от изменений внутри этого тестового проекта. Расширение другого проекта по-прежнему включает его целиком. Ответ проекта — объединение, как в начале раздела «Состав ответа».

## F-002 — Проверка partial стоит не на том хранении

Severity: minor

Target: [task-02](task-02-change-detection-med.md), проверки; [task-03](task-03-baseline-lifecycle-hi.md).

Task-02 сравнивает снимок одного документа. Проверка требует, чтобы правка `partial` в двух документах не терялась из-за того же ключа в другом документе. Функция одного документа чужой ключ не видит. Правило хранения по документу без схлопывания записано в task-03, а проверки там нет. В списке task-02 после новой фразы осталось «с правкой каждого» — хвост старого предложения.

Проверку перенести в task-03. Из task-02 оставить правку объявления внутри одного документа. Хвост «с правкой каждого» убрать.
