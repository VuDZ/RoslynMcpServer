## R3-001 — перестановка членов не видна в снимке (MUST-FIX)

`Services/Testing/Baseline/BaselineDocumentSnapshotBuilder.cs`: `DeclarationSurface`
хеширует заголовок типа без членов (`WithMembers(default)`), а хеш члена — только его
собственный синтаксис и путь namespace-блоков. Порядок членов внутри типа не входит ни в
один хеш.

Read-only probe рецензента (исходники builder и моделей в отдельном file-based приложении,
Microsoft.CodeAnalysis.CSharp 5.9.0): во всех строках ниже меняется только
`TextChecksum`; ключи, хеши членов, хеши вне членов и `HasUnparseableContent` совпадают.

| До → после | Смысл меняется | Снимок различает |
|---|---|---|
| `enum E { A, B }` → `enum E { B, A }` | да — значения членов | нет |
| `class C { static int A = 1; static int B = A + 1; }` → поля переставлены | да — `B` становится `1` | нет |
| `struct S { int a; long b; }` → поля переставлены | да — layout | нет |
| `class C { void M(){} void N(){} }` → методы переставлены | нет | нет (верно) |

Task-02 по контракту выводит «изменений нет» из равенства хешей, поэтому такая правка в
нетестовом проекте не даст проектного расширения, и затронутые тесты пропадут молча.
Программа считает «не изменением» только правку комментариев и пробелов; перестановка
к ним не относится. Это и есть риск из шапки task-01: «неверный ключ или хеш члена молча
теряет изменения».

Требуется: учесть порядок членов, для которых он значим, — как минимум члены enum и
поля (включая event-поля и инициализаторы) — в хеше заголовка типа или в хеше члена.
Перестановку только методов, свойств без инициализаторов и вложенных типов допустимо
не различать. Регрессии — по таблице выше, сначала красные; строка с методами — guard.

## R3-003 — `DirectivesHash` вне контракта task-02 (не блокирует task-01)

Снимок отдаёт `DirectivesHash`, которого нет в списке видов изменений task-02. Он может
измениться один — например, в файле только с `#if false … #endif` вокруг объявлений.
Task-02 должна явно отобразить его, вероятно в «весь файл», и проверить этот случай.
Передаётся исполнителю task-02; правки task-01 не требует.
