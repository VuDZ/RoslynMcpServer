## T06-C1 — NUnit-фикстура с аргументами

Проба не измеряла фикстуры с аргументами конструктора, и T06-L01 их не называет. Рецензент добавил во временную копию
NUnit-проекта два класса и снял FQN из VSTest discovery:

| Фикстура | Фактический `FullyQualifiedName` | Фильтр по норме программы | Выбрано |
|---|---|---|---|
| `[TestFixture("a")]`, `[TestFixture("b")]` | `Ns.ArgFixture("a").M`, `Ns.ArgFixture("b").M` | `Ns.ArgFixture.M` | **0** |
| то же | | свёртка `Ns.ArgFixture.` | **0** |
| `[TestFixtureSource(nameof(Sources))]` | `Ns.SourceFixture(1).S` | свёртка `Ns.SourceFixture.` | **0** |
| то же, что первая строка | | `Ns.ArgFixture` без точки | 2/2 |

По норме, записанной до этой проверки, изменённый тест такой фикстуры получил бы фильтр, который ничего не выбирает, —
молчаливая потеря тестов (R-18). В пробе дефекта нет, поэтому новый раунд не открывается: task-07 не начата, условие
передано туда.

Условие для task-07: для NUnit-класса, у которого `[TestFixture]` несёт аргументы конструктора, или есть
`[TestFixtureSource]`, не строить `Class.Method` и свёртку `Class.`. Допустимо имя класса без точки
(`FullyQualifiedName~Ns.Class`, надмножество: заденет и классы с тем же префиксом) или проект целиком с причиной.
Измеренная форма `[TestFixture(typeof(int))]` на generic-классе остаётся по таблице task-06; generic-фикстура с
аргументами конструктора не измерялась и тоже идёт по условию.
