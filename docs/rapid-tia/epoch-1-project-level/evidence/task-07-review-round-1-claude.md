## Имена, которых нет в каталоге task-06

Временная копия фикстур `spikes/AdapterTestNames`, Linux, FQN из VSTest discovery, счётчики по TRX. Фильтр построен
так же, как его строит планировщик: `FullyQualifiedName~<класс>.<имя метода>`.

| Случай | Фактический `FullyQualifiedName` | Фильтр | Выбрано |
|---|---|---|---|
| NUnit `[TestCase(1, TestName = "Custom")]`, `[TestCase(2)]` | `Ns.NamedCases.Custom`, `Ns.NamedCases.Rows(2)` | `~Ns.NamedCases.Rows` | 2/2, включая `Custom` |
| NUnit generic-метод `Generic<T>()` | `Ns.NamedCases.Generic<T>` | `~Ns.NamedCases.Generic` | 1/1 |
| MSTest `[TestMethod("Shown")]` | `Ns.NamedCases.Plain` | `~Ns.NamedCases.Plain` | 1/1 |
| MSTest `[DataRow(1, DisplayName = "Row one")]` | `Ns.NamedCases.Rows` | `~Ns.NamedCases.Rows` | 1/1 |
| xUnit v3 `[Fact(DisplayName = "Shown")]` | `Ns.NamedCases.Plain` | `~Ns.NamedCases.Plain` | 1/1 |
| xUnit v3 `[Theory(DisplayName = "Rows shown")]` | `Ns.NamedCases.Rows` | `~Ns.NamedCases.Rows` | 1/1 |

Пользовательские имена и `DisplayName`, а также generic-методы фильтр метода не ломают. NUnit с `TestName` меняет FQN, но
адаптер всё равно выбирает строку по имени метода. Это сужает T07-L02 для этих версий адаптеров; другие версии не
измерялись.

## T07-C1 — вход планировщика строит task-08

Планировщик не переводит имена: имя класса во время выполнения, полнота инвентаря класса и признак аргументов фикстуры
приходят от вызывающего кода (`VstestTestClass`). Replay-тесты task-07 берут имя класса из измеренного фильтра каталога,
то есть проверяют склейку и экранирование, а не перевод. Правила task-06 и T06-C1 в коде пока не реализованы.

Спецификация task-08 этого не требовала; ограничение T07-L01 назвало границу, но не передало её. Если вызывающий код
построит имена по исходнику (`Outer.Inner`, `GenericTests<T>`, класс-база), планировщик даст фильтры, которые выбирают
0 тестов, — молчаливая потеря по R-18. Условие записано в
[task-08](../task-08-estimate-tool-hi.md#передача-из-task-07-обязательные-условия).
