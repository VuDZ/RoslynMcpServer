# task-03 — ревью приёмки, раунд 22, второй рецензент

- Дата: 2026-11-05.
- Рецензент: Claude Opus 5.5 (`claude-opus-5-5`), надзор приёмки по поручению владельца.
- Версия: `063f1c7`, та же, что в [ACCEPT Codex раунда 22](task-03-review-round-22.md); по
  [стандарту](../../../README.md#как-считать-и-писать-отчёты) это один раунд. Сравнение с `1622e41` (тот же production-код,
  что `e116df1`) и `1b617c4`.
- Scope: исправление R21-001, сохранность R14-001, R11-001 и R9-001, полная main suite на Linux.
- Вердикт: **ACCEPT**. R21-001 закрыт на Linux, новых MUST-FIX нет. Замечания ниже записаны как границы и задачу не
  возвращают: это решение владельца, [R-18](../../README.md#решения-владельца-2026-10-29).

## Что подтверждено

- Release-сборка solution: 0 ошибок, 3 предупреждения. Три полных main suite на Linux (KVM, 2 ядра, .NET SDK 10.0.114,
  Release, `Category!=AnalyzerLifecycle&Category!=RequiresPinnedSdk&Category!=RequiresWindows`) на чистом дереве
  `063f1c7`: **1792/1792** каждый, без падений и пропусков, счётчики сверены по TRX. Windows и AnalyzerLifecycle рецензент
  не повторял, здесь результат берётся из [validation раунда 22](task-03-final-validation-round-22.md).
- Код: `HasMappedDescendants` и прежний обход дают один ответ для путей карты, включая корень; набор внешних каталогов
  вычисляет прежнее условие. Обход карты остался только для каталога, под которым есть входы.
- Новые тесты на этой машине: на `1622e41` падают все 7 детерминированных при всех 3 запусках и настоящий
  `node_modules` при 200 исходниках в 3 запусках из 3, при 50 исходниках в 1 из 3. На `063f1c7` 13/13 при 3 запусках,
  а настоящие сценарии проходят 5 запусков из 5 при двух процессах, занимающих оба ядра.
- Прежние проверки R14, R11 и R9 на настоящем watcher дают те же результаты, что на `e116df1`. Отличие одно: перенос
  сразу после `mkdir` (S3) в этом запуске поднял флаг. Это та же гонка, что в T3, вход в журнале есть в обоих исходах.
  Ограничение раунда 21 про каталог с не-C# входом вне проекта не изменилось.

## Границы, не блокеры

Синтетическая карта, 10% путей вне регионов, события поданы через тестовый вход, один запуск.

| Путей × регионов | Конструктор карты, `1b617c4` / `063f1c7` | Событие `node_modules`, `1b617c4` / `063f1c7` |
|---|---|---|
| 20 000 × 1 | 5 мс / 45 мс | 3957 / 4 мкс |
| 20 000 × 100 | 11 мс / 436 мс | 3687 / 42 мкс |
| 20 000 × 500 | 7 мс / 2,2 с | 4266 / 206 мкс |
| 100 000 × 1000 | 34 мс / 19,1 с | 23 093 / 384 мкс |

- **Конструктор карты стал дороже.** `CreateExternalInputDirectories` проверяет каждый путь по регионам, поэтому цена
  растёт как произведение путей на регионы. Цена разовая, на загрузке и при захвате кэша состояния. На настоящем большом
  solution доля от времени загрузки не измерялась. Ускорить стоит, если это станет заметно.
- **Цена события зависит от числа проектов.** От числа путей карты она больше не зависит, но `Consult` обходит регионы,
  как и на `1b617c4`. При сотнях проектов массовое удаление всё ещё может переполнить очередь.
- **Массовое удаление из `obj`.** На Linux 20 000 файлов при 2000 исходников поднимают флаг на всех трёх коммитах. По коду
  вероятная причина — линейный поиск по `_compositionPaths` в `RememberPath`; профилировщик не применялся. На Windows, по
  [замерам исполнителя](task-03-review-round-21-measurements.md), флаг поднимается уже при 5000 файлах и 2000 исходников,
  и на `1b617c4` тоже. Рецензент это не повторял, и если такое случится при обычной очистке `obj`, ответ до конца сессии
  будет грубым.
- **Манифест validation.** Хэши двух production-файлов в
  [манифесте](task-03-final-validation-round-22-linux/source-manifest.json) совпадают с коммитом, а хэш
  `BaselineDeletedPathCostTests.cs` нет, и окончаниями строк это не объясняется. Причина не установлена. Полные прогоны
  рецензента выполнены на закоммиченном файле.
