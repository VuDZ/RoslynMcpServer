## Журнал `.git` под `artifacts`

Регрессия исполнителя `Real_git_add_and_commit…` для репозитория внутри `artifacts` отключает настоящий
watcher. На настоящем watcher флаг опущен, но в журнале 17 путей `.git` (на `bfbe27c` — 19). Это прежнее
поведение событий `Changed`/`Created`, исполнитель его записал. Новое правило task-04 отбирает такие пути
как вывод сборки, поэтому отдельное исправление здесь не требуется.

## R11-001 — пути вне каталога solution больше не игнорируются (MUST-FIX)

`WorkspaceDiskPathFilter.IsIgnoredPath(fullPath, workspaceDirectory)` возвращает `false` для любого пути вне
каталога solution. Если solution лежит в `build/` или `src/`, то `bin`, `obj`, `node_modules` и `.git`
соседних каталогов обрабатываются как обычные пути. Это возвращает дефект
[R5-003](task-03-review-round-5.md) для такой раскладки.

Настоящий watcher, файловые операции и реальный git, временный тест рецензента:

| Раскладка и действие | `bfbe27c` | `d8de3a5` |
|---|---|---|
| `build/All.slnx`, `src/App`: каталог `obj/foo` → `obj/bar` | флаг опущен, журнал пуст | **`RequiresFullScan=true`** |
| То же: каталог `node_modules/.staging/pkg` → `node_modules/pkg` | флаг опущен, журнал пуст | **`RequiresFullScan=true`** |
| То же: файл `obj/temp.lock` → `obj/index` | журнал пуст | **2 пути в журнале**, флаг опущен |
| `build/All.slnx`, проект в корне репозитория: `git add` и `git commit` | `.git` в журнале нет | **4 пути `.git` в журнале**, флаг опущен |
| То же: каталог `.git/rebase-apply` → `.git/rebase-merge` | флаг опущен, журнал пуст | **`RequiresFullScan=true`** |
| Solution в корне репозитория: те же действия | без изменений | без изменений |

Флаг не сбрасывается до загрузки другого solution, поэтому инструмент до конца сессии будет отвечать
грубее. Тесты при этом не теряются.

Границы наблюдения: перемещения каталогов выполнены через `Directory.Move`, настоящий `npm` не запускался,
операция git, переименовывающая каталог внутри `.git`, не искалась, частота в реальной работе не измерялась.
Записи `.git` в журнале при `git add` и `git commit` воспроизведены на реальном git.

Источник — в том числе формулировка рецензента в [R9-001](task-03-review-round-9.md): «только ниже каталога
solution». Правильной была её вторая половина: не учитывается только общий с этим каталогом префикс пути.
Та же неточность была в правиле [task-04](../task-04-level0-path-mapping-med.md): вывод сборки соседнего
проекта получал бы «Not covered». Правило уточнено.

Требуется:

- у пути не учитывается только префикс, общий с каталогом solution; остальные сегменты проверяются как
  обычно. Путь вне каталога solution от этого не становится неигнорируемым;
- всё, что закрыто R9-001, сохраняется: приоритет карты входов и репозиторий внутри каталога с игнорируемым
  именем;
- поведение прочих событий и обновление документов не менять.

Вероятное направление, рецензентом не проверено: сравнивать сегменты пути с каталогом solution и отбрасывать
совпавшее начало. Исполнитель выбирает решение сам.

Регрессии на настоящем watcher, RED записан до правки:

- `build/All.slnx`, `src/App`: переименование каталога в `obj` и перемещение каталога в `node_modules` — флаг
  опущен, этих путей в журнале нет; переименование файла в `obj` — в журнале нет;
- `build/All.slnx`, проект в корне репозитория: реальные `git add` и `git commit` — флаг опущен, `.git` в
  журнале нет; переименование каталога внутри `.git` — флаг опущен;
- guards при той же раскладке: настоящее переименование каталога в `src/App` поднимает флаг, переименование
  `.cs` в `src/App` даёт оба пути в журнале, явный вход под `src/App/obj` при переименовании попадает в журнал.

Validation после правки: Release build, SourceStructure, полная main suite на Windows и не менее трёх полных
прогонов на Linux; остальное по [AGENTS.md](../../../../AGENTS.md).
