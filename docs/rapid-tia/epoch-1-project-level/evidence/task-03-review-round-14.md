## R14-001 — перемещение каталога без `Renamed` оставляет журнал неполным при опущенном флаге (MUST-FIX)

Каталог, исчезнувший без события `Renamed`, приходит как `Deleted` самого каталога. `QueueDiskPath` пишет в журнал
только этот путь, а известные входы под ним в журнал не попадают. При опущенном флаге журнал считается полным,
поэтому документ, которого на старом месте уже нет, выглядит неизменённым.

Временный тест рецензента, solution в корне репозитория или в `build/`, проект в `src/App`, документ `Sub/A.cs` со
статусом `Known`. «Настоящий» — физический watcher и `Directory.Move`, «подставленный» — watcher отключён, события
переданы через тестовый вход.

| Действие | Способ | Флаг | Журнал | Граф устарел |
|---|---|---|---|---|
| `Sub` вынесен за пределы дерева, `Compile` по маске или явный | настоящий | нет | только `src/App/Sub` | да |
| `Other` создан и сразу `Sub` → `Other/Sub` | настоящий, 3 запуска из 5 | нет | только `src/App/Other`, `src/App/Sub` | не замерялось |
| То же с паузой 1,5 с или с `Other`, существовавшим при загрузке | настоящий, 3 из 3 | **да** | с `Sub/A.cs` | не замерялось |
| `Sub` → `Other/Sub`, события `Deleted` и `Created` каталога | подставленный | нет | только два пути каталогов | да |
| Подключённый ссылкой `Shared/Sub/L.cs` при `Shared/L0.cs`, `Sub` вынесен | настоящий | нет | только `Shared/Sub` | **нет** |
| Подключённый ссылкой `Shared/Sub/L.cs` без соседей, `Sub` вынесен | настоящий | нет | **пуст** | **нет** |
| Guard: рекурсивное удаление `Sub` | настоящий | нет | `Sub` и `Sub/A.cs` — верно | не замерялось |

После `EnsureDiskChangesAppliedAsync` при вынесенном `Sub` документ остаётся в опубликованном solution, флаг опущен.
Только `load_workspace` того же пути поднимает флаг и возвращает `Sub/A.cs` в журнал.

В случаях, где граф устарел, task-08 напишет «Not covered, нужен reload», но план не назовёт тесты затронутого проекта.
Для подключённых ссылкой каталогов этого признака нет; в последнем случае нет вообще никакого сигнала, и тесты
теряются молча. Это нарушает контракт: при опущенном флаге журнал считается полным.

Windows: в [RED исполнителя R11-001](task-03-review-round-11-red.md) перенос каталога между родителями не дал
`Renamed` и завершился таймаутом, причина не устанавливалась, сценарий заменён. Ожидаемая там последовательность —
`Deleted` и `Created` каталога; строка таблицы с ней подставлена рецензентом на Linux, настоящий запуск на Windows
не выполнялся. Если она подтвердится, на Windows дефект возникает при обычном переносе папки.

Это не регрессия R11-001: из production-кода раунд менял только `WorkspaceDiskPathFilter.cs`, а запись пути в
`QueueDiskPath` существует с `95b88b2`. Дефект пропустили все раунды, включая раунды рецензента.

Границы наблюдения: перемещения выполнены через `Directory.Move`, `mv` и `git mv` не запускались, частота в реальной
работе не измерялась. Repo внутри `artifacts` и явный вход под `obj` для этого сценария рецензент не проверял.
Причина, по которой `src/App` → `src/App2` поднимает флаг, а вынесенный `Shared/Sub` — нет, не исследована.

Требуется:

- после исчезновения каталога без `Renamed` каждый известный вход под ним должен быть в журнале либо должен быть поднят
  флаг, на обеих платформах и для входов вне проекта, подключённых ссылкой;
- перемещение каталога, за которым следит собственный watcher, не должно проходить без сигнала. Если платформа не даёт
  события вообще, это записать и закрыть другим способом;
- обычное удаление каталога с файлами флаг не поднимает: журнал там уже полон, а флаг необратим;
- каталог без известных входов флаг не поднимает, игнорируемые каталоги `bin`, `obj`, `node_modules`, `.git` остаются
  вне журнала и разрыва, как после R11-001;
- записать настоящую последовательность событий при переносе каталога между родителями на Windows.

Вероятное направление, рецензентом не проверено: при `Deleted` пути, под которым в карте есть входы, писать в журнал
каждый такой вход; путь каталога можно оставить, task-04 трактует его как прочий не-C# путь. Исполнитель выбирает
решение сам.

Регрессии, RED записан до правки, настоящий watcher, где не указано иное:

- `Sub` вынесен за пределы дерева при `Compile` по маске и явном, solution в корне и в `build/`;
- подключённый ссылкой вложенный каталог вынесен; подключённый ссылкой каталог с собственным watcher вынесен;
- `Sub` → `Other/Sub` с `Other`, существовавшим при загрузке, — на Windows настоящий запуск, тот самый сценарий, что
  дал таймаут;
- подставленные `Deleted` и `Created` каталога: детерминированно закрепляют и порядок Windows, и гонку `mkdir` с
  переносом, потому что на настоящем watcher она воспроизводится не всегда;
- репозиторий внутри `artifacts` и явный вход под `obj`: каталог с входом вынесен — вход в журнале либо флаг поднят;
- guards: рекурсивное удаление каталога с документом — флаг опущен, файл в журнале; пустой каталог и каталог без
  входов — флаг опущен; каталог под `obj` при `build/All.slnx` вынесен — флаг опущен, журнал пуст; настоящее
  переименование каталога поднимает флаг, как раньше.
