## R1-001 — фильтр через `run_test_by_filter` по инструкции идёт на старых бинарниках

Рабочий цикл в [README](../../../../README.md) (EN, раздел `estimate_affected_tests`, и RU) и в
[`AGENTS.md.sample`](../../../../AGENTS.md.sample) («During edits»): после сохранения правки вызвать
`estimate_affected_tests`, затем `run: true` **или** выполнить возвращённые фильтры через `run_test_by_filter`
(проект целиком — через `run_dotnet_test`).

У `run_test_by_filter` без явного `noBuild` сборки нет: `TestTools.FilterTestOmitSkipsRebuild = true`, описание
параметра — «Skip the pre-test build. Omit means true». У `run_dotnet_test` и `run_specific_test` по умолчанию сборка
есть. Предупреждения о том, что DLL старше исходников, в ответе нет.

Реальный сценарий: агент меняет тело теста и сохраняет файл, estimate возвращает фильтр этого теста, агент по
инструкции вызывает `run_test_by_filter(project, filter)`. Выполняется прежняя DLL, тест зелёный, правка не проверена.
Это ровно риск, ради которого task-09 требует свежую сборку («прогон на старых бинарниках показывает зелёный результат
для непроверенной правки»). Новый тест в старой DLL отсутствует, и его прогон тоже не проверяет правку.

Поведение уже исполняется в main suite: `EstimateAffectedTestsRunTests.Run_builds_changed_sources_instead_of_passing_on_stale_binaries_and_continues_after_test_failure`
вызывает `RunTestByFilter(project, "FullyQualifiedName~Ns.Cases.First")` без `noBuild` после правки, которая делает
тест падающим, и проверяет, что прогон проходит («Filtered tests passed»), а новый код не выполняется. Тест зелёный и
в Linux-прогоне выше.

Фраза «Without `run`, execute a filter with `run_test_by_filter`» была в README и раньше, с task-08, но task-11
сделала её рабочим циклом агента. Независимый рецензент раунда 1 проверил документацию против кода исполнения `run`, но
не умолчание `noBuild` у `run_test_by_filter`. По [R-18](../../README.md#решения-владельца-2026-10-29) неверная
инструкция в реальном сценарии — повод для возврата, как R1-001 task-09.

### Решение владельца и требуемое поведение

Второй раунд task-11; способ выбирает исполнитель.

- Везде, где рабочий цикл предлагает выполнить возвращённый фильтр без `run`, явно указан `noBuild: false` у
  `run_test_by_filter` (или фильтр исполняется инструментом, который по умолчанию собирает). Места: README EN и RU,
  `AGENTS.md.sample`; проверить и ARCHITECTURE, справку инструмента и описание `estimate_affected_tests`.

  SourceStructure и main suite, ни новая версия. Если правится строка в C# (справка, описание инструмента) — полные
  правила, как для кода.
