## Почему это дефекты

Признаки `IsTestMethod` и `IsOwnTestClassRoot` — основание для сужения: по правилу «Без
графа» они гасят проектное расширение тестового проекта. Ложный признак молча теряет
тесты. Ошибка лишнего расширения стоит только времени прогона.

Read-only probe рецензента (исходники builder, detector и моделей версии `c5b9276` в
отдельном file-based приложении, Microsoft.CodeAnalysis.CSharp 5.9.0) дал результаты в
таблицах ниже; правка в каждой строке — `Work(1)` → `Work(2)` либо значение
инициализатора.

## R2-001 — базовые тестовые классы сужают ответ (MUST-FIX)

| Документ | Результат | Что теряется |
|---|---|---|
| `[TestFixture] abstract class Base { [SetUp] public void Prepare() { … } }` | `root=True` | все тесты наследников; у `Base` своих тестов нет, ответ пуст |
| `[TestClass] public abstract class Base { [TestInitialize] public void Init() { … } }` | `root=True` | то же |
| `abstract class Base { protected Base() { … } [Fact] public void Shared() {} }` | `.ctor`: `root=True` | запуски в наследниках |
| `abstract class Base { [Fact] public void Shared() { … } }` | `test=True` | запуски в наследниках |
| `class Base { public Base() { … } [Fact] public void T() {} } class D : Base { [Fact] public void U() {} }` | `.ctor`: `root=True` | тесты `D`, хотя наследник в том же документе |

Источник — формулировка программы «изменённый член исполняют только они», неверная для
наследования; автор текста программы — рецензент этого раунда. Task-02 реализовала её
дословно. Правило уточнено [решением R-17](../../README.md#решения-владельца-2026-10-29) (вариант B, выбран
владельцем): `sealed`-only отклонён, потому что выключил бы исключение для обычных
незапечатанных тестовых классов.

Требуется в task-02:

- член абстрактного типа и типа, у которого есть наследник в этом же документе, не
  получает `IsOwnTestClassRoot`; для partial-типа достаточно `abstract` на любой части в
  документе;
- тестовый метод такого типа сохраняет `IsTestMethod`, но несёт отдельный факт
  запрета сужения; имя — на усмотрение исполнителя, например `BlocksNarrowing`;
- снимок документа хранит простые имена всех типов из его списков базовых типов: без
  квалификатора и generic-арности (`N.Base<int>` → `Base`). Эти имена — вход task-05,
  проверка наследников в других документах в task-02 не входит.

## R2-002 — нечастные static-члены и статический конструктор (MUST-FIX)

| Документ | Результат | Что теряется |
|---|---|---|
| `class A { public static readonly int V = 1; [Fact] public void T() {} }` | `V`: `root=True` | тесты других классов, читающих `A.V` (например `MemberData(…, MemberType = typeof(A))`) |
| `class A { public static int V { get; } = 1; [Fact] public void T() {} }` | `V`: `root=True` | то же |

`const` в той же задаче исключён именно потому, что его читают другие классы; для
нечастных static-членов сработала та же причина. Статический конструктор тоже пишет
состояние, видимое другим классам.

Требуется: static-поле или static-свойство с инициализатором — корень, только если член
частный (`private` или без модификатора доступа); `protected`, `internal`, `public` и их
сочетания — обычный член. Статический конструктор — обычный член: в тестовых классах он
редок, поэтому точность почти не страдает. Instance-инициализаторы, конструктор и setup
остаются корнями.

## R2-003 — роль берётся только из текущего снимка (исправить в этом раунде)

| До → после | Результат | Что теряется |
|---|---|---|
| `class H { public H() { … } }` → правка конструктора и новый `[Fact]` в `H` | `.ctor`: `root=True` | вызывающие `new H()` из других классов |
| `class H { public int Run() => 1; }` → `class H { [Fact] public int Run() => 2; }` | `test=True` | прежние вызывающие `Run` |

Требуется: изменённый член получает `IsOwnTestClassRoot`, только если был корнем в
baseline. Метод, ставший тестовым, сохраняет `IsTestMethod` (часть 1 программы) и несёт
факт запрета сужения из R2-001. Отличить добавление атрибута от правки тела по хешу
нельзя, поэтому запрет действует и при правке только атрибута.

## R2-004 — новый тестовый класс расширяет весь проект (исправить в этом раунде)

`class A { [Fact] … }` → тот же файл плюс `class B { [Fact] public void U() {} }` даёт
`MemberAdded` типа `B` без признаков и `MemberAdded` теста `U`. Запись типа — обычный
член, поэтому исключение не срабатывает. Тесты не теряются, но частый сценарий агента
запускает весь тестовый проект.

Требуется: добавленная запись типа с собственными тестами (и не абстрактного) получает
`IsOwnTestClassRoot`. Изменённая запись типа остаётся `TypeChanged` без признаков.

## Регрессии

Все случаи R2-001…R2-004 пишутся первыми и красные до правки production-кода. Заменить
ожидания, закрепляющие дефект: строка `static C()` в
`Own_constructor_and_initializer_changes_are_test_class_roots` и строка
`void Run() {}` → `[Fact] void Run() {}` в
`Test_role_uses_current_syntax_and_custom_attribute_hierarchies_are_not_guessed`.
Guard: запечатанный и обычный класс без наследников в документе, `private`-инициализатор
и инициализатор без модификатора — корни, как раньше.

## Перенесено в эпоху 3

В эпохе 1 оба случая перекрываются проектным расширением и тестов не теряют; записаны в
[описание эпохи 3](../../epoch-3-level1-production/README.md), где появится уровень «весь тип».

- **R2-005.** `#define`/`#undef` действуют на весь файл, но попадают в хеш первого
  токена. `#define X\nclass A {}\nclass B { void M() {\n#if X\nWork();\n#endif\n} }` при
  смене `X` на `Y` даёт `TypeChanged` только для `A`; хеш `M` не меняется.
- **R2-006.** Новый член блока `extension(…)` C# 14 не даёт `NewExtensionMethod`: факт
  проверяет только `this` у первого параметра. Ключ получает безымянный сегмент пути
  (`` E`0.`0 ``).
