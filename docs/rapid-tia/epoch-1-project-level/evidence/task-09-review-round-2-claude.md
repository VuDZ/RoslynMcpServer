## T09-C1 — после собственного `run` проект до конца baseline идёт целиком

`run` пересобирает тестовый проект. Его выходная сборка есть в карте входов и относится к своему проекту (T04-C3), поэтому
после сборки она числится изменённым входом, а проект с зависимыми тестовыми проектами расширяется целиком. Не-C# входы
не сравниваются по содержимому и сохраняются после reload (R3-001 task-08), так что расширение держится до загрузки другого
solution.

Воспроизведение: временный тест рецензента на `TestImpactRunFixture` (настоящий MSBuild, watcher и xUnit), Linux, одна
последовательность; тест удалён, дерево чистое.

| Шаг | Ответ инструмента |
|---|---|
| Правка тела теста в `First` | `First`, фильтр `FullyQualifiedName~Ns.Cases.First` |
| `run: true` | `passed`, Total 3 |
| Повторный estimate без правок | `First` **целиком**, причина — `First/bin/Release/net10.0/First.dll`; «1 members in 2 files» |
| Настоящий reload того же solution, Release (`ClearWorkspaceAsync` + `LoadAsync`, `LastLoadReopenedGraph=True`) | без изменений, `First` целиком |
| Правка откатана | 0 изменённых членов, `First` целиком |
| Правка теста в `Second` | `First` целиком, `Second` по фильтру |

Reload с другой конфигурацией (Debug) добавляет ещё и сгенерированные `obj/Debug/...AssemblyInfo.cs` обоих проектов,
и оба идут целиком.

Тесты при этом не теряются, ответ только шире, поэтому по R-18 это огрубление, а не возврат. Механизм не новый: T04-C3
([второй рецензент task-04](task-04-review-round-1-claude.md#t04-c3--полная-пересборка-без-правок-даёт-все-тесты-ограничение))
уже говорит, что с правкой инкрементальная сборка затрагивает изменённый проект, и тот же эффект даёт обычный
`run_dotnet_test`. С task-09 он неизбежен: первый же `run` делает все следующие ответы по собранным проектам ответами
«целиком» до конца baseline. Для `RoslynMcpServer.Tests` владельца это около 2000 тестов и 10 минут. Тесты task-09 этот
сценарий не видят: estimate после `run` не проверяется, а ручной прогон фильтра идёт с `noBuild=true` именно в обход
T04-C3.

Уточнение T04-C3: ответ «целиком» даёт не только полная пересборка без правок. Любая сборка, которая перезаписала выходную
сборку проекта, в том числе инкрементальная после правки и сборка внутри `run` или `run_*`, переводит этот проект и
зависимые от него тестовые проекты в «целиком» до загрузки другого solution. Откат правки и reload этого не снимают.
Попутно строка «Changed since load: … in N files» считает выходную сборку файлом.

  buildArgs нет; это уже записано в [раунде 2](task-09-review-round-2.md).
