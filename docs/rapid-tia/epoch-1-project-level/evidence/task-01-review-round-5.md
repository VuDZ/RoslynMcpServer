## R5-001 — перестановка свойств без инициализаторов не видна в снимке (MUST-FIX)

`Services/Testing/Baseline/BaselineDocumentSnapshotBuilder.cs`, `DeclarationOrder`:
порядок учитывается только для `PropertyDeclarationSyntax { Initializer: not null }`.
Это следует из формулировки [R3-001](task-01-review-round-3.md), где рецензент допустил
не различать перестановку «свойств без инициализаторов». Допущение ошибочно: порядок
свойств наблюдаем и без инициализаторов.

Read-only probe рецензента (исходники builder и моделей версии `7545186` в отдельном
file-based приложении, Microsoft.CodeAnalysis.CSharp 5.9.0): во всех строках меняется
только `TextChecksum`; ключи, хеши членов, хеши вне членов и `HasUnparseableContent`
совпадают.

| До → после | Что меняется в поведении |
|---|---|
| `record R { public int A { get; init; } public int B { get; init; } }` → свойства переставлены | вывод `ToString()`: синтезированный `PrintMembers` печатает члены в порядке объявления |
| `struct S { int A { get; set; } long B { get; set; } }` → свойства переставлены | порядок скрытых полей автосвойств, то есть layout |
| `class D { public int A { get; set; } public int B { get; set; } }` → свойства переставлены | порядок свойств в JSON System.Text.Json по умолчанию |

Потеря молчаливая: если других изменений нет, task-02 по равенству хешей выведет
«изменений нет», и проектного расширения не будет.

Требуется:

- нумеровать в общем порядке типа все свойства, кроме индексаторов, а не только свойства
  с инициализаторами; члены enum и поля/event-поля — как сейчас;
- регрессии по таблице выше, сначала красные;
- guard-случай «перестановка свойств без инициализаторов сохраняет хеши» в
  `Reordering_members_without_meaningful_order_keeps_hashes_by_key` закрепляет как раз
  этот дефект: его заменить регрессией, а guard оставить для методов, вложенных типов,
  индексаторов и событий с accessors;
- комментарий у `DeclarationOrder` дополнить причиной для свойств (`PrintMembers`,
  layout, порядок сериализации).

Перестановка методов, индексаторов, событий с accessors и вложенных типов по-прежнему
допустимо не различать: их порядок не меняет layout, синтезированных членов record и
сериализации свойств.
