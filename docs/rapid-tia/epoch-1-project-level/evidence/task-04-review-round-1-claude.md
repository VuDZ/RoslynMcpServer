## Реальный поток

Настоящий watcher, настоящая сборка до загрузки. `Specs` → `App` → `Lib`, `Iso` ни от кого не зависит, оба тестовых, у
проектов маски `Compile` по умолчанию. Каждый сценарий — один запуск на Linux. На вход маппера подан весь журнал путей.

| Действие | Флаг | Граф устарел | Тестовые проекты | Reload | Not covered |
|---|---|---|---|---|---|
| Правка `Lib/L.cs` | нет | нет | `Specs` | нет | — |
| Правка `Iso/I.cs` | нет | нет | `Iso` | нет | — |
| Правка `Iso/I.cs` и `dotnet build` | нет | нет | `Iso` | нет | — |
| `dotnet build` без правок | нет | нет | — | нет | — |
| `notes.txt` в корне, вне проектов | нет | нет | — | нет | — |

| Новый `Lib/Fresh.cs` | нет | да, состав | **все** | да | — |
| Новый `Lib/notes.txt` | нет | да, состав | **все** | да | `Lib/notes.txt` |

После reload флаг поднят, а журнал содержит все исходники, поэтому при таком входе маппер даёт все проекты. Это следствие
того, что рецензент подал журнал как есть, а не дефект маппера: что пойдёт на вход, определяет task-08.

## T04-C1 — новый файл в каталоге проекта расширяет ответ до всех тестов

Любой неизвестный путь внутри каталога проекта классифицируется как `PotentialMembership` и поднимает
`ProjectGraphStale` через изменение состава, в том числе не-C#. Маппер при поднятом признаке отдаёт все тестовые проекты.

Программа требует другого: для нового `.cs` — ближайший проект и совет reload, для прочего пути вне карты — «Not covered»
без расширения, а все тесты — только для файла графа проектов. Тест `New_CSharp_file_uses_the_nearest_project_and_requires_reload`
подаёт признак `false`; при настоящем watcher в каталоге проекта такого состояния рецензент не получил, так что эта ветка
программы фактически не работает. Ограничение T04-R1-L05 это расширение записало, но не этот вывод.

Тесты не теряются, ответ избыточен. Но добавление файла — частое действие, а следующий за ним reload поднимает необратимый
флаг, и ответ становится ещё грубее.

## T04-C2 — «нужен reload» сразу после reload

Удалённый `Lib/Old.cs` и файл `Lib/Template.cs` из `Compile Remove` после reload нет ни в solution, ни в карте. Маппер
считает их новым `.cs`: ближайший проект и `RequiresReload=true`. Совет повторяется, пока не будет загружен другой solution,
и может зациклить агента.

Формально это неверный ответ в реальном сценарии, условие возврата по [R-18](../../README.md#решения-владельца-2026-10-29).
Владелец решил не возвращать задачу: вызывающего кода ещё нет, правка небольшая и ложится на следующую задачу. Набор
проектов тесты не теряет.

## T04-C3 — полная пересборка без правок даёт все тесты (ограничение)

Выходные сборки есть в карте и относятся к своим проектам, поэтому `dotnet build --no-incremental` без правок выбирает все
тестовые проекты. Инкрементальная сборка этого не делает: без правок журнал пуст, с правкой `Iso` затронут только `Iso`.
