## Цель

Собрать из изменений (task-02) и проектов (task-04) ответ: какие тесты и проекты
затронуты и почему. Интерфейс сразу принимает вторую часть — тесты по графу, — которую
добавит эпоха 3; в эпохе 1 она пуста.

## Входы и границы

[Программа](../README.md): раздел «Состав ответа». Перед первой правкой C# прочитать
[code style](../../code-style.md) целиком.

Без графа вызовов: изменение обычного (не тестового) члена C# в эпохе 1 даёт проектное
расширение его проекта, как предписывает часть 3 при «граф уровня 1 ещё не готов».

## Конкретный результат

- Часть 1: новые и изменённые тестовые методы — поимённо, до любой отсечки; изменённый
  или новый корень тестового класса (конструктор, setup, фикстура) — все тесты класса.
- Часть 3: проектное расширение для перечисленных в программе случаев.
- Правило «Без графа» из раздела «Состав ответа» [программы](../README.md): изменение,
  добавление или удаление обычного члена C# — проектное расширение его проекта. Если в
  тестовом проекте изменены только тестовые методы и собственные корни тестовых классов
  (конструктор, инициализаторы полей, setup и teardown самого класса), ответ по этому
  проекту сужается до этих тестов. Изменение типа фикстуры, вспомогательного или
  другого нетестового члена тестового проекта — проектное расширение.
- Для каждого включения — причина, пригодная для ответа и для «Not covered».

## Порядок работы — TDD (R-16)

1. Сначала тесты из раздела «Проверки»: они пишутся до production-кода и падают по
   ожидаемой причине (red). Чтобы тест компилировался, допустимо завести пустой
   контракт — типы и сигнатуры с `NotImplementedException`; падение из-за ошибки
   компиляции или фикстуры красным прогоном не считается.
2. Затем минимальная реализация до зелёного прогона (green), затем рефакторинг при
   зелёных тестах.
3. Красный прогон фиксируется в отчёте задачи: какие тесты написаны первыми и вывод
   focused-прогона до реализации. В коммит идёт только зелёное состояние: main suite
   перед коммитом — по [AGENTS.md](../../../AGENTS.md).
4. Тест, добавленный после реализации, отмечается в отчёте отдельно с причиной.

## Проверки

Каталог «Состав ответа» [программы](../README.md): новый тест в существующем файле;
новый тестовый файл до и после reload; переименованный тест; обычный метод, ставший
тестовым; удалённый тест; изменение конструктора или setup тестового класса — только
тесты этого класса; изменение типа фикстуры — проектное расширение; изменение
вспомогательного метода в тестовом проекте — проектное расширение; изменение и
удаление production-метода — проектное расширение с транзитивными тестовыми
проектами.

Это focused минимум; Release build, main suite и SourceStructure — по
[AGENTS.md](../../../AGENTS.md). Дата, scope, evidence и фактические модели
записываются в шапку и README эпохи после ревью и validation.
