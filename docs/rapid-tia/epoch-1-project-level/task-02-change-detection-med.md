## Цель

Чистая функция «снимок baseline + текущий снимок → классифицированные изменения
документа». Результат — вход состава ответа (task-05).

## Входы и границы

[Программа](../README.md), разделы «Baseline и обнаружение изменений» и «Изменения
связывания (R-14)» — только та часть, что выражается синтаксически. Перед первой
правкой C# прочитать [code style](../../code-style.md) целиком.

Без графа и без проектов: проектное расширение здесь только помечается видом
изменения, отображение на проекты — task-04 и task-05.

## Конкретный результат

Для пары снимков — список изменений с видом:

- член изменён, добавлен, удалён (удалённый — с ключом из baseline);
- смена сигнатуры — удаление старого ключа и добавление нового;
- изменение вне членов: `using`/alias/namespace → «весь файл»; `global using` →
  «проект»; атрибут сборки или модуля → «проект»;
- изменение только `DirectivesHash` (директивы и неактивный код вне членов) → «весь файл»;
- изменение атрибутов, `partial`, базового типа или интерфейсов типа → «весь тип»;
- документ не разбирается до членов → «весь файл»;
- ключ, который не сопоставляется однозначно, → «весь файл»;
- правка только комментариев и пробелов и правка, вернувшая текст baseline, —
  изменений нет.

Отдельно — признак, что изменённый или добавленный член — тестовый метод или корень
тестового класса (по имени атрибута, как [TestAttributeMatcher](../../../Services/Testing/TestAttributeMatcher.cs)).

Признак разрешает сужение ответа, поэтому он консервативен (R-17 [программы](../README.md)):

- член абстрактного типа и типа с наследником в этом же документе — не корень; тестовый
  метод такого типа остаётся тестовым, но несёт отдельный факт запрета сужения;
- static-поле или static-свойство с инициализатором — корень, только если член частный;
  статический конструктор — обычный член;
- изменённый член — корень, только если был корнем в baseline; метод, ставший тестовым,
  остаётся тестовым и несёт факт запрета сужения;
- добавленная запись неабстрактного типа с собственными тестами — корень.

Снимок документа дополнительно хранит простые имена типов из его списков базовых типов,
без квалификатора и generic-арности: это вход проверки наследников в
[task-05](task-05-response-composition-med.md).

## Порядок работы — TDD (R-16)

1. Сначала тесты из раздела «Проверки»: они пишутся до production-кода и падают по
   ожидаемой причине (red). Чтобы тест компилировался, допустимо завести пустой
   контракт — типы и сигнатуры с `NotImplementedException`; падение из-за ошибки
   компиляции или фикстуры красным прогоном не считается.
2. Затем минимальная реализация до зелёного прогона (green), затем рефакторинг при
   зелёных тестах.
3. Красный прогон фиксируется в отчёте задачи: какие тесты написаны первыми и вывод
   focused-прогона до реализации. В коммит идёт только зелёное состояние: main suite
   перед коммитом — по [AGENTS.md](../../../AGENTS.md).
4. Тест, добавленный после реализации, отмечается в отчёте отдельно с причиной.

## Проверки

Каталог «Обнаружение изменений» [программы](../README.md): тело, сигнатура,
переименование, добавление и удаление члена; правка объявления `partial`-члена внутри
документа даёт изменение этого члена; generic-перегрузки; явная реализация интерфейса; только комментарии;
возврат к baseline; сломанный синтаксис; `using` и alias; файл только с `global using`;
`AssemblyInfo.cs` без членов с `InternalsVisibleTo`. Ожидания точные, а не «содержит».

Признаки сужения ([раунд 2 ревью](evidence/task-02-review-round-2.md)): тест и корни абстрактного
класса; корень класса с наследником в том же документе; `public`/`protected`/`internal`
static-инициализатор, static-свойство и статический конструктор; конструктор вместе с
новым `[Fact]` в ранее нетестовом классе; метод, ставший тестовым, вместе с правкой тела;
новый тестовый класс в существующем файле; простые имена базовых типов снимка
(`N.Base<int>` → `Base`). Guard: обычный класс без наследников в документе,
`private`-инициализатор и инициализатор без модификатора остаются корнями.

Файл только с `#if false … #endif` вокруг объявлений: правка внутри неактивной ветви
даёт «весь файл»; отдельно проверить пару снимков с изменением только `DirectivesHash`
([передача R3-003 и уточнение R5-002](evidence/task-01-review-round-5.md)).
