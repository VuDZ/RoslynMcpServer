## Цель

Чистая функция «состав ответа → план запуска по каждому тестовому проекту»: фильтр
VSTest или «проект целиком», с причиной. План показывается в ответе инструмента и
исполняется флагом `run`.

## Конкретный результат

- Фильтр набора — дизъюнкция `FullyQualifiedName~<имя>` с экранированием; результат —
  надмножество, и это записано в причине.
- Класс, все тесты которого выбраны, сворачивается в `FullyQualifiedName~Namespace.Class.`.
- Бюджет длины фильтра; при превышении — проект целиком с причиной.
- Проектное расширение — проект целиком без фильтра.
- Имена вложенных и generic классов — в виде, записанном в программе после task-06
  (если проба потребовала правки программы, она сделана до этой задачи).

## Передача из task-06 (обязательные условия)

[Второй рецензент раунда 1 task-06](evidence/task-06-review-round-1-claude.md): у NUnit-фикстуры с аргументами
конструктора имя теста содержит аргументы фикстуры (`Ns.ArgFixture("a").M`, `Ns.SourceFixture(1).S`), и фильтры по
таблице task-06 выбирают 0 тестов.

- **T06-C1.** Для NUnit-класса, у которого `[TestFixture]` несёт аргументы конструктора, или есть `[TestFixtureSource]`,
  не строить `Class.Method` и свёртку `Class.`. Допустимо имя класса без точки (`FullyQualifiedName~Ns.Class`,
  надмножество) или проект целиком; причина называется в плане. Generic-фикстура с аргументами конструктора не
  измерялась и идёт по этому же условию; измеренная форма `[TestFixture(typeof(int))]` остаётся по таблице task-06.
- Регрессия: unit-тест на FQN из записи второго рецензента, без живого runner.

Лимит и критерий возврата — [R-18](../README.md#решения-владельца-2026-10-29).

## Порядок работы — TDD (R-16)

1. Сначала тесты из раздела «Проверки»: они пишутся до production-кода и падают по
   ожидаемой причине (red). Чтобы тест компилировался, допустимо завести пустой
   контракт — типы и сигнатуры с `NotImplementedException`; падение из-за ошибки
   компиляции или фикстуры красным прогоном не считается.
2. Затем минимальная реализация до зелёного прогона (green), затем рефакторинг при
   зелёных тестах.
3. Красный прогон фиксируется в отчёте задачи: какие тесты написаны первыми и вывод
   focused-прогона до реализации. В коммит идёт только зелёное состояние: main suite
   перед коммитом — по [AGENTS.md](../../../AGENTS.md).
4. Тест, добавленный после реализации, отмечается в отчёте отдельно с причиной.
