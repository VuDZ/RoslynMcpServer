## Цель

`run: true` запускает план task-07 одним вызовом MCP через общий сервис запуска
тестов: сначала сборка, затем тесты; каждый процесс получает однозначный исход.

## Конкретный результат

- Параметры прогона: только таймаут; конфигурация и платформа наследуются от
  `load_workspace`.
- Сборка: процесс тестового проекта идёт со сборкой (`noBuild: false`); значение по
  умолчанию `run_test_by_filter` («опущенный `noBuild` пропускает сборку») не
  переносится. Проект целиком — без фильтра, путём `run_dotnet_test`.
- Исходы процесса, не смешиваются: `passed`/`failed` со счётчиками, `build failed` с
  диагностикой в бюджете вывода, `timed out`, `cancelled`, `not run`. Убитый процесс не
  попадает в упавшие тесты.
- `timeoutSeconds` — на каждый процесс; падение одного проекта не останавливает
  остальные.
- Отмена MCP-запроса: текущий процесс убивается с деревом, следующие не стартуют, итог
  пишется одной строкой в лог сервера; ответ отправляется по возможности, без гарантии
  доставки.
- Ответ прогона начинается той же строкой-предупреждением и заканчивается «Not covered».

## Проверки

- Интеграционный тест: исходники изменены после последней сборки, старые бинарники на
  месте — `run` исполняет новый код (тест, проходящий на старой DLL, падает).
- Два тестовых проекта, первый падает — второй запущен, оба отчёта в ответе.
- `build failed` в одном проекте не запускает его тесты и не останавливает другой.
- Таймаут процесса — исход `timed out`, остальные процессы выполнены.
- Отмена `tools/call` через MCP-клиент, а не прямой вызов обработчика: процессы
  остановлены, итог есть в логе; доставка ответа не проверяется как обязательная.
