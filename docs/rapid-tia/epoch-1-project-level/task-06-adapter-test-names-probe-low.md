## Цель

Узнать фактические `FullyQualifiedName`, которые адаптеры VSTest выдают для
вложенных и generic тестовых классов и параметризованных тестов, и проверить, что
фильтр `FullyQualifiedName~…` их выбирает. Без этого фильтр task-07 строится наугад.

## Входы и границы

[Программа](../README.md): раздел «Ответ инструмента», пункт про имена вложенных и
generic классов. [TestFilterHelper](../../../Services/Testing/TestFilterHelper.cs) —
текущее построение фильтра.

Только VSTest: xUnit v2, xUnit v3 в режиме VSTest (`mtp-off`), NUnit, MSTest. MTP —
в отложенной [task-10](task-10-run-mtp-plan-med.md). Проба не меняет production-код.

## Конкретный результат

- Маленькие тестовые проекты-фикстуры (вне solution сервера или в каталоге фикстур
  тестов) с вложенным классом, generic-классом, `Theory`/`TestCase`/`DataRow` с
  параметрами.
- Сохранённые логи `dotnet test --list-tests` и прогона с фильтром — для
  юнит-тестов task-07 без живого `dotnet test`.
- `evidence/task-06-adapter-names.md`: таблица «конструкция → FQN по адаптерам →
  выбирает ли `~`-фильтр», версии пакетов.

## Проверки

- Для каждой конструкции и адаптера записан фактический FQN.
- Фильтр, построенный по правилу программы, выбирает тест; если нет — записано, какой
  вид имени нужен, и форма фильтра возвращается в [программу](../README.md) точечной
  правкой раздела «Ответ инструмента» до начала task-07. Task-07 строит фильтр по
  программе, а не по evidence в обход неё.

Задача не меняет production-код, поэтому SourceStructure и main suite требуются только
если в репозиторий добавляются тестовые фикстуры, которые идут в main suite.
Дата, scope, evidence и фактические модели записываются в шапку и README эпохи после
ревью.
