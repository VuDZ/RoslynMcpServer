## Контракт и файлы

Добавлен `Services/Testing/Baseline/BaselineDocumentChangeDetector.cs` с функцией
`Compare(baseline, current)`. Результат — ImmutableArray<BaselineDocumentChange>;
модели `BaselineDocumentChange`, `BaselineChangeKind`, `BaselineChangeReason`
расположены в `Services/Testing/Baseline/Models/`. Каждая запись содержит вид, причину,
необязательный синтаксический ключ и отдельные признаки текущего тестового метода и
собственного корня тестового класса. Внешних инструментов, workspace, графа, проектов
и форматирования фильтров нет.

- Изменение тела/синтаксиса даёт MemberModified; добавление и удаление — MemberAdded и MemberRemoved. Удалённый ключ берётся из baseline; смена ключа — удаление и добавление. У удалённого члена оба текущих тестовых признака выключены.
- Изменение совпавшего объявления типа, включая delegate, — TypeChanged с ключом типа. Ключи при этом не подменяются; например, первичная сигнатура record может дать удаление и добавление.
- Обычные imports/namespace дают FileChanged; global using и assembly/module атрибуты — ProjectChanged. Новые extension-методы с `this` и новые/изменённые операторы/преобразования дают дополнительную ProjectChanged с ключом причины по синтаксической части R-14.
- Самостоятельное изменение DirectivesHash даёт FileChanged. Директива внутри изменённого члена уже покрыта его хешем. В реальном файле только с неактивными объявлениями меняется также внечленный хеш builder, что даёт FileChanged с причиной ImportsAndNamespaces; изолированная пара с одним DirectivesHash проверена отдельно.
- Несопоставимые повторные ключи не схлопываются: неоднозначность даёт FileChanged. Для синтаксически сломанного документа также добавляется FileChanged; ненадёжные обычные recovered-изменения не выдаются. Однозначные новые/изменённые тесты сохраняются даже рядом с File/Project сигналами.
- Отсечки по TextChecksum нет: сравниваются классифицированные хеши, состояние разбора и мультимножество ключей/хешей. Поэтому изолированная пара с прежним checksum и новым DirectivesHash не теряется, а trivia, возврат к baseline и перестановка обычных методов не создают изменений. Неизменившиеся неоднозначные объявления сами по себе не создают изменение.

`BaselineMemberSnapshot.cs` дополнен необязательными init-свойствами фактов. Его
прежний трёхпараметрический конструктор, ключи и хеши task-01 не менялись.
`BaselineDocumentSnapshotBuilder.cs` вычисляет факты, не сохраняя SyntaxNode или
semantic model. Тестовые имена сопоставляются существующим
TestAttributeMatcher.IsTestAttributeSyntaxName.

Тестовый тип определяется по собственному тестовому методу или явному имени
TestClass/TestFixture в текущем документе, включая partial-части того же документа.
Его конструкторы, исполняемые инициализаторы, setup/teardown по именам атрибутов и
синтаксически указанные lifecycle-интерфейсы могут быть собственными корнями.
Отдельный хеш объявления без инициализаторов отличает правку инициализатора от
правки accessor/объявления; контекст сохраняется и до появления инициализатора.
`const` остаётся обычным членом: его значение может быть встроено в другой класс.
Generic/static Dispose helpers не считаются lifecycle; конкурирующие неявные методы
с одинаковым именем консервативно остаются обычными, explicit-реализация различается
по своему интерфейсу. Метод, потерявший тестовый атрибут, классифицируется по текущей
роли, а не по старому тестовому статусу.

## Исправления после ревью приёмки, раунд 2

Дата: 2026-11-03. Исполнитель: прежний исполнитель эпохи Codex; точный runtime model
ID средой не предоставлен. Scope — R2-001…R2-004 и уточнённое решение R-17. Исправления
в коде готовы к подтверждению; финальную validation, ревью, статусы, коммит и push
выполняет координатор. Приёмка раунда 1 выше относится к предыдущей версии.

**R2-001.** Синтаксические факты группируются по пути типа, объединяя partial-части
одного документа. Abstract на любой части или простое имя типа среди base lists
документа запрещают собственные корни этого типа. Тестовые методы сохраняют
IsTestMethod; отдельный BlocksNarrowing в снимке члена и выходе сравнения запрещает
сужение для наследования. Добавлено неизменяемое множество BaseTypeNames в снимок
документа: все списки базовых типов, без квалификаторов и generic-арности, с
устранением повторов. Например, N.Base<int> даёт Base. Группировка фактов — приватная
деталь builder; дерево и изменяемые коллекции в снимке не сохраняются.

**R2-002.** Static-инициализаторы полей, event-полей и свойств — корни только при
private-only доступе: явном private либо отсутствии модификатора доступа. Public,
protected, internal и комбинации, включая private protected, исключаются независимо
от присутствия private. Статический конструктор — обычный член. Исполняемые instance
инициализаторы, конструкторы и setup eligible-типа сохраняют прежние признаки.

**R2-003.** Для изменённого собственного корня требуется такая же роль в baseline,
дополнительно к прежнему сравнению initializer context. Метод, ставший тестовым,
сохраняет тестовый признак и получает BlocksNarrowing независимо от правки тела;
запрет действует и при добавлении только атрибута. Прежний запрет наследования из
baseline также сохраняется для изменённого теста. Добавленные корни могут быть
eligible; добавление первого инициализатора к существующему non-root члену сужение
не разрешает. Конструктор H, изменённый вместе с новым Fact в H, остаётся обычным.

**R2-004.** Добавленная запись неабстрактного типа с собственными тестами получает
IsOwnTestClassRoot, если нет локального барьера наследования. Изменённая запись типа
по-прежнему TypeChanged без признаков роли. Тип только с маркером TestClass/TestFixture,
но без собственных тестовых методов, новым тестовым корнем типа не объявляется.
