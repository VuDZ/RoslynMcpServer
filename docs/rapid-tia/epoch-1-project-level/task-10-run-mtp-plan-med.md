## Почему отложена

В проектах владельца MTP не используется, а раннер `mtp` — отдельная программа, код
которой не начат. Ждать её ради эпохи 1 незачем: VSTest-путь даёт всю пользу для этих
проектов. Задача берётся, когда раннер `mtp` готов или когда появится проект на MTP.

## Цель

Исполнять MTP-проект по плану программы: процесс на класс или метод, пять условий
перехода на проект целиком, замер накладных расходов процесса `S`.

## Входы и границы

[Программа](../README.md): R-13, разделы «План для MTP-проекта», «Сборка», «Резерв C».
[Раннер `mtp`](../../test-runner-selection/epoch-1-explicit-runner.md) — допустимые
виды фильтра. Перед первой правкой C# прочитать [code style](../../code-style.md)
целиком.

Резерв C (несколько фильтров в одном процессе) — не эта задача, а изменение
test-runner-selection после пробы флагов xUnit v3.

## Конкретный результат

- Проба имён тестов xUnit v3 в режиме MTP (вложенный, generic, параметризованный) —
  дополнение evidence task-06.
- План MTP-проекта: процесс на класс (`FullyQualifiedName~Namespace.Class`) или метод;
  проект целиком при любом из пяти условий программы, с причиной в ответе — с флагом
  `run` и без него.
- Исполнение: первый процесс проекта со сборкой, следующие с `noBuild`; последовательно.
- `evidence/task-10-mtp-overhead.md`: замер `S` на реальном xUnit v3 MTP-проекте для
  этой последовательности и решение о константе предела (сейчас 4).
