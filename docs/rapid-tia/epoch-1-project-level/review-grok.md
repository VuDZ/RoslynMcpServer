## F-001 — Состав ответа эпохи 1 и «граф ещё не готов»

Severity: major

Target: [task-05](task-05-response-composition-med.md); программа, «Состав ответа».

В программе ответ — объединение частей. Часть 3 включает проектное расширение, пока графа нет. В эпохе 1 графа нет всегда, поэтому любое изменение C# раздувает ответ до тестового проекта, а поимённые тесты из части 1 в `run` не влияют. Task-05 это обходит отдельным правилом: если в тестовом проекте менялись только тестовые методы, проект не расширять. Этого правила в программе нет, а README эпохи запрещает задачам менять требования. Правило нужное, но его надо внести в программу. Иначе исполнитель task-05 сузит ответ, а исполнитель по разделу «Состав ответа» — нет.

В то же исключение должны входить корни, которые task-05 уже умеет назвать без графа: конструктор, setup, фикстура. Сейчас исключение написано только для тестовых методов, и правка конструктора снова запускает весь проект. Туда же удаление обычного члена: битсетов ещё нет, часть 2 пуста, и без проектного расширения такой член не выбирает ни одного теста. В проверках task-05 есть только удалённый тест.

## F-003 — Task-03 может стереть baseline при reload

Severity: major

Target: [task-03](task-03-baseline-lifecycle-hi.md); программа, «Фиксация baseline текстов» и R-03.

Программа требует: reload того же solution baseline не сбрасывает, а reload до конца снимка сохраняет уже записанные хеши. В задаче то же сказано про reset. Рядом — номер поколения и «задача, завершившаяся после следующей загрузки, результат отбрасывает». Для графа в программе так и есть. Для снимка «результат» легко прочитать как все хеши этой задачи, включая уже записанные. Тогда reload после правки csproj, ради которого baseline и не сбрасывают, историю сотрёт. В тексте нужно оставить: записанные хеши переживают reload и reset, отбрасывается только ещё не записанный хвост и чужое поколение.

## F-004 — Эпоха 4 ставит обычный using в каскад

Severity: major

Target: [эпоха 4](../epoch-4-persisted-graph/README.md), «Содержание»; программа, шаг 3 «Последовательности после загрузки».

В контуре каскад на все транзитивно зависящие проекты включает `using`. В программе на это множество идут `global using`, оператор, преобразование и атрибут сборки. Обычный `using` и alias остаются уровнем файла. Если нарезать задачи из этого абзаца, смена `using` будет заново извлекать факты всего хвоста solution. Промежуточный проект без тестов в том же абзаце назван правильно.

## Что сходится

Отложение MTP в task-10 уже записано в таблице эпох; до него проект на MTP идёт тем же путём, что текущие `run_*`. Сборка и исходы `run` в task-09 совпадают с решением владельца: один VSTest-процесс на проект, со сборкой, `cancelled` не смешивается с упавшими тестами. Ключ листа для метаданных отложен в эпоху 3, где появляется граф. Это лучше не перекраивать.

Исправлений по этому отчёту пока нет.
