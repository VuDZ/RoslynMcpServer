## Цель

Закрыть ограничение T09-C1 по [R-19](../README.md#решения-владельца-2026-10-29): любая сборка, перезаписавшая выходную
сборку проекта (в том числе `run`, `run_*` и инкрементальная сборка после правки), до конца baseline переводила проект и
зависимые тестовые проекты в «целиком». Откат правки, reset и reload этого не снимали.
[Owner-проба](evidence/task-11-owner-measurement.md) показала это 1/1.

## Причина

[WorkspaceInputMapBuilder](../../../Services/Workspace/WorkspaceInputMapBuilder.cs) заносит `OutputFilePath` и
`OutputRefFilePath` каждого проекта в карту входов с ролью `Output`, а ссылки на эти файлы — с ролью
`MetadataDependency` и производителем. Фильтр вывода сборки в
[ProjectImpactMapper](../../../Services/Testing/ProjectImpactMapper.cs) пропускает только пути **вне** карты, поэтому
перезаписанная DLL относилась к своему проекту. Не-C# входы с baseline не сравниваются, и путь оставался изменённым.

## Конкретный результат

- Путь, у которого в карте только роли `Output` и `MetadataDependency` с производителем из загруженного solution, —
  продукт сборки. Сам производитель и проекты, которые транзитивно зависят от него по графу проектов, по такому пути не
  выбираются: их отслеживаемые входы (исходники, файлы проектов, входы evaluation) уже дают сигнал.
- Потребитель, который держит такую DLL ссылкой на файл без пути в графе проектов до производителя, по-прежнему
  выбирается при её изменении: граф проектов эту связь не видит.
- Продукт сборки без оставшихся владельцев не попадает ни в изменённые пути (и в счётчик файлов ответа), ни в
  «Not covered».
- Внешние DLL без производителя в solution (например, `lib/*.dll` в репозитории) обрабатываются как раньше.
- Карта входов и watcher не меняются: роль `Output` нужна им для других целей.
- Документация: README EN/RU, `AGENTS.md.sample`, ARCHITECTURE, CHANGELOG 1.7.1 — ограничение T09-C1 заменено правилом
  «сигнал дают написанные входы, а не продукты сборки»; ручной фильтр по-прежнему требует `noBuild: false`.
