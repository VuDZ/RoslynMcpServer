# Epoch 2 — Консервативный межпроцессный кэш

Статус: **proposed**. Требует завершённую Epoch 1.

## Задача

Пропускать MSBuild load после рестарта на неизменном, полностью поддерживаемом
графе. Любое значимое изменение даёт полный miss запроса. Per-project merge,
обновление состава документов по glob и stat-only shortcut не входят в эпоху.

## Алгоритм load

1. Нормализовать request identity и обновить сессионные настройки.
2. `forceReload=true` обходит RAM и диск. Иначе сохранить существующий RAM path
   с disk-sync и stale guard; не делать disk capture из непроверенного RAM-hit.
3. При RAM miss и useDiskCache проверить совместимость записи, поддержку графа,
   membership manifests, explicit dependencies и strict content hashes.
4. На полном совпадении гидратировать отдельного кандидата, проверить generation
   по контракту и опубликовать его. Зафиксировать disk-hit без вызова full DTB.
5. Любое сомнение — обычный MSBuild load. Не склеивать hydrated и stale проекты.
6. После успешного стабильного load поддерживаемого графа сохранить новое
   immutable поколение. Ошибка записи кэша не превращает успешный load в ошибку.

Capture разрешается лишь при подтверждённой полноте графа. Ошибки загрузки,
неразрешённые references и неполученные обязательные входы запрещают сохранение.
Допустимые предупреждения должны быть явно классифицированы в профиле.

## Реализация

- Сервисы key/DTO/probe/store через DI; тяжёлый I/O не помещать в tools.
- Реализовать `useDiskCache=false`, `forceReload=false` и metadata ответа согласно
  контракту. Reset очищает RAM; следующий load может получить disk-hit.
- SHA-256 всех значимых входов. Изменившийся только `.cs` тоже даёт miss в этой
  эпохе: простой безопасный baseline для следующих оптимизаций.
- Раздельные membership scan и explicit probes. Ограниченный I/O parallelism,
  первоначально не более 4 операций; отмена обязательна.
- Атомарное хранение, параллельные writers/readers, cleanup и corruption fallback
  входят в эпоху, а не откладываются после выпуска.
- Логировать reason, число проектов/входов, bytes hashed и времена
  probe/DTB/hydrate/publish. Не выводить environment secrets.

## Приёмка

- V01–V18, V23; отдельный процесс подтверждает hit с нулём DTB операций.
- Strict-проверка замечает замену содержимого при прежних size и mtime.
- Любое изменение значимого входа и новое членство дают обычный load.
- Force гарантированно обходит оба слоя. Диск недоступен — load работоспособен.
- Выполнен performance-gate Epoch 0. Если нет — opt-in остаётся экспериментальным,
  либо эпоха возвращается на revise. Default не включается автоматически.

## Handoff

`epoch-2-handoff.md`: схема, каталог, defaults, причины miss, поддерживаемый профиль,
процент hit на реальной нагрузке, результаты сбойных тестов и замеров. Прямо
указать, что улучшение живой синхронизации относится к следующей эпохе: существующий
stale hint не считается гарантией свежего графа на каждом semantic call.
