# Epoch 1 — Жизненный цикл и эквивалентная гидрация

Статус: **proposed**. Требует go Epoch 0. Production load остаётся обычным MSBuild.

## Задача

Отделить активную semantic solution и её сохранение от конкретного загрузчика.
Доказать, что новый workspace работает не только для чтения, но и для текущих
edit/refactoring инструментов. Не ограничиваться заменой типа поля на Workspace.

## Работа

- Ввести минимальную границу loader/capture/hydrator и владельца активной сессии.
  Сохранить один активный workspace; временный loader имеет отдельный lifetime.
- Реализовать DTO из контракта и гидрацию для профиля Epoch 0. Остальные профили
  возвращают unsupported до попытки публикации кандидата.
- Разделить базовую solution и analyzer overlay. Все semantic tool paths получают
  overlay; все пути применения изменений соблюдают защиту от записи shadow refs.
- Проаудировать UpdateDocumentInMemory, ApplySolutionChangesToDisk, disk sync,
  rename/code fixes и reset. Семантика записи не должна случайно зависеть от
  того, применяет ли конкретный Workspace изменения к `.csproj` на диске.
- Явно разделить отражение уже произошедшего disk change и пользовательскую
  правку проекта. Обнаружение нового файла scanner не разрешает переписывать
  `.csproj` через TryApplyChanges.
- Ввести единый notification path успешных собственных записей, пригодный для
  последующей инвалидации. Ошибка записи не считается новым подтверждённым входом.
- Сохранять несколько членств linked file и TFM contexts. Не выбирать только
  первый DocumentId или ближайший каталог проекта как доказательство членства.
- Кандидат публиковать целиком; cancellation/failure освобождает временные ресурсы
  и сохраняет прежнюю сессию, если она была. Состояние stale при этом не очищается.

## Приёмка

V01–V09: одинаковая семантика и поведение редактирования на обычном и
гидратированном workspace. Проверить файл после rename/AST edit, следующий
semantic call, последующую обычную сборку и неизменность analyzer refs в csproj.

Результат эпохи — внутренний механизм с проверками. Нет чтения production кэша,
новых tool names, lazy graph, отключения analyzers или изменения defaults.

## Handoff

`epoch-1-handoff.md`: границы ответственности, поддержанные поля, результаты
тестов, disposal/cancellation, доказательство отсутствия записанных overlay paths.
Любой потерянный compiler input блокирует переход к Epoch 2 для данного профиля.
