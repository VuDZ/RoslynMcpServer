## Как возникает отказ

В сервере есть два потребителя MSBuild с разными требованиями к runtime.

1. Дочерний `BuildHost` выполняет design-time build и передаёт данные проекта `MSBuildWorkspace` по RPC. Новый форк собран для `net8.0` с `rollForward=Major` и reference-пакетами MSBuild `17.11.48`. Фактический MSBuild и runtime в дочернем процессе зависят от потребительского SDK. [Происхождение форка](../../../forks/roslyn-buildhost/UPSTREAM.md).
2. Сам сервер создаёт `BinaryLogger` и читает binlog через `BinaryLogReplayEventSource`. Из записей он восстанавливает происхождение analyzer references и проверяет их перед публикацией workspace. Эти классы загружаются в процесс самого MCP-сервера. [Захват и чтение binlog](../../../Services/Analyzers/AnalyzerProvenanceCaptureService.cs).

При старте из каталога с точным `global.json` для `11.0.100` метод `MsBuildBootstrapper.RegisterCore` явно регистрирует MSBuild из этого SDK. В SDK `11.0.100` файлы `Microsoft.Build`, `Microsoft.Build.Framework`, `Microsoft.Build.Tasks.Core`, `Microsoft.Build.Utilities.Core` и `Microsoft.NET.StringTools` имеют версию `18.12.2.53018` и assembly reference `System.Runtime, Version=11.0.0.0`. Те же сборки SDK `10.0.402` имеют версию `18.9.15.50611` и ссылаются на `System.Runtime, Version=10.0.0.0`. [Регистрация MSBuild при старте](../../../Diagnostics/MsBuildBootstrapper.cs).

На серверном runtime `10.0.15` вызов `AnalyzerProvenanceCaptureService.OpenAndCaptureAsync` завершается `FileNotFoundException` для `System.Runtime, Version=11.0.0.0` до открытия проекта. Установленный рядом runtime 11 сам по себе не меняет runtime уже запущенного процесса.

## Сравнение B0, B1 и B2

На Windows x64 выполнено 72 запуска. Для каждой сборки на каждом контроле один прогрев и три измерения с новыми PID в чередующемся порядке, отдельно для cold и warm SQLite. На SmokeApp и решении сервера процесс регистрации MSBuild закреплён на `10.0.402`, на `Roslyn.slnx` на `10.0.301`. Фактический runtime сервера B0/B1 — `10.0.15`, B2 — `11.0.0`. Все три BuildHost-процесса в этих сериях использовали `11.0.0`. Собственные MSBuild Server процессы в выборке отсутствовали. Для всех 72 запусков подтверждены ожидаемое состояние кеша конкретного решения, загрузка, первая семантическая операция и завершение дочерних процессов. - На холодном `Roslyn.slnx` медианы загрузки плюс первый definition в первой серии — **60,46 с B0 → 55,76 с B1 → 59,81 с B2**. Эффект переноса Roslyn B1/B0 −7,77%.
