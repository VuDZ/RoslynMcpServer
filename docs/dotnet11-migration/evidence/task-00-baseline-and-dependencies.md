Время клиента включает синхронный WMI sampling при ожидании RPC. Server CPU — дельты kernel/user в окнах двух вызовов. CPU BuildHost — сумма последних наблюдённых накопленных значений его PID, нижняя оценка при завершении между отсчётами. Server peak берётся из kernel working set high-water mark, host peak — максимум суммы working set наблюдаемых BuildHost, tree peak — максимум одновременной суммы server+BuildHost. Сравнение B1/B2 требует того же инструмента и режима. [Расчёт агрегатов и сопоставление SQLite ключей](../../../artifacts/dotnet11-stage0-20261118/Get-Stage00B0Summary.ps1).

## Ревью и решение о порядке

Один раунд независимой сверки результатов. Внесены четыре уточнения: раскрыты SDK и первичные логи исторического macOS run, добавлена file version MSBuild для прямого результата reader, сверены точные ключи SQLite и добавлен solution-вариант SmokeApp, подтверждено baseline-поведение при обеих формах Windows `DOTNET_ROOT` с явным описанием ограничений sampler.

SDK gate пройден. На точных `10.0.100`, `10.0.300`, `10.0.402` и `11.0.100` новый клиент и поставляемый host выполнили штатные загрузку и семантические операции. Для отсутствующего точного SDK и для установки без SDK получены ожидаемые отрицательные результаты. Минимальная потребительская полоса остаётся нерешённой. В наблюдавшихся SDK‑10-only средах host работал на .NET 10, поэтому переход runtime до переноса Roslyn и форка не требуется.

Порядок плана сохраняется: этап 1 переносит Roslyn и форк согласованно на `net10.0`, этап 2 переводит runtime сервера, этап 3 подтверждает поставки и откат. Этапы 1–3 имеют статус `planned`. Полноценный product smoke SQLite, новый форк, watch/reload и generator admission, проверки MSBuild Server на остальных ОС и новый нативный macOS candidate smoke относятся к своим этапам. Частное офисное решение осталось недоступным. [План](../README.md), [матрица и границы кандидатного прогона](task-00-candidate-matrix.md), [нерешённый минимум](../UNRESOLVED-v2.md).
