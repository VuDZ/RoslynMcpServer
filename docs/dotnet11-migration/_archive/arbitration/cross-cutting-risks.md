# Связи принятых правок

Дата: **2026-11-18**. По отдельности правки совместимы. Ниже места, где их легко собрать в противоречие.

## Корневой SDK 11 и строки потребительского SDK 10

R-01 закрепляет сборку репозитория точным SDK 11 с `rollForward` `disable`. R-02 требует отдельные живые строки `10.0.1xx`, `10.0.300` и `10.0.4xx`. NEW-ARB-001 не даёт корневому файлу стать pin этих строк.

Если ревизия плана выполнит только R-01, `dotnet` из корня и любая фикстура без более близкого `global.json` начнут доказывать SDK 11. Строка «прежний SDK 10 сохранён» тогда будет зелёной без прежнего сценария. Обратная ошибка — оставить корневой `latestFeature`, чтобы «не сломать SDK 10»: проект `net11.0` снова не соберётся. Нужны оба pin, и для каждой строки в отчёте назван тот файл, который реально оказался ближайшим.

Копия корневого файла в `RawImportEvidenceFixture` следует за R-01 и не подменяет строки R-02.

## Нерешённый минимум и запрет тихого сужения

R-02 разрешает этапу 0 остановиться, но не разрешает ему вычеркнуть полосу. Пока `unresolved.md` открыт, этапы 1–3 не получают формулировку «поддерживается SDK 10.0.4xx и новее» и не переписывают `PinnedSdk` `10.0.300`. Историческая фикстура и публичное обещание остаются разными графами: отказ фикстуры записывается как отказ или pending, даже если владелец позже сузит обещание, и сужение обещания не требует ради зелёного прогона сменить константу фикстуры.

Зависимость клиента от Framework 18.7.1 не является поводом на этапе 1 сменить `MsbuildReferenceVersion` форка. Такая замена сломает сборку host: у пакета 18.7.1 нет `ref/net8.0`. Она же создаст ложный пол runtime и подтолкнёт к запрещённому минимуму `10.0.4xx`.

## Runtime сервера и runtime host

R-01 и этап 2 переводят сборку, а затем TFM сервера на .NET 11. Поставляемый host кандидата остаётся `net8.0` с `rollForward` `Major`. Пункт 6 этапа 2, запрещающий переводить host на `net11` за компанию, после этой сверки становится только жёстче. Smoke этапа 3 по-прежнему показывает фактический framework процесса. Запись «host теперь требует shared runtime 11» допустима только если процесс действительно его потребовал. Иначе самодостаточный сценарий SC с SDK 10 и без shared runtime 11 нельзя заранее объявить сломанным и нельзя заранее объявить доказанным.

## MSBuild Server, чужие процессы и замеры

G-01 добавляет наблюдение сервера сборки и возможный opt-out только дочернему процессу. Тот же контракт запрещает reaper и `dotnet build-server shutdown` завершать чужие серверы. Расширение reaper «чтобы gate стал зелёным» нарушает уже принятую границу чужих сессий и подменяет наблюдение убийством процесса.

Opt-out меняет переиспользование MSBuild между запусками. Серии B1/B2 и stock/fork тогда перестают отличаться только runtime или форком. Правило одного записанного режима в разделе замеров обязательно, иначе порог 5/10 процентов будет приписан не той причине. Отключение analyzers, смена GC или числа worker по-прежнему не маскируют регрессию.

## Языковая фикстура и язык сервера

R-03 добавляет библиотеку `netstandard2.0` с `LangVersion` 15 в матрицу этапов 1–2 и в smoke этапа 3. Этап 1 ещё держит собственные исходники на C# 14 и `net10.0`. Фикстура — проект пользователя, её наличие не поднимает `LangVersion` сервера и не требует runtime `net472` на Linux и macOS. Пять конструкций `net11` и исключение memory-safety preview остаются рядом, а не вместо неё.

## Документация, которая врёт после правки pin

После R-01 фраза ARCHITECTURE об отсутствии корневого `global.json` станет вдвойне неверной. Её исправление назначено этапу 3 и не объявляет AR-18 закрытым. Если синхронизацию выкинуть, следующий проход снова примет устаревший абзац за состояние дерева, то есть повторит исходную ошибку R-01. Исторический `evidence/preparation-2026-11-18.md` при этом не переписывать: он фиксирует подготовку, а не новый baseline.
