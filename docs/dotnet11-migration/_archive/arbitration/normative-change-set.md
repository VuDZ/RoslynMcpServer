## G-01. MSBuild Server

### `README.md`, раздел «Матрица совместимости», абзац об отмене и оставшихся BuildHost

Добавить отдельное наблюдение, не заменяя им текущие правила BuildHost и чужих сессий.

- Различать workspace BuildHost, MSBuild worker (`/nodemode:1`) и MSBuild Server (`dotnet`, `MSBuild.dll`, `/nodemode:8`).
- После build/test, отмены, timeout, неуспешной сборки и shutdown записать, был ли сервер создан, переиспользован или не запускался: PID, командная строка, время старта. Учитывать окружение, унаследованное дочерним процессом.
- Ноль процессов BuildHost не является PASS этого наблюдения.
- Пока прогон на SDK 11 не показал, что уже стоящий `MSBUILDDISABLENODEREUSE=1` не оставляет постоянный сервер, дочерние команды CLI получают `DOTNET_CLI_USE_MSBUILD_SERVER=false` и только его. Если унаследованный `MSBUILDUSESERVER` при этой переменной всё ещё поднимает сервер, тому же дочернему процессу ставится и `MSBUILDUSESERVER=0`. Окружение машины не изменять. Если прогон доказал достаточность текущего флага, второй механизм не добавлять.
- `dotnet build-server shutdown` не вызывать в поставке и не считать доказательством. В изолированной тестовой среде команда допустима только после записи наблюдения и не превращает неуспех в PASS.
- Источники поведения — страница нового SDK .NET 11 (разделы про MSBuild Server и про переменные окружения) и страница MSBuild Server. Список breaking changes .NET 11 этого пункта не содержит; ссылки этапа 2 на один этот список недостаточно.
