# Нерешённое

Дата: **2026-11-18**.

## Минимальная поддерживаемая полоса потребительского SDK не выбрана

Арбитраж не снимает поддержку `10.0.1xx`, точного `10.0.300` или `10.0.4xx` и не назначает `10.0.4xx` новым минимумом.

Что уже известно и решением не является:

- Клиент `Microsoft.CodeAnalysis.Workspaces.MSBuild` 5.12.0 зависит от `Microsoft.Build.Framework` 18.7.1.
- Host этого пакета в commit `1324e1d` ссылается на MSBuild `17.11.48` и поставляется как `net8.0` с `rollForward` `Major`.
- У пакетов MSBuild 18.7.1 нет `ref/net8.0`, поэтому номер зависимости клиента нельзя переносить на reference-пакет форка.
- По таблице SDK MSBuild 18.0, 18.6, 18.9 и 18.12 стоят в разных feature band. Числовое сравнение 18.0 и 18.6 с 18.7.1 не является наблюдаемым отказом сервера.

Чего нет:

- Скачанный на этапе 0 прогон загрузки и семантических операций новым клиентом и новым host на точном `10.0.100`, точном `10.0.300` и точном `10.0.402`, с записанными путём MSBuild и ближайшим `global.json`.
- Решение владельца, если какая-либо из этих ранее положительных строк не проходит.

Пока нет прогона и, при отказе строки, решения владельца, этапы 1–3 не получают права сузить матрицу. Допустимые продолжения после появления evidence записаны в `normative-change-set.md`: подтвердить прежний профиль, остановиться на no-go либо принять отдельно названное владельцем сужение. Исполнитель сужение сам не выбирает.

Других нерешённых развилок арбитраж не оставляет. Вопрос, гасит ли `MSBUILDDISABLENODEREUSE=1` MSBuild Server на SDK 11, является прогоном уже принятого gate G-01, а не открытым выбором конструкции.
