## Принятые правки

### Корневой pin репозитория

Finding ID: **R-01** (`ACCEPT`).

- В отправной точке назван фактический корневой `global.json`: с commit `59f6936`,
  `version` `10.0.100`, `rollForward` `latestFeature`, `allowPrerelease` false.
  `latestFeature` не переходит на SDK 11. Пока установлен SDK 10.0 не ниже `10.0.100`,
  файл не собирает `net11.0`.
- Описано поведение `GlobalJsonSdkReader`: поля `rollForward` и `allowPrerelease` не читаются;
  существующая папка названной версии возвращается сразу; префикс `10.0.100.` не покрывает
  `10.0.402` и `11.0.100`. Reader не исполняет `latestFeature`. При установленной папке
  `10.0.100` reader держит её, а CLI может уйти на более высокий band `10.0`.
- Сохранены текущие факты CI и release: канал `10.0.x` без `global-json-file`;
  release перезаписывает checkout на `10.0.402` и `rollForward` `disable`.
  Выбор CLI в test-suite всё равно делает корневой файл.
- Этап 0 включает этот файл и расхождение reader/CLI в baseline. Поддержка `latestFeature`
  reader не приписывается.
- Этап 2 обновляет существующий корневой файл на один точный стабильный SDK 11,
  `rollForward` `disable`, `allowPrerelease` false. `11.0.100` остаётся кандидатом.
  В файл попадает номер, установленный на Windows x64, Linux x64 и macOS ARM64.
  Плавающий `11.0.x` при `disable` не используется.
- CI ставит этот точный номер и отдельно SDK 10 строк матрицы. Release записывает
  тот же номер и `disable`. Перезапись checkout допустима, расхождение с корнем — нет.
- Приёмка pin: одновременно SDK 10, точный SDK 11 и более новый SDK 11 дают один toolchain
  без ложного `MCP_MSBUILD_SDK_MISMATCH`. Нет точного SDK — явный отказ без подмены номера.
- Чтение `rollForward` не реализуется. AR-18 не закрывается. Пользовательские `global.json`
  вне репозитория не переписываются.
- Устаревшая фраза `docs/ARCHITECTURE.md` об отсутствии корневого файла исправляется
  на этапе 3 и в этой ревизии плана не правится. Исправление не объявляет AR-18 закрытым.

### Полосы SDK, reference-пакет host и gate этапа 0

Finding ID: **R-02** (`ACCEPT WITH MODIFICATION`).

- Единая строка «SDK 10» заменена несводимыми случаями: точный `10.0.100` (`10.0.1xx`,
  MSBuild 18.0), точный `10.0.300` с `rollForward` `disable` (MSBuild 18.6, фикстура
  `RequiresPinnedSdk`), точный `10.0.402` (`10.0.4xx`, MSBuild 18.9), точный SDK 11
  репозитория (MSBuild 18.12 у `11.0.1xx`), а также среды «обе версии», «только SDK 10»,
  «только SDK 11», отсутствующий закреплённый SDK и отсутствие SDK.
- У каждого случая записываются номер или band, `rollForward`, фактические версия и путь
  MSBuild, ближайший `global.json`, рабочий каталог и результат. Прогон на `10.0.402`
  не закрывает `10.0.1xx` и `10.0.300`. Строка `10.0.300` остаётся результатом исторической
  фикстуры, а не публичным обещанием самой по себе.
- В отправной точке записан состав кандидата 5.12.0: зависимость клиента
  `Microsoft.Build.Framework` 18.7.1, commit `1324e1d`, host `_MsbuildVersion` `17.11.48`,
  `runtimeconfig` `net8.0` / `8.0.0` / `rollForward` `Major`, отсутствие `ref/net8.0`
  у пакетов MSBuild 18.7.1. Эти факты не являются пройденным этапом 0.
  Из `runtimeconfig` не выводится требование shared runtime 11 для дочернего host.
- Этап 0 различает три профиля: compile-time клиента, reference-пакет форка
  (четыре `Reference` на `ref\net8.0`, `MsbuildReferenceVersion`, PackageDownload)
  и MSBuild, который Locator загружает из SDK. Правило Locator применяется только
  к компоненту, который компилируется против пакета и загружает его через Locator.
- Этап 1 берёт четыре `Reference` и `MsbuildReferenceVersion` из inventory этапа 0.
  Пока upstream host остаётся на `17.11.48` и `net8.0`, пути не меняются на пакет 18.7.1.
  Если проект host сам меняет версию или TFM, новый путь должен существовать в пакете,
  а выход host не копирует MSBuild.
- Этап 2 не переводит BuildHost на `net11` вместе с сервером. `runtimeconfig` кандидата
  это правило подтверждает. Смена TFM host — только с отдельной причиной, сравнением
  и повторением RPC/scenario gates.
- У этапа 0 три несводимых исхода полос: подтвердить прежний профиль прогоном каждой
  строки; при отказе ранее положительной строки остановиться до решения владельца;
  не называть несовместимость полосы или MSBuild требованием runtime 11.
  Смена порядка этапов из-за runtime host остаётся отдельно доказанным исходом.
  Для кандидата 5.12.0 одного `runtimeconfig` недостаточно.
- `PinnedSdk.Version` `10.0.300` не меняется. Фикстуры `RequiresPinnedSdk` не становятся
  обязательным положительным public-support gate. Отказ фикстуры остаётся отказом или pending.

### MSBuild Server

Finding ID: **G-01** (`ACCEPT WITH MODIFICATION`).

- В матрице и в native smoke этапа 3 различаются workspace BuildHost, worker `/nodemode:1`
  и MSBuild Server (`dotnet`, `MSBuild.dll`, `/nodemode:8`).
- После build/test, отмены, timeout, неуспешной сборки и shutdown записываются создание,
  повторное использование или отсутствие сервера: PID, командная строка, время старта,
  включая унаследованное окружение. Ноль BuildHost не является PASS. Непроверенный
  результат не является PASS.
- Сначала прогоняется текущий runner. Пока прогон на SDK 11 не показал, что
  `MSBUILDDISABLENODEREUSE=1` не оставляет постоянный сервер, дочерний процесс получает
  `DOTNET_CLI_USE_MSBUILD_SERVER=false`. Если унаследованный `MSBUILDUSESERVER` при этом
  всё ещё поднимает сервер, тому же процессу ставится `MSBUILDUSESERVER=0`.
  Окружение машины не меняется. Доказанная достаточность текущего флага второй механизм
  не добавляет. `/nr:false` допустим только если названные переменные сервер не гасят,
  а ключ гасит.
- `dotnet build-server shutdown` не входит в поставку, не считается доказательством
  и не превращает неуспех в PASS. В изолированной тестовой среде команда допустима
  только после записанного наблюдения.
- Обязательные источники — разделы страницы нового SDK .NET 11 про MSBuild Server
  и про переменные окружения, и страница MSBuild Server. Список breaking changes .NET 11
  этого пункта не содержит. Этап 2 повторяет затронутые тесты окружения и отмены.
- B0, B1, B2 и серии stock/fork сравниваются в одном записанном режиме MSBuild Server.
  Смена opt-out требует повторного снятия сравниваемых серий. Тёплый сервер не относится
  к эффекту runtime или форка.
- Reaper не расширяется на произвольные `dotnet`, MSBuild Server и worker nodes.
  Чужие серверы сборки и BuildHost другой сессии не завершаются.
- План не утверждает, что текущий runner уже оставляет сервер и блокирует publish.

### Статический член интерфейса на старом TFM

Finding ID: **R-03** (`ACCEPT`).

- Пять конструкций на `net11` сохранены. Memory-safety preview по-прежнему не входит
  в обещание.
- В языковую строку добавлена библиотека `netstandard2.0` с явным `LangVersion` `15.0`,
  невиртуальным статическим методом интерфейса с телом и вызовом на типе интерфейса.
  Ожидание: нет `CS8701`, символ привязан к члену, definition и references доступны,
  effective language version `15.0` не подменён default TFM. Тот же исходник на языке 14
  воспроизводит прежнее ограничение. Запуск `net472` на Linux и macOS не требуется.
- Случай не обещает instance default implementation, `static abstract`, `static virtual`
  и protected-члены интерфейса. Он не поднимает `LangVersion` исходников сервера раньше этапа 2.
- Матрица действует на этапах 1–2. Этап 3 включает семантический smoke случая,
  пока он остаётся частью обещания C# 15: символ и отсутствие `CS8701`, не только
  успешный `load_workspace`.

### Ближайший pin потребительской строки

Finding ID: **NEW-ARB-001** (`ACCEPT`). Совместно с **R-01** и **R-02** там, где pin
репозитория и полосы SDK встречаются в одном запуске.

- Для потребительской строки ближайший `global.json` к фактическому рабочему каталогу CLI
  и к каталогу, от которого сервер ищет pin, — файл этого случая. Корневой pin SDK 11
  строку не закрывает. Запуск из корня не доказывает файл, лежащий ниже корня.
- В отчёт входят путь `dotnet`, версия SDK и путь MSBuild этого запуска.
  `dotnet --version` в корне репозитория строку не закрывает.
- `RawImportEvidenceFixture` после смены pin остаётся слепком toolchain репозитория.
  Этап 2 обновляет её ожидания явно. Её результат не доказывает строки `10.0.1xx`,
  `10.0.300` и `10.0.4xx`.
- Правило действует на матрице этапа 1, на проверках этапа 2 и на потребительских
  запусках smoke этапа 3. `RawImportEvidenceFixture` не доказывает эти строки и на этапе 1:
  она копирует корневой pin. Пользовательские файлы вне репозитория не переписываются.

## Закрытые рекомендации

Полных `REJECT` нет. Следующие рекомендации в v2 не исполняются.

- **R-01.** Предварительно закрыть AR-18 и только потом разрешить нестрогий pin.
  Для миграции выбран точный SDK 11 с `rollForward` `disable`. Реализация политик
  `rollForward` в объём не входит.
- **R-02.** Считать пол `Microsoft.Build.Framework` 18.7.1 доказанным отказом runtime
  на MSBuild 18.0 и 18.6. Назначать минимум SDK 10 равным `10.0.4xx`. Разрешать этапу 0
  самому отказаться от `10.0.1xx` и от `10.0.300`. Переводить PackageDownload и
  `ref\net8.0` форка на пакет 18.7.1 из-за зависимости клиента. Менять `PinnedSdk.Version`
  ради зелёного прогона. Объявлять фикстуры `RequiresPinnedSdk` обязательным положительным
  public-support gate. Выводить требование runtime 11 для host из этих пакетов.
- **G-01.** Сразу вписать opt-out, не оставив прогона текущего флага. Утверждать, что
  утечка сервера и блокировка publish уже воспроизведены. Считать ноль BuildHost достаточным.
  Вызывать `dotnet build-server shutdown` как доказательство или как очистку поставки.
  Расширять reaper на произвольные процессы `dotnet`. Добавлять `/nr:false` вместе
  с переменными без прогона, который показал необходимость ключа.
