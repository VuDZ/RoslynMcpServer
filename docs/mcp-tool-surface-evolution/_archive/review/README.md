# Review: falsification of MCP tool surface evolution

Дата: 2026-09-19. Каталог содержит замечания к спецификации, не изменения реализации.

Сверка: рабочее дерево на commit `b9f2e02589b229f60d50b4ead5d535ce5b04b7b6`,
сервер **1.3.24**, Roslyn **5.9.0**, MCP SDK **1.3.0**. Проверены каталог,
схемы/адаптеры navigation и rename, published-snapshot accessors, существующие
catalog tests, packaging и история удалённого CI workflow. Документы темы
и входящий `roslyn_mcp_tool_review.md` на момент проверки ещё не отслеживаются
Git; версия commit фиксирует baseline кода, а не содержимое этих документов.

Цель ревью — опровергнуть предложенную архитектуру, а не улучшить её изложение.
План и production-код не изменены.

реализации с текущим контрактом идентичности. Замечания не требуют отменять
перенос двух tools в Stage 1 или преждевременно реализовывать v2.

## Проверка доказательств

Через `run_dotnet_run` выполнен изолированный probe вне репозитория с DLL
из NuGet cache **5.9.0**, на Windows x64 / SDK **10.0.204**. Exit code **0**,
stderr пуст; все четыре проверяемые C#-компиляции без ошибок. Подтверждено:

1. `SymbolKey.IsVisible=False`.
2. Одинаковые ключи для `N.C.M` из двух независимых компиляций с одной
   assembly identity; ключ из `A.cs` успешно разрешается в метод из `B.cs`.
3. После вставки соседней одноимённой локальной функции старый ключ
   разрешается в добавленную функцию, а не в исходную.

Минимальный код probe и результаты приведены в Evidence E2-03;
reflection используется только для исследования непубличного Roslyn API,
не предлагается как уже принятое production-решение.

Полный test suite, lifecycle integration tests, CI и будущие Stage 1/2
не запускались: это ревью плана. Анализ существующих тестов не выдаётся
за их успешный прогон. Исправления требований должны получить собственные
acceptance tests; текущие примеры Stage 2 не проверяют найденные случаи.
