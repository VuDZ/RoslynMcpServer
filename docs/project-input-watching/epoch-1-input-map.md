# Эпоха 1. Карта входов и принадлежности

Статус: **не начата**. Сложность: средняя; полный MSBuild input scope сложнее.

## Цель

Получить проверяемую карту физических входов загруженного графа, не
приравнивая дерево каталогов `.sln` к составу проектов.

Форма общего состояния и pull API уже выбрана в
[input-state-contract.md](input-state-contract.md). Эта эпоха определяет
источник evidence и модель данных; не проектирует независимую ленту для
test-build-freshness. Generation совпадает с token WPF watcher-сессии.

## Работа

- Построить обратный индекс: canonical path → набор project instances,
  `DocumentId` и ролей. Сохранять все вхождения; сравнение путей соответствует ОС.
  Проверить правила aliases/symlinks; недоказанное соответствие не объединять.
- Индекс строится только по фактически загруженным instances. Обычная загрузка
  внутреннего TFM не даёт автоматически второй instance того же `.csproj`.
  Условные входы другого TFM, не подтверждённые этим графом/evidence, переводят
  покрытие всего графа в unknown. Нельзя объявлять multi-TFM coverage полным
  по данным одного TFM.
- Использовать оценённую принадлежность проекта, а не разбор только явных
  `<Compile Include>`: SDK globs, linked пути и условия уже влияют на состав.
- Разделить известные пользовательские входы, области потенциального membership
  и роль `generated`: intermediates/outputs с подтверждённым производителем.
  `.g.cs` и generated AssemblyInfo в Compile не становятся пользовательскими
  inputs только по этому факту; путь внутри `obj`/`artifacts` тоже роли не доказывает.
  Сохранить явный пользовательский input в этих деревьях при evidence его роли.
  Для смешанных ролей хранить производителя и потребителей раздельно;
  неизвестная provenance/роль означает unknown, а не blanket ignore.
- Определить источник правил появления новых файлов и импортов: доступные
  публичные MSBuild данные или ограниченный подтверждённый профиль. Если
  полноценные правила получить нельзя, обозначить conservative regions и
  неизвестную полноту, а не выдавать индекс документов за полную карту.
- Проверить `.cs`, XAML, ресурсы, AdditionalFiles, analyzer configs, imports,
  walk-up props/targets/global.json, restore inputs и project references.
  Для каждой категории зафиксировать источник данных, событие, владельцев
  и ограничения. Список расширений не заменяет роли файла.
- Описать watcher plan отдельно от search roots: каталог, recursion, точечные
  пути/фильтры, роли и completeness evidence. Внешний файл и walk-up props/import
  требуют нерекурсивного watcher на каталог самого файла или точечной подписки.
  Запретить рекурсивные ancestor roots и объединение, расширяющее их охват.
  Рекурсивные membership regions разрешены внутри project directories.
  Внешние рекурсивные globs без доказанной полноты остаются unknown.
- Состояние absent walk-up input и возможность появления новых файлов входят
  в evidence. Отсутствие пути в индексе известных документов не подтверждает
  отсутствие membership, особенно для нового `.cs` под SDK project directory.
- Выбор [W-01](UNRESOLVED.md) закрыт: одна карта ролей C# и обнаруженных не-C#
  inputs, text sync только пользовательского C#, остальные роли дают уведомление
  и unknown при недостатке evidence. Закрыть W-02 по источнику membership и
  явно проверить полноту supported profile. Неподтверждённые категории/metadata-only
  зависимости не исключаются из отчёта ради заявления о полном покрытии.

## Проверки

Fixture включает Solution в отдельной папке, внешний проект, linked-файл
в третьей папке, общий путь в двух проектах, Compile Remove, внешний glob,
ancestor props и условный project reference. Проверить внешний reference,
который доступен как metadata, но отсутствует в загруженном Roslyn-графе:
такое покрытие не считается полным.

Один путь с разными ролями сохраняет все роли; новые glob-items не теряются.
Проверить generated `.g.cs`/AssemblyInfo, явный пользовательский input в `obj`
и неоднозначную роль. Ancestor props на три уровня выше не добавляет рекурсивную
подписку на чужое дерево; отсутствующий props и внешний glob проверяются отдельно.

Неполная/ошибочная загрузка не публикует индекс как полный. Обязательная
multi-TFM проверка: один реально загруженный TFM и неподтверждённые условные
входы другого → unknown на весь граф. Fixture с двумя instances одного `.csproj`
допустим только когда production load/evidence действительно даёт оба в графе;
искусственная модель не доказывает такое покрытие обычной загрузки.

## Результат и переход

В отчёте закрепить модель, источник MSBuild evidence, supported/unknown
категории и выбранное grouping watchers. Следующая эпоха использует эту карту.
Она не начинает свою вторую модель принадлежности по каталогам.

Для каждого внешнего linked/input path отчёт указывает нерекурсивную подписку
на каталог файла/точечное наблюдение либо coverage unknown, если это недоступно.
Факт доставки события через широкий рекурсивный ancestor watcher приёмку
не проходит. Урезанный профиль можно описать как частичный результат, но
unknown за его пределами нельзя объявлять complete для всего целевого графа.
