# Приоритетные исправления AR-02, AR-18 и AR-09

**2026-11-21. Исходная проверка на `6d88c97` (1.6.1).** Выполнена Release-сборка
сервера. AR-02 проверен по коду, AR-18 и AR-09 воспроизведены через MCP на Windows.
Статусы находятся в [реестре](README.md).

## AR-02. Источники настроек плагинов

При старте сервер читает `RoslynMcp.jsonc` после определения рабочего каталога.
Настройка `plugins` из этого каталога подменяет список из конфигов exe и пользователя.
Загрузка плагинов происходит до первого `tools/list`.

Условия приёмки [P-01](proposals.md#p-01) — список плагинов берётся из доверенных
источников. Наличие `plugins` в отдельном конфиге рабочего каталога не заменяет этот
список, в том числе если локальный массив пуст. Сервер объясняет игнорирование в
стартовой диагностике. Остальные локальные настройки и явный `ROSLYN_MCP_PLUGINS`
продолжают работать.

## AR-18. Единый выбор SDK

При `sdk.version: 10.0.301` и `rollForward: latestFeature` CLI выбрал `10.0.402`,
а сервер закрепил MSBuild `10.0.301`. `run_dotnet_build` вернул `Build failed` и
`MCP_MSBUILD_SDK_MISMATCH` при коде процесса `0`. Прямая сборка прошла.
Контроль с `10.0.402` и `rollForward: disable` прошёл и через MCP.

Условия приёмки — загрузка, дочерние команды и диагностика используют результат
резолвера `dotnet` для нужного каталога. Разрешённое продвижение SDK проходит
без ложной ошибки, строгий pin и реальные несовпадения по-прежнему различимы.

## AR-09. Оценённые свойства в list_projects

На проекте, который получает свойства только из `Directory.Build.props`,
MSBuild вернул `TargetFramework=net10.0` и `OutputType=Library`. `list_projects`
показал `(unknown)` для обоих, хотя проект загрузился.

Условия приёмки — свойства из импорта и условий соответствуют оценке загруженного
проекта. Мультитаргетинг учитывает выбранный вариант. При отсутствии подтверждённых
сведений инструмент явно сообщает `(unknown)`.

## Реализация в worktree

- **AR-02.** `plugins` читается из конфигов рядом с exe и в каталоге пользователя.
  Явный `ROSLYN_MCP_PLUGINS` действует по-прежнему. Если отдельный конфиг рабочего
  каталога содержит `plugins`, сервер игнорирует значение и предупреждает в stderr
  и логе. [Настройка плагинов](../setup.ru.md)
- **AR-18.** Дочерние команды учитывают политику `global.json` через выбранный `dotnet`.
  Сборка и повторные шаги используют один результат разрешения SDK в рамках общего
  бюджета. Диагностика показывает запрошенную и выбранную версии, а health сообщает
  путь зарегистрированного MSBuild. При запуске Locator выбирает из обнаруженных
  совместимых установленных SDK. [Регистрация MSBuild](../ARCHITECTURE.md#deployment-and-compatibility)
- **AR-09.** `list_projects` получает TFM при загрузке Roslyn, а `OutputType` из того
  же оценённого экземпляра проекта в BuildHost. Данные привязаны к `ProjectId` и
  сохраняются вместе со снимком запрошенной загрузки. При отсутствии данных от
  BuildHost сохраняется известный TFM, а `OutputType` выводится как `(unknown)`.
  [Описание инструмента](../tools.ru.md)

## Проверка

**2026-11-21. AR-02, AR-18 и AR-09 приняты в worktree `codex/architecture-review-fixes`**
от `6d88c97`. По каждому исправлению проведено независимое ревью. Повторное ревью
AR-18 подтвердило общий таймаут и выбор хоста при отдельной установке runtime.
Повторное ревью AR-09 подтвердило привязку ответа к собственной загрузке и чтение
оценённого `OutputType` из BuildHost.

- **Windows, SDK 10.0.402.** Release-сборка решения, 2723 теста основного набора
  (2574 в основном шарде и 149 в `TiaIntegration`), отдельно 128 `SourceStructure`
  и 13 `AnalyzerLifecycle`. Все тесты прошли.
- **Ubuntu 24.04 под WSL2, SDK 10.0.404.** Release-сборка решения, 2712 тестов
  основного набора (2563 в основном шарде и 149 в `TiaIntegration`), отдельно
  128 `SourceStructure` и 13 `AnalyzerLifecycle`. Все тесты прошли.

В итоговых TRX нет пропусков. Использованы штатные фильтры CI. Тесты категории
`RequiresPinnedSdk` исключены из основного набора, в Linux дополнительно исключены
тесты категории `RequiresWindows`. `AnalyzerLifecycle` запускался с
`ROSLYN_MCP_ANALYZER_LIFECYCLE=1`.

Сквозной прогон MCP через stdio на обеих платформах подтвердил загрузку и сборку
с политиками `latestFeature`, `patch`, `latestPatch` и `disable`, свойства из
`Directory.Build.props`, выбранный TFM `net10.0-windows` и игнорирование `plugins`
из рабочего каталога с сохранением доверенной настройки и обычных ключей cwd.
Девять целевых тестов AR-09 на Windows отдельно подтвердили конкурентную загрузку,
отсутствующее или нестандартное значение `OutputType` и отказоустойчивое чтение метаданных.
