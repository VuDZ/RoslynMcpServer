## P-01 · Доверие к `RoslynMcp.jsonc` из репозитория (AR-02)

1. **Рекомендуется:** ключ `plugins` читается только из каталога exe и
   `ROSLYN_MCP_PLUGINS`; в cwd-конфиге игнорируется с предупреждением в stderr/логе.
   Остальные ключи cwd-конфига (`configuration`, `max-results`, …) остаются.
2. Оставить как есть и записать в ARCHITECTURE (инвариант 12), что содержимое
   открываемого репозитория считается доверенным, включая загрузку плагинов при старте.
3. Разрешать `plugins` из cwd только при явном opt-in переменной окружения.

## P-02 · Размещение экспериментального StateCache (AR-05)

1. **Рекомендуется, пока эксперименты продолжаются:** код не переносить; одна строка в
   ARCHITECTURE («`Services/Workspace/StateCache/` — эксперимент, production-вызовов
   нет»); структурный тест «из production-кода нет обращений к `StateCache`» — снимается
   осознанно при интеграции.
2. Вынести в отдельный проект, на который ссылаются только тесты. Чище, но требует
   переноса internals и правок структурных тестов, которые анализируют production-дерево.
3. Если направление закрывается — удалить код, сохранив выводы в
   `docs/workspace-state-cache/`.

Во всех вариантах: записать в теме, где эксперименты упёрлись и что продолжается.

## P-03 · Поддерживаемые платформы (AR-12)

1. **Рекомендуется:** Linux-job для шарда `unit` (WPF-тесты исключить категорией, а не
   skip'ом, чтобы не конфликтовать с `Assert-NoSkippedTests.ps1`); релиз Linux —
   отдельным решением позже.
2. Официально объявить продукт Windows-only и сократить `RuntimeIdentifiers`.
3. Оставить как есть, явно указав в README «не-Windows не тестируется».

Решение (2026-10-21): расширенный вариант 1 — поддерживаются `win-x64` и `linux-x64`; обе платформы в CI (`unit` и `lifecycle`), красный job любой из них блокирует релиз; релиз выкладывает архивы обеих; остальные RID собираются, но не поддерживаются (arm — позже); реализация — [linux-x64-support](../linux-x64-support/README.md).
