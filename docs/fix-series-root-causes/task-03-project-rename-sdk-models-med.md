## Серия

P1-03, P1-23, P2-27, P1-32, P2-43, P1-51 из [ревью 25 ноября](../project-review-2026-11-25/README.md).

## Причина серии

[ProjectRenameHelper.cs](../../Services/Editing/ProjectRenameHelper.cs) повторяет семантику SDK и MSBuild вручную на `XmlDocument` и регулярных выражениях:

- в `.slnx`: имена элементов без учёта регистра, вложенность `Folder`, `BuildDependency`, границы модели для расширений (P1-23, P1-32, P2-43);
- в `.sln`: строки проектов разбираются регулярным выражением;
- в `ProjectReference`: операции `Include`, `Update` и `Remove` (P1-51).

Каждый раунд добавлял ещё одну часть семантики. Раундов меньше, чем в [task-01](task-01-source-write-representation-hi.md) и [task-02](task-02-test-results-from-trx-hi.md), поэтому приоритет ниже.

## Spike

Ответить на вопросы и записать результат в `evidence/`:

1. Сохраняет ли `Microsoft.VisualStudio.SolutionPersistence` при чтении и записи `.slnx` и `.sln` форматирование, комментарии, незнакомые элементы и атрибуты расширений. Этой библиотекой пользуются `dotnet sln` и MSBuild. Проверить, доступна ли она через текущую зависимость `Microsoft.Build` 18.7.1 или нужна отдельная ссылка.
2. Сохраняет ли `ProjectRootElement` с `preserveFormatting: true` форматирование `.csproj` при изменении `Include` и `Update` у `ProjectReference`.
3. Даёт ли модель позиции элементов (`Location`), достаточные для точечной текстовой правки.

## Варианты

| | A. Библиотеки для чтения и записи | B. Модель для чтения, точечная правка текста | C. Своя модель XML |
|---|---|---|---|
| Суть | Модель SolutionPersistence и `ProjectRootElement` читают и пишут файлы | Модель определяет, какие ссылки менять. Запись правит только значения атрибутов в исходном тексте по позициям | Как сейчас: семантика повторяется вручную со ссылками на SDK |
| Плюсы | Семантика совпадает с SDK | Семантика SDK и минимальный diff | Нет новых зависимостей |
| Минусы | Возможна потеря форматирования, ответ даст spike | Нужны точные позиции элементов | Новые расхождения с SDK |

**Рекомендация по результатам spike:** B для всех трёх форматов. Полная сериализация теряет данные расширений переименованного проекта в `.slnx`. Точечные правки дали ожидаемые байты во всех проверенных представлениях. [Основание решения](evidence/task-03-project-rename-sdk-spike.md#рекомендация-o-03)
