## Red

На B ожидаемо упали 7 случаев для сохранения UTF-8 без BOM, объявления через `.editorconfig` и `RoslynMcp.jsonc` и подсказки при добавлении BOM. На отдельной копии `3be841d` с новыми фикстурами ожидаемо упали ещё 11 случаев для R-1, R-2 и `#!`. Старая реализация либо отказывала по общему правилу B, либо сохраняла представление с BOM при полной записи. Она также отказывала не-ASCII в скриптах.

## Реализация

Оба текстовых инструмента используют одно правило выбора кодировки. BOM обычного исходника сохраняется. Для нового файла или файла без BOM применяется актуальное объявление `charset` либо `sourceEncoding`. При отсутствии объявления D сохраняет кодировку не-ASCII вне патча. Для полной записи старый файл служит источником сведений о представлении. Если при полной записи прежнее представление не удаётся определить и объявления нет, безопасно записывается полный заданный текст с UTF-8 BOM. Для непредставимого текста такой переход применяется к одиночному читателю, а при нескольких загруженных страницах явный отказ сохраняет согласие читателей. Патч при непредставимости отклоняется.

Готовый буфер формируется под блокировкой, проверяется на переход через границу валидности UTF-8 и сравнивается с текстом после декодирования каждой известной страницей. Тот же буфер передаётся атомарной записи. Публикация использует согласованные текст и кодировку. `CodePage` обычной сборки, которая отличается от загруженных сведений, остаётся заявленным ограничением D.

Для `#!` поддерживается числовая директива `#:property CodePage=N`. Roslyn выделяет директиву из синтаксических trivia, поэтому похожая строка внутри комментария или литерала не выбирает кодировку. Патч, который сменил бы страницу скрипта с нетронутым не-ASCII, отказывает и предлагает задать полный текст. Это сохраняет текст за пределами замены при смене представления.

Для нового `.cs` без объявления и известного читателя сохранено поведение P1-44. Такой файл может стать компилируемым после загрузки проекта, поэтому обычный исходник создаётся с UTF-8 BOM даже при ASCII-тексте. Переносимый ASCII-патч существующего файла без владельца, в том числе shebang, сохраняет байты нетронутых национальных вариантов.

В первом расширенном целевом прогоне прошли 190 из 196 случаев. Четыре проверки были исправлены так, чтобы выбирать исходный документ по пути, а не считать сгенерированные документы. Восстановлена диагностика случайного BOM для файла без владельца. Проверка отказа для UTF-16 теперь сверяет номер `CodePage`. Повторный целевой прогон дал 11 из 11. Отдельные тесты подтвердили применение объявленного BOM при совпадающем тексте полного запроса и сохранение Latin-1 в компилируемом файле с расширением `.txt`.

Два скрипта записаны через MCP stdio в UTF-8 и Latin-1. Latin-1 скрипт с `#:property CodePage=28591` дополнительно изменён через `apply_patch`. Оба файла начинались с `23 21` и после прямого запуска в Ubuntu 24.04 под WSL напечатали `233` (`U+00E9`).
