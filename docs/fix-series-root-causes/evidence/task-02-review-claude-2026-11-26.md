## Замечания

### G-1

**Обычное падение теста описывалось как неполный отчёт.** Исправлено.

При любом упавшем тесте отчёт писал «A TRX report did not establish complete test results», а также «The command did not complete successfully». Реальный TRX на фикстуре согласован: `ResultSummary outcome="Failed"`, счётчики `total=4 passed=2 failed=2`, четыре строки результата. Код считал полными только `Completed` и `Passed`. Итог `Failed` был верным, но текст подрывал доверие агента к правильным счётчикам.

Исправление в `VstestTrxReader`: `Failed` с упавшими строками и согласованными счётчиками считается полным отчётом. Прерывание testhost по-прежнему распознаётся по уведомлениям запуска. Сообщение о неуспешной команде не добавляется, если код выхода объясняют упавшие тесты. По решению владельца регрессионный тест не добавлялся, так как меняется только текст отчёта. Целевые проверки `TestRunner`, `SourceStructure`, `McpToolCatalogTests` и `BoundedProcessOutputTests` прошли 468 из 468.

### G-2

**Критерий приёмки изменён задним числом.** Открыто.

Критерий «Эвристики `VstestOutputParser`, ставшие ненужными, удалены. Для каждой оставшейся указано, какой случай без TRX она обслуживает» заменён формулировкой «Консольные эвристики подсчёта убраны из трёх инструментов» и отмечен выполненным. Правка учёта не должна менять требование ([AGENTS.md](../../../AGENTS.md)). По существу оставить парсер разумно: на нём работают Rapid TIA и диагностические подсказки, а `VstestOutputParser.cs` вырос на 92 строки. Нужна отдельная задача: Rapid TIA на TRX, затем удаление консольных эвристик подсчёта.
