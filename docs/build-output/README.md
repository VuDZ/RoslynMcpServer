# Silent-вывод сборки

Дата: 2026-10-05.

Статус: принято 2026-10-05 для версии 1.5.5 после повторной Release-сборки и полного основного CI-набора (1264/1264, без пропусков).

Объём: `includeBuildWarnings=false` в `run_dotnet_build`, трёх тестовых тулах,
`run_dotnet_run` и явной команде `build` в `execute_dotnet_command`;
технический контекст запуска только при неуспехе или неподтверждённом результате тестов.

Свидетельства: [валидация](validation.md).

## Поведение

- Успешная сборка по умолчанию возвращает только `Build succeeded`.
- `includeBuildWarnings=true` добавляет предупреждения: без дублей, максимум 20 диагностик,
  при ошибке сначала ошибки. Успешный ответ остаётся без технической шапки.
- Ошибки, включая warnings-as-errors, видны независимо от параметра. Неуспех без
  распознанных ошибок, таймаут и исчерпание бюджета сохраняют отдельный статус и диагностический фрагмент.
- Контекст SDK, рабочего каталога и аргументов находится после ошибок под `Execution context`.
- Полный лог сбоя сборки, включая скрытые предупреждения, доступен по `reportCursor`
  без повторного запуска. Фильтрация применяется до ограничения фрагментов вывода.
- Результаты тестов и stdout/stderr упавших тестов сохраняются. Параметр работает и на
  маршруте сборки проекта, и на маршруте сборки solution target перед запуском DLL.
- `run_dotnet_run` выполняет сборку, затем `dotnet run --no-build`; оба этапа используют
  общий таймаут. Вывод самого приложения не фильтруется как диагностический текст сборки.
- У сырого тула этот формат применяется только к явному первому аргументу `build`.
  Остальные команды сохраняют stdout/stderr, а технический контекст появляется при неуспехе.
