# Analyzer shadow copy — спецификация v2

Статус: **нормативная спецификация; эпохи 1–4 приняты; эпоха 6 — аудит
документации завершён**; серия не завершена (эпоха 5: E5-S1 есть, U-ARB-01 =
capture на load, [эскиз F-09 принят](epoch-5-f09-acceptance.md), rollout ждёт
P0-spike; matcher запрещён).
Дата: 2026-09-11. Язык нормативного текста — русский; имена API и идентификаторы сохранены.
Shipped: v1.3.6 mapping, v1.3.7 restart-required / main-only, v1.3.8 write boundary
(`f54aec15f48f942ef9ac077c752bf03ae018bf31`).

## Назначение и область

Система сохраняет семантический анализ через in-memory overlay: analyzer references
загруженного решения заменяются ссылками на подготовленные shadow-копии без
сохранения этих замен в проект. Исходные задачи — восстановление генерации при
неправильном analyzer path и возможность пересобирать существующий реальный output
без блокировки сервером. Это разные проверяемые свойства.

v2 объединяет обязательные решения арбитража. Ссылки на историю нужны для аудита,
а правила реализации полностью изложены в этом каталоге. Открытые решения
перечислены в [UNRESOLVED-v2.md](UNRESOLVED-v2.md): соответствующие этапы имеют
явные условия допуска, поэтому v2 не означает безусловную готовность всей реализации.

## Текущее поведение v1.3.8 (shipped)

Сверх арбитражного baseline v1.3.5:

- Prepare — `load_workspace` / enable / явный artifact refresh. Edit, watcher
  flush и post-apply — `mapping.Apply` без analyzer I/O (`v2-main-only`).
- Same-identity обновление генератора: **restart-required**. Cached load и
  reset+load готовят файлы, но не исполняют V2. Main-only: private helpers
  отклоняются. Reset не выгружает CLR.
- Запись: preflight → exact inverse → persist → reconciliation → publish mapping.
  Unknown/stale analyzer diff отклоняется до серверных записей. Partial persistence
  сообщает Status, Reason и известные сохранённые пути — это не полный успех.
- Matcher по имени DLL не менялся (эпоха 5 / U-ARB-01). Sticky `false`/omitted —
  U-ARB-05. Поколения при clear не удаляются.

## Историческое поведение v1.3.5

Основание — факты, зафиксированные арбитражем для commit
`3dcd63f7f814e6ac366c409693b34a8492130307`, .NET 10, Roslyn 5.9.0.
Ниже — baseline до эпох 2–4, не текущий shipped.

- `GetCurrentSolution()` возвращает сохранённый `_solution`, при его отсутствии —
  `workspace.CurrentSolution`. Пересчёта overlay при каждом чтении нет.
- Подготовка использует timestamp, копирует основную DLL и необязательный PDB
  с перезаписью; matcher ищет проект по имени DLL. Повторное применение после
  редактирования снова выполняет подготовку и может терять её результат.
- При том же ключе path/Configuration/Platform/TFM и актуальном графе load может
  переиспользовать workspace. Повторный `true` отдельно запускает shadow-подготовку.
- `shadowCopyInSolutionAnalyzers=false` и отсутствие аргумента не выключают ранее
  активированный overlay на cached load. Для отключения применяется
  `reset_workspace`, затем load с `false`/без аргумента. До U-ARB-05 это поведение сохраняется.
- Reset и смена решения очищают состояние workspace/overlay, но не singleton loader
  и не CLR assemblies. Коллизия реально исполненных сборок требует измерения.
- Watcher доставляет dirty paths; синхронизация текста происходит на production flush.
- Сохранение документов и применение workspace не образуют общей транзакции;
  существующий fallback согласует уже записанные тексты после отказа apply.

Историческая порча `.csproj` при применении overlay к реальному workspace была
подтверждена. Повторная загрузка версий, helpers и конкретный источник возможного
lock существующей DLL остаются предметом обязательных экспериментов.

## Термины

| Термин | Единственное значение в v2 |
| --- | --- |
| cached load | Тот же ключ загрузки, граф не stale, существующий workspace переиспользуется; это не обещание свежего исполнения |
| reset+load | Dispose workspace и открытие заново в том же процессе сервера |
| process restart | Новый процесс сервера и новый loader |
| graph-stale reopen | Повторное открытие графа из-за его устаревания; процесс loader сохраняется |
| artifact refresh | Перечитывание и хеширование обязательных исходных байтов для проверки нового output |
| подготовка | Получение проверенного неизменяемого поколения и результата для mapping |
| mapping | Неизменяемое отображение original↔shadow, связанное с сессией загрузки и проектами |
| overlay reapply | Применение готового mapping к `Solution` без файлового I/O анализаторов |
| активное поколение | Поколение, на которое ссылается опубликованный overlay; это не доказательство исполнения |
| reconciliation | Согласование workspace с тем, что фактически сохранилось на диске после частичного отказа |

Термин «полный reload» без указания одной из операций выше не используется.
Чистым является только преобразование `Solution` по готовому mapping.

## Целевые инварианты и условия приёмки

Номера сохраняют соответствие семи инвариантам v1; это **цели и условия выпуска**,
а не заявление о выполнении в v1.3.5.

1. Изменения analyzer references, внесённые overlay, никогда не попадают в `.csproj`.
   Приёмка — эпоха 4, матрица эпохи 1.
2. Семантические операции используют согласованный overlay. Контракт состоит из
   трёх частей: целостность неизменяемого снимка; свежесть доставленных disk changes
   после указанной границы flush; использование одного базового снимка внутри
   семантической операции. Flush не обещает видеть ещё не доставленное событие FSW.
   Приёмка — инвентаризация читателей эпох 1/4 и аудит эпохи 6.
3. `GetCurrentSolution()` сам не копирует файлы и не загружает assemblies.
   Последующая compilation может лениво загрузить генератор. Приёмка — эпохи 1/2/3.
4. Опубликованные поколения неизменяемы; повторная подготовка не перезаписывает их.
   Приёмка — эпоха 2; этот инвариант не доказывает новое CLR execution эпохи 3.
5. Ошибку подготовки нельзя выдавать за успешный refresh или генерацию.
   Подготовка, rewrite, load failure и наблюдаемое исполнение различаются.
   Приёмка — эпохи 2/3/4/5.
6. Функция остаётся opt-in. Новые публичные MCP параметры и схемы не вводятся
   этой ревизией. Политика повторного флага ограничена U-ARB-05.
7. Поиск generated declarations по имени остаётся вне серии.

Операция удерживает базовый immutable snapshot и использованный mapping до своего
завершения. Нельзя вычислить symbol по одному снимку, а преобразовать заново
полученный `GetCurrentSolution()`. Реестр истории snapshots и merge engine не нужны.

## Сквозные границы

В памяти различаются запрошенный режим, prepared mapping (включая частичный
результат по ссылкам), активные поколения, последний refresh и наблюдаемое
исполнение. Один enabled bool их не заменяет. Mapping не сериализует Roslyn snapshots.

Load, включение overlay и ответ должны относиться к одной load session. Эпоха 1
проверяет сериализацию MCP dispatch; если конкурентные вызовы возможны, внутренняя
оркестрация удерживает общий scope либо проверяет expected session до включения.
Новый публичный параметр для этого не требуется.

Общий per-solution shadow root сохраняется. Manifest проверяет целостность, но
не удостоверяет происхождение, если файлы и manifest подменены вместе. Применяются
локальное владение каталогом и проверка путей эпохи 2. Новый sandbox, сервис доверия,
подписи, авторизация пользователей или messaging infrastructure не вводятся.
Фоновая доставка FSW и flush описаны отдельно; автоматического build или artifact
refresh на событие watcher нет в целевом контракте.
