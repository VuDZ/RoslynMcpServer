# Эпоха 5 — Подтверждение происхождения analyzer references

Статус: **планируется**. Зависимость: эпоха 1.

## Проблема

Совпадение имени analyzer DLL с уникальным `AssemblyName` проекта даёт
кандидата, но не доказывает связь. Внешняя или NuGet-ссылка может иметь то же
имя. Ошибочная замена меняет исполняемый анализатор даже при существующем
и корректном исходном пути.

## Решения и требования

1. Разделить поиск кандидата по имени и подтверждение происхождения.
2. Использовать доступные данные об analyzer project reference, evaluated
   MSBuild metadata и разрешённых output-путях. Сначала проверить, какие
   данные реально доступны используемой версии workspace; не предполагать,
   что analyzer `ProjectReference` всегда представлен обычным Roslyn
   `ProjectReference`.
3. Установить проверяемое правило соответствия. Наличие пути, похожего на
   output проекта, само по себе не заменяет подтверждение связи.
4. При недостаточности данных оставить исходную ссылку и сообщить причину.
   Не выполнять дополнительный build только ради сопоставления.
5. Сохранить поддержку исходного repro с отсутствующим неправильным путём:
   требование равенства исходного пути правильному output не решает задачу.
6. Configuration/TFM учитывать там, где они меняют выбор сборки. Если вариант
   неоднозначен, пропустить замену вместо выбора первого совпадения.

При необходимости отдельной MSBuild evaluation её стоимость и входные
параметры должны быть описаны. Результаты собираются при load/reload, а не
при каждом семантическом запросе.

## Диагностика

Различать как минимум: подтверждённая замена, неоднозначность, происхождение
не подтверждено, output отсутствует, ошибка подготовки. Для сопоставленной
ссылки логировать исходный путь, выбранный проект и основание выбора.
Не включать все подробности в каждый MCP response; сохранить краткую сводку.

## Приёмка

- Исходный repro с перенаправленным `OutputPath` продолжает исправляться.
- Внешний analyzer с совпадающим именем не заменяется in-solution сборкой.
- Несколько проектов с одинаковым `AssemblyName` не разрешаются случайно.
- Проверены разные конфигурации и multi-targeting: либо правильный выбор,
  либо явный безопасный пропуск с документированным ограничением.
- Отсутствие output и неподтверждённая связь различимы в диагностике.

Автоматическая сборка генераторов и универсальное восстановление любых
ошибочных MSBuild-путей не входят в эту эпоху.
