# Эпоха 4 — Единая граница записи workspace

Статус: **планируется**. Зависимость: эпоха 1.

## Проблема

Исторический дефект может вернуться через любой новый вызов `TryApplyChanges`,
если передать solution, унаследовавший overlay. Сейчас часть путей строит
изменения от исходного workspace, а часть использует специальную защиту.
Корректность зависит от дисциплины каждого нового call site.

## Требования

- Все production-вызовы `MSBuildWorkspace.TryApplyChanges` проходят через
  единую внутреннюю границу в `SolutionManager` либо выделенном компоненте.
- Граница получает candidate и актуальный workspace snapshot, проверяет
  применимость изменений, снимает overlay и только затем выполняет запись.
- Сохраняется учёт происхождения замен: project id, исходная analyzer reference,
  shadow reference и связь с исходным снимком. Учитывается жизненный цикл
  снимков, ещё используемых выполняющимися операциями.
- Снимаются именно изменения, внесённые overlay. Нельзя автоматически
  затирать любые отличия analyzer references и тем самым скрывать будущую
  намеренную правку.
- Пока намеренное редактирование analyzer references не поддерживается,
  непонятный diff отклоняется с объяснением, а не молча игнорируется.
- При устаревшем candidate применяется существующий контракт конкуренции
  workspace; если его недостаточно, вводится явный отказ/повтор. Защита
  overlay не должна сама перезаписывать более свежие изменения.

Восстановление исходных ссылок не должно терять порядок или дублировать их.
Отдельно определить поведение для добавленных/удалённых проектов; отсутствие
проекта в исходном снимке не является разрешением записать temp reference.

## Обновление overlay

После успешной записи создаётся новый согласованный overlay-снимок.
При неуспешном `TryApplyChanges` candidate не публикуется как текущее состояние.
Семантический читатель получает целиком старый или новый снимок, без промежуточного
состояния с частично заменёнными ссылками.

## Проверки и приёмка

- Поиск production-вызовов `TryApplyChanges` подтверждает одну границу записи.
- Unit-тесты проверяют снятие известного overlay, отсутствие overlay,
  неизвестный analyzer diff, устаревший снимок и изменения состава проектов.
- Интеграционный тест выполняет edit/rename от overlay solution, подтверждает
  изменение документа и побайтовую неизменность `.csproj`.
- Disk-watcher sync и остальные существующие пути изменения текста проходят
  через ту же границу без потери overlay.
- Нет временных `<Analyzer Include>` после сохранения и последующей сборки.

Переработка всей модели конкурентного редактирования и добавление нового
публичного инструмента управления analyzer references — вне этой эпохи.
