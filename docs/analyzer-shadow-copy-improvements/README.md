# Analyzer shadow copy: план улучшений

Статус: **историческая спецификация v1**. Живая норма и аудит —
[v2/](v2/README.md). Эпохи 1–4 приняты в v1.3.6–v1.3.8; эпоха 6 — аудит
документации завершён; эпоха 5 deferred (U-ARB-01). Серия **не завершена**.

Этот каталог продолжает [историю исходного исправления](../analyzer-shadow-copy/README.md).
Номера эпох локальны для этого каталога. Файлы ниже — доарбитражный план; не
читать их как текущий shipped-контракт.

## Цель

Сохранить анализ через in-memory overlay и гарантировать, что повторные
запросы, изменения документов и перестройка генератора не приводят к потере
генерации, блокировке реального build output или записи временных ссылок в
проект. Явно определить границы поддержки загрузки сборок.

## Исходные факты и открытые вопросы

При подготовке спецификаций код был прочитан, но новые эксперименты и тесты
не запускались. Следующие наблюдения нельзя смешивать:

- Исторически подтверждено: передача overlay в реальный `MSBuildWorkspace.TryApplyChanges`
  могла записать временный `<Analyzer>` в `.csproj`. Механизм описан в
  [исходной эпохе 2](../analyzer-shadow-copy/epoch-2-first-fix-attempt-and-disk-corruption.md).
- Наблюдается в коде: `GetCurrentSolution()` возвращает сохранённый `_solution`
  с fallback на `workspace.CurrentSolution`. Overlay обновляется в отдельных
  точках синхронизации, а не при каждом чтении, вопреки части текущих текстов.
- Наблюдается в коде: shadow-копирование использует timestamp и `File.Copy`
  с перезаписью; переносит основную DLL и PDB; сопоставляет ссылки по имени DLL.
- Требует проверки: повторная запись уже загруженной shadow-копии, обновление
  генератора в одном процессе, приватные зависимости и изоляция версий сборок.

## Общие инварианты

1. Overlay не попадает на диск через изменение analyzer references в `.csproj`.
2. Все семантические операции получают согласованный overlay-снимок.
3. Чтение `GetCurrentSolution()` не запускает копирование и загрузку сборок.
4. Опубликованные shadow-файлы не перезаписываются.
5. Ошибка подготовки не выдаётся за успешную генерацию или обновление.
6. Opt-in `shadowCopyInSolutionAnalyzers` сохраняется. Новые параметры MCP
   не вводятся без отдельного обоснования.
7. Поддержка поиска generated declarations по имени остаётся вне этой серии.

## Правила фиксации результатов

Каждая эпоха заканчивается записью выполненных проверок, наблюдаемых результатов,
ограничений и фактического статуса. Число прошедших unit-тестов не заменяет
проверку реального `MSBuildWorkspace`. Незавершённые эпохи не описываются как
выпущенные. Обнаруженные ограничения исправляются в актуальной документации
сразу; эпоха 6 выполняет итоговую сверку, а не откладывает эти уточнения.
