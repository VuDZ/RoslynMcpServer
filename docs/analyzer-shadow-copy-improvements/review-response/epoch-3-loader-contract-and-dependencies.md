# Ответ: эпоха 3

Источники: [review](../review/epoch-3-loader-contract-and-dependencies.md),
[спецификация](../epoch-3-loader-contract-and-dependencies.md).
Обозначения источников — в [README ответа](README.md).

## E3-01 — PARTIALLY ACCEPT

**Основание.** Различие content path и binding identity реально; C clear не
меняет L. Но непрохождение нового критерия текущим кодом не делает сам критерий
недопустимым требованием улучшения. Более сильная причина пересмотреть его — U:
предлагалось сначала определить поддержку reload, с допустимым документированным
ограничением, а обязательное достижение in-process V2 добавлено автором спецификации.
Точный исход на .NET 10 ещё не измерен; «обычно вернёт V1» не baseline.

**Изменение.** «Требуемый контракт», «Решение по результатам»: сначала отдельный
feasibility gate с тремя операциями E1-02. In-process update — вариант дизайна,
а не безусловный release gate. После измерений выбрать поддерживаемый режим
с явной диагностикой ограничений; нельзя автоматически принять restart лишь
потому, что первая реализация не прошла тест.

**Последствия.** Меняются scope и критерии завершения, инструкции reload и
операционная стоимость restart. Сам loader/ALC этим ответом не выбран.

## E3-02 — PARTIALLY ACCEPT

**Основание.** Отсутствующая helper DLL и конфликт загруженных identity — разные
причины; ALC не материализует отсутствующие файлы. Это полезное уточнение порядка
экспериментов. Однако копирование всех `*.dll` из произвольного output с blacklist
Roslyn/System не доказано безопасным discovery: каталог может быть общим,
содержать лишние сборки, несовместимые либо неполные зависимости.

**Изменение.** «Решение по результатам», «Подготовка зависимостей»: сначала
контролируемый fixture с известным явным набором main+helper, затем helper-only
change и version conflict. ALC рассматривать после разделения prepare/binding.
Production discovery оформляется отдельным проверенным решением; all-DLL copy
допустим как ограниченный эксперимент, не как уже принятый общий алгоритм.

**Последствия.** Manifest input, объём копирования, dependency policy и tests.
Не требуются автоматически ни вторая MSBuild evaluation, ни ALC. Неполнота
discovery — основание ограничить поддержанный сценарий, а не грузить всё подряд.

## E3-03 — PARTIALLY ACCEPT

**Основание.** Sharing контрактов должен быть входным условием ALC эксперимента.
Для type identity необходима та же Assembly instance, с которой работает хост.
Но утверждение «Roslyn только Default — единственный возможный режим» шире
требования: важно разделить фактически используемый контракт; в этом хосте
Default — ожидаемый источник. Маска `System.*` тоже не полноценная политика
для всех NuGet assemblies.

**Изменение.** Перед ALC prototype перечислить shared host contracts, правила
совместимости версий и запрет shadow-копий этих контрактов. Добавить negative
test отдельной `Microsoft.CodeAnalysis` и positive test реального исполнения.

**Последствия.** Внутренний binding contract, type-identity tests, ограничение
на поддерживаемые generator dependencies. Это уточнение входного условия,
а не разрешение заменить loader без feasibility gate.
[Microsoft: shared dependencies и type conversion](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext).

## E3-04 — PARTIALLY ACCEPT

**Основание.** L resolver действительно перебирает общую коллекцию каталогов
без связи с requesting generator. Код не доказывает, какие каталоги добавит
Roslyn, поэтому нужно инструментировать `AddDependencyLocation`. Но singleton
сам по себе не исключает router с явными владельцами, а один loader на поколение
без отдельного binding context не гарантирует изоляцию. Дихотомия review слишком узка.

**Изменение.** «Подготовка зависимостей», «Ресурсы и приёмка»: поддержка
конфликтующих helpers требует доказанного scope разрешения; иначе явно
unsupported. Удаление callback привязать к реальному владельцу/отсутствию
зависимых операций, не к простому workspace clear. Проверять requesting
assembly, выбранный путь и отсутствие чужого resolver fallback.

**Последствия.** Lifetime контекстов/обработчиков, diagnostics и memory tests.
Нельзя оставить текущий global search и объявить isolation выполненной;
нельзя обещать снятие обработчика при ещё живых lazy compilations.

## E3-05 — PARTIALLY ACCEPT

**Основание.** В исходном тексте нет логического противоречия: промежуточный
релиз явно не равен завершённой эпохе. Однако обязательный бесконечный gate на
in-process V2 не обоснован U, как установлено в E3-01. Принимать любой измеренный
результат как продуктовую готовность тоже нельзя: wrong generator после
переключения solution или helpers из чужого каталога не исправляются словом restart.

**Изменение.** Разделить завершение исследования (контракт выбран по evidence)
и завершение реализации выбранного режима (его acceptance проходит). Restart
может быть окончательным поддержанным режимом после решения, а не автоматическим
победителем. При unsafe смешении версий режим должен отказывать с указанием
restart до выдачи заведомо неверной семантики.

**Последствия.** Status/release model, возможное снижение функционального scope,
диагностика unsupported refresh. Арбитраж A-01: допустимость restart-контракта.

## E3-06 — ACCEPT

**Основание.** F выставляет `Applied` после rewrite, до lazy load. U не требует
eager execution и не обосновывает его стоимость. «N rewritten» само по себе
является верным отчётом о ссылках, а не ложью об исполнении; проблема возникает,
если интерпретировать его как доказательство успешной генерации.

**Изменение.** «Подготовка зависимостей», README invariant 5: разделить prepared,
references-rewritten, load-failed и execution-result в терминологии/diagnostics.
Оставить lazy загрузку по умолчанию, коррелировать её ошибки с project/generation
на первом семантическом запросе. Проверить доступные Roslyn load-failure events
и compilation diagnostics на используемой версии; не приписывать ошибки одному
`GetSemanticModelAsync`, пока не подтверждён канал. Eager load — отдельное решение.

**Последствия.** Внутренние статусы и observability; MCP summary остаётся кратким
отчётом о rewrite без гарантии генерации. Тесты first-use load failure обязательны;
добавление новых public полей/параметров сейчас не требуется.
