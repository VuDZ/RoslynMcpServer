# Ответ: эпоха 6

Источники: [review](../review/epoch-6-contract-and-documentation.md),
[спецификация](../epoch-6-contract-and-documentation.md).
Обозначения источников — в [README ответа](README.md).

## E6-01 — ACCEPT

**Основание.** C reoverlay читает build output при edit; переход к mapping
без prepare меняет наблюдаемое поведение. То, что recopy был ненадёжным или
случайным, не позволяет переписать историю как «всегда только reload».
U не устанавливал silent compatibility break.

**Изменение.** «Контракт снимков», «Изменения документации»: таблица действие ×
текущий код × выбранная цель × проверка. Отдельно cached load, reset+load,
process restart, edit и graph-stale reopen. Reuse-on-edit пометить как
потенциально несовместимую поведенческую смену workaround и дать инструкцию
обновления генератора. Не обещать, что reset выгрузит CLR.

**Последствия.** Release notes, operator workflow, version decision после
измерений; новый номер релиза сейчас не назначается. Формулировка breaking
относится к поведению, а не доказывает необходимость major version.

## E6-02 — PARTIALLY ACCEPT

**Основание.** Ошибки recompute-on-read в A, historical README и C remarks
подтверждены. Исправлять их нужно независимо от loader. Но README серии уже
явно требует немедленных уточнений и называет этап 6 итоговой сверкой;
противоречие «обязательно ждать 1–5» из него не следует. Кроме того, текущий
запрос пользователя прямо запрещает менять исходные документы и код.

**Изменение.** В будущем плане выделить ранний docs-only correction с тремя
точными targets: `ARCHITECTURE.md / Workspace lifecycle`, historical README
«Fixed architectural decisions», remarks
`ShadowCopyInSolutionAnalyzerReferencesAsync`. Эпоха 6 только проверяет
согласованность. В этом проходе changes перечисляются, но не применяются.

**Последствия.** Только документация/комментарии, без runtime/API изменения.
Исторический код не переписывается; добавляется точное примечание о фактическом
поведении. Защищённые файлы остаются неизменными по требованию пользователя.

## E6-03 — ACCEPT

**Основание.** C имеет cache hit, stale reopen, явный clear и несколько apply
веток; W отдельно включает overlay. Список общих слов «load/reload» скрывает
E1-04 и различие обновления graph и файлов генератора.

**Изменение.** «Контракт снимков», «Проверка»: матрицу построить от реальных
входов и веток C/W, включая failed prepare, partial rewrite, no output,
same-path flag transition, fallback после apply failure. Для каждого указать:
что происходит с graph, mapping, generation, loader и watcher dirty set.

**Последствия.** Полная lifecycle спецификация и трассировка тестов эпохи 1;
наблюдаемая семантика флага требует отдельного выбора, не нового имени для
неопределённого reload. Runtime правки не выполняются docs-эпохой молча.

## E6-04 — PARTIALLY ACCEPT

**Основание.** Reuse-on-edit — изменение эпохи 2, orchestration после записи —
эпохи 4. Эпоха 6 не должна впервые вводить их реализацию. Но исходный текст
помечен как будущая спецификация и уже запрещает объявлять deferred выполненным;
описание целевого состояния само по себе ещё не ложь о shipped коде.

**Изменение.** Перенести нормативный acceptance reuse в этапы 2/4, в этапе 6
оставить сверку фактов и документирование исключений. Разрешить закрыть
документационный аудит при выбранном и явно описанном результате/deferred этапа 3,
без обязательного внедрения in-process loader. Отдельно вести статус серии.

**Последствия.** Разделение documentation completion, research decision и
implementation completion. Документы отражают текущий код, не превращаются
в способ закрыть красные функциональные проверки. API и persistence этот
этап непосредственно не меняет.
